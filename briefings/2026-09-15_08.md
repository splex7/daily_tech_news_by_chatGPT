# AI·LLM·에이전트 최신 브리핑

**2026년 9월 15일 08시 KST 기준**

직전 브리핑의 ASML High NA EUV, GitHub HydraFusion, NVIDIA CUDA Rust, AWS SageMaker PREFIX_AWARE, Strix는 중대한 추가 업데이트가 없어 제외했다. 이번 회차는 오픈 모델 학습 데이터 플라이휠, 장기 실행 Agent Runtime, Local-first Agent, Durable Execution 인프라, 오픈소스 Background Agent UX를 중심으로 선정했다.

## 1. Bolt `Forge` 공개 — 실제 개발 세션으로 오픈웨이트 코딩 모델을 학습하는 데이터 플라이휠

![Bolt Forge](https://bolt.new/public-page-assets/media/solutions/what-is-bolt-forge/blog_forge.webp)

**핵심 요약:** Bolt.new가 9월 14일 `Bolt Forge`를 Research Preview로 공개했다. Forge는 단일 모델이 아니라 GLM 5.3 Flash를 기본으로 GLM 5.3, Kimi K3, DeepSeek v4 Pro 같은 오픈 모델을 선택해 사용하는 Coding Agent다. 개인 Pro 사용자는 10월 14일까지 Forge 사용량을 최대 50배 더 받을 수 있다.

더 중요한 것은 학습 구조다. 사용자가 Forge로 전환할 때 명시적으로 동의하면 Bolt가 Prompt, Code, Fix Trace가 포함된 Build Session에서 Secret과 개인정보를 제거하고 익명화한 뒤 Arcee AI에 전달한다. 이 데이터는 Trillion-parameter-class Open-weight Model의 학습에 쓰이며, Bolt는 결과 모델의 Weight를 공개해 누구나 다운로드하고 실행할 수 있게 하겠다고 밝혔다. Teams와 Enterprise Workspace는 데이터 수집 대상에서 제외된다.

Bolt 자체 `Build Index`에서는 Forge 오픈 모델이 92.2점으로 최고 유료 모델 101점의 약 91%를 기록했다. 자체 Benchmark이므로 독립 평가와는 구분해서 볼 필요가 있다.

**왜 중요한지:** Closed Coding Agent의 가장 큰 우위 중 하나는 실제 사용자의 `시도 → 오류 → 수정 → 성공` 과정에서 나오는 고품질 Interaction Data다. Forge는 저렴한 사용량을 제공하는 대신 동의한 실제 개발 Workflow를 오픈 모델의 Training Data로 돌려주는 구조를 만든다.

즉 오픈 모델 경쟁이 단순히 Weight 공개에서 `실제 사용자 Workflow → Training Data → Open Weight → 다시 사용자에게 배포`되는 데이터 플라이휠 경쟁으로 이동하고 있다.

출처: [Bolt 공식 발표](https://bolt.new/blog/what-is-bolt-forge), [Business Wire](https://www.businesswire.com/news/home/20260914296571/en/Bolt.new-Launches-Forge-to-Widen-Who-Gets-to-Build-with-AI-and-to-Train-Open-Models-on-What-They-Make)

## 2. Salesforce `Agentforce Long-Horizon Runtime` — Agent가 며칠·몇 주 동안 같은 목표를 계속 추적

![Salesforce Agentforce](https://www.salesforce.com/news/wp-content/uploads/sites/3/2026/09/Salesforce-Introduces-Purpose-Built-AI-Agents-That-Take-On-Bigger-Jobs-and-Get-Better-Over-Time.png?w=300)

**핵심 요약:** Salesforce가 Agentforce에 새로운 Long-Horizon Runtime을 도입했다. 기존 Agent가 한 번의 대화나 짧은 Task를 끝내는 데 초점을 맞췄다면, 새 Runtime은 하나의 목표를 며칠 또는 몇 주 동안 유지하면서 새로운 정보와 사용자 피드백에 따라 Plan을 수정하고 작업을 이어갈 수 있게 한다.

핵심 구성은 `Memory`, `Durable Execution`, `Dynamic Steering`이다. Memory는 Session이 끝나도 Context와 진행상태를 보존하고, Durable Execution은 중단된 계획을 재개하거나 상황 변화에 따라 수정하며, Dynamic Steering은 사용자의 Feedback과 지시에 따라 Agent 행동을 조정한다. Outbound Sales Agent인 Hunter가 첫 적용 대상이며 향후 다른 Agent와 고객이 직접 만드는 Agent에도 확대될 예정이다.

Salesforce는 동시에 Multi-Agent Orchestration을 GA로 제공하고, AI Skills와 Agent Optimizer를 10월 GA 예정으로 공개했다. Agent Script는 AI Reasoning과 Deterministic Rule을 섞어 Agent 행동을 통제하는 오픈소스 언어로 제공된다.

**왜 중요한지:** 실제 기업 업무는 대부분 한 번의 Prompt로 끝나지 않는다. 영업 Opportunity, 공급망 문제, 고객지원 Escalation처럼 며칠 동안 상태가 바뀌고 사람의 승인도 기다려야 한다.

Agent Platform의 핵심 경쟁력이 `답변 품질`에서 `Goal Persistence + State + Resume + Human Steering`으로 이동하고 있다는 신호다. 기업용 Agent는 점점 Chatbot보다 장기 실행 Workflow Engine에 가까워지고 있다.

출처: [Salesforce 공식 발표](https://www.salesforce.com/news/stories/agentforce-job-ready-ai-agents/)

## 3. Perplexity `Portable Computer`, Windows RTX 정식 지원 — 로컬 Agent와 Cloud Frontier Model을 한 Workflow에서

![Perplexity Portable Computer on Windows](https://blogs.nvidia.com/wp-content/uploads/2026/09/Local-AI_Perplexity-on-Windows_Blog_Feature.jpg)

**핵심 요약:** 9월 14일 Perplexity Portable Computer가 Windows용 Perplexity App에서 NVIDIA GeForce RTX와 RTX PRO Workstation을 공식 지원하기 시작했다. 최소 24GB VRAM이 필요하며 기존 DGX Spark와 Linux RTX 지원에서 Windows PC로 사용 범위가 확대됐다.

Portable Computer에서는 Orchestrator, Planner, Tool Router, Scheduler, Durable Task Queue, Local Search Index와 모델이 로컬에서 동작한다. Qwen 3.8 27B처럼 Perplexity Computer용으로 Post-training된 모델을 사용할 수 있고, 로컬에서 처리한 작업은 Computer Credit을 소비하지 않는다. 더 강한 Reasoning이나 최신 Web 정보가 필요할 때는 사용자의 허락을 받은 뒤 해당 단계만 Cloud Model로 Escalation할 수 있다.

Outlook, OneDrive, Word, Google Drive, Gmail, Slack, GitHub Connector도 지원한다. NVIDIA는 민감한 파일을 로컬에 유지하면서 GitHub PR Review, 금융 문서 분석, Funnel 분석 같은 Multi-step Workflow를 수행하는 사례를 제시했다.

**왜 중요한지:** Local AI가 `작은 모델로 Chat`하는 단계에서 `Local Agent Runtime + Tool + Durable Task + 선택적 Cloud Escalation` 구조로 발전하고 있다.

앞으로 Personal Agent의 기본 Architecture는 모든 요청을 Cloud에 보내는 방식보다 `Private·반복 작업은 Local → 어려운 Reasoning만 Cloud`로 분리될 가능성이 높다. Windows RTX 지원은 이 구조를 DGX 같은 특수 장비에서 일반 고성능 PC 시장으로 확장한다는 점에서 의미가 크다.

출처: [NVIDIA 공식 발표](https://blogs.nvidia.com/blog/local-ai-perplexity-windows-pcs/), [Perplexity Portable Computer](https://www.perplexity.ai/en-GB/hub/blog/introducing-portable-computer-for-local-first-ai)

## 4. Temporal, `$550M` 조달·기업가치 `$12.55B` — Agent의 `Durable Execution`이 독립 인프라 시장으로

![Temporal Durable Execution](https://images.ctfassets.net/0uuz8ydxyd9p/1YiCTIWs5UYzTv98YKzyK/6362b8f447f3ef62e8dd9a67d744b4dd/Happy_Laptop__2_.png?fm=png&h=110&q=80&w=320)

**핵심 요약:** Temporal이 9월 14일 Series E에서 5억5천만 달러를 조달해 기업가치가 125억5천만 달러로 상승했다. 2026년 2월 50억 달러 평가 이후 7개월 만에 두 배 이상 높아진 것이다. Lightspeed Venture Partners가 주도했고 Wellington Management, Goldman Sachs Alternatives의 Growth Equity, Tiger Global 등이 공동으로 참여했다.

Temporal은 Open-source Durable Execution Platform으로 장시간 실행되는 Application과 AI Agent의 상태를 보존하고 장애가 발생했을 때 처음부터 다시 시작하지 않고 중단 지점에서 복구하도록 한다. Temporal은 연환산 매출 Run Rate가 2억5천만 달러를 넘었고 전년 대비 200% 이상 성장했다고 밝혔다. OpenAI, NVIDIA, Netflix, JPMorgan Chase 등도 고객으로 거론됐다.

**왜 중요한지:** Agent가 몇 초짜리 LLM Call이 아니라 몇 시간·며칠짜리 업무를 수행하면 실패는 예외가 아니라 정상적인 운영 조건이 된다. API Timeout, Model Error, 사람이 승인을 늦게 하는 상황, Process Restart가 모두 발생한다.

그래서 Agent Stack에는 `Reasoning Model`과 별개로 `State Persistence + Retry + Pause/Resume + Idempotency + Recovery`를 담당하는 계층이 필요하다. Temporal의 기업가치 급등은 Durable Execution이 Agent 시대의 독립적인 Infrastructure Category로 인정받기 시작했다는 강한 시장 신호다.

## 5. AWS `Pizza Bot` — 장시간 Background Agent를 Chat 대신 `Inbox`로 관리하는 오픈소스 패턴

![AWS Pizza Bot](https://d2908q01vomqb2.cloudfront.net/ca3512f4dfa95a03169c5a670a4c91a19b3077b4/2026/09/09/pizza-bot-figure-1.png)

**핵심 요약:** AWS가 아직 이번 브리핑 시리즈에서 다루지 않았던 `Pizza Bot`을 Apache 2.0 오픈소스로 공개했다. Pizza Bot은 Agent와 계속 Chat을 주고받는 대신, Background Task를 Email Inbox처럼 관리한다. 완료된 작업은 `Unread`, 사람의 승인이나 답변이 필요한 작업은 `Action` Queue에 들어간다.

Self-hosted이며 Telemetry가 없고 Anthropic, Amazon Bedrock, Gemini, OpenAI, OpenRouter, Ollama의 Local Model 등을 선택할 수 있다. 내부 Runtime은 DeepAgents와 LangGraph를 사용해 Agent State를 Checkpoint하며, Desktop App을 닫거나 Client가 연결을 끊더라도 Server가 살아 있으면 작업이 계속된다. Thread, Checkpoint, Memory, Attachment, Setting, Log는 SQLite와 일반 파일 형태로 사용자가 통제하는 폴더에 저장된다.

MCP Server를 Tool Layer로 사용하고 Anthropic 방식의 `SKILL.md` Agent Skills를 지원한다. Skill마다 사용할 MCP Tool을 제한하고 특정 Tool 호출 전 사람의 승인을 요구하도록 구성할 수도 있다. AWS에 따르면 이전 내부 버전은 Amazon 안에서 2,000명 이상이 Meeting Prep, Email Draft, Slack Summary, CRM Logging, Web Research 등에 사용했다.

**왜 중요한지:** Agent가 정말 일을 대신하기 시작하면 `실시간 Chat UI` 자체가 병목이 된다. 사람이 Agent 화면을 지켜보는 것이 아니라 여러 Agent가 Background에서 일하고, 사람이 필요한 순간만 Inbox에 올라오는 방식이 더 자연스럽다.

즉 Agent UX가 `Conversation`에서 `Asynchronous Work Queue + Approval Inbox`로 이동하는 패턴을 보여준다. 특히 MCP와 Skill을 그대로 재사용하고 Self-hosting까지 지원한다는 점에서 기업 내부 Agent Workspace의 참고 Architecture로 가치가 높다.

## 이번 회차의 핵심

이번 다섯 소식은 Agent 산업이 `더 똑똑한 모델` 이후의 문제를 빠르게 해결하고 있다는 점에서 연결된다.

- **Bolt Forge** → 실제 Coding Workflow를 오픈 모델 학습 데이터로 순환
- **Salesforce Agentforce** → Agent 목표를 며칠·몇 주 동안 유지
- **Perplexity Portable Computer** → Local Runtime과 Cloud Frontier Model을 선택적으로 결합
- **Temporal** → 실패해도 계속 이어지는 Durable Execution 인프라
- **AWS Pizza Bot** → 장시간 Background Agent를 Inbox로 감독

결국 Agent 경쟁의 중심은 단일 Model Benchmark에서 다음 전체 Stack으로 이동하고 있다.

> **Training Data Flywheel → Long-Horizon Runtime → Local/Cloud Routing → Durable Execution → Human Approval UX**

모델이 충분히 강해진 뒤의 차별점은 `얼마나 오래, 싸게, 안전하게, 중단 없이 실제 일을 계속하게 만들 수 있는가`가 되고 있다.
