## 1. Banma `AutoOmni 2.0-23B-A3B` — 자동차 안에서 돌아가는 23B급 Omni-model

> 관련 이미지: [AutoOmni 제품군 참고 이미지](https://www.bitauto.com/article/1003109373486/)

### 핵심 요약
Banma Intelligence가 9월 23일 Apsara Conference에서 `AutoOmni 2.0-23B-A3B`를 공개했다. MoE 구조의 온디바이스 Omni-modal LLM으로, 차량용 고성능 SoC에서 직접 실행하는 것을 전제로 한다. 회사는 일상적인 차량 Cockpit Task에서 230B급 Cloud Model과 비슷한 성능을 보이고, 복잡한 Task에서는 동급 Cloud Model 성능의 약 90%를 달성했다고 주장한다. 또한 8개 이상의 Task Stream을 안정적으로 동시 실행하고, 기존 대비 5～6배 빠른 Large-model Inference를 제공한다고 설명했다.

FREELANDER 8이 Qualcomm Snapdragon Cockpit Elite SA8397P에서 AutoOmni를 탑재한 첫 양산 차량으로 소개됐고, Cloud-integrated Agent Architecture를 통해 Navigation, Vehicle Control, Infotainment 같은 여러 Domain Task를 묶어 수행하는 시연도 공개됐다.

### 왜 중요한가
자동차 AI가 `Cloud LLM에게 질문하는 음성비서`에서 **차량 안에서 실시간으로 보고 듣고 판단하는 Local Agent Runtime**으로 이동하고 있다. On-device Model은 Latency, Privacy, 연결 끊김, Cloud Inference 비용 문제를 동시에 줄일 수 있다. 특히 20B급 이상의 멀티모달 모델이 차량 SoC에서 실용적으로 동작하기 시작하면 자동차는 AI Agent가 상시 실행되는 대표적인 Edge Device가 될 가능성이 높다.

- 출처: [PR Newswire](https://www.prnewswire.com/apac/news-releases/banma-intelligence-unveils-autoomni-2-0--23b-on-device-omni-model-302886940.html)

## 2. Palo Alto Networks `Continuous Frontier AI Defense` — Claude·GPT·Open-weight를 한 보안 Harness에서

> 관련 이미지: [Unit 42 Frontier AI Defense](https://www.paloaltonetworks.com/frontier)

### 핵심 요약
Palo Alto Networks의 Unit 42가 `Continuous Frontier AI Defense`를 전 세계에 출시했다. Anthropic Claude Mythos 5, OpenAI GPT-5.6-Cyber, Open-weight Model을 하나의 Multi-model Harness로 Orchestration해 Web App, API, Cloud Infrastructure, Source Repository 등의 취약점을 지속적으로 찾고 실제 Exploitability를 검증한 뒤 수정 방법까지 제시한다.

Unit 42 자체 평가에서는 복잡한 Enterprise 환경에서 어떤 단일 모델도 취약점의 40% 이상을 잡지 못했고, Claude Mythos 5와 GPT-5.6-Cyber가 찾아내는 Exposure의 겹침도 10% 미만이었다. 회사 내부 적용에서는 기존 Penetration Test 1년 분량의 결과를 약 3주에 생성했고, High·Critical Vulnerability 발견은 제품당 3.2배, 평균 Remediation Time은 51% 줄었다고 보고했다. 이 수치는 업체 자체 평가라는 점은 감안해야 한다.

### 왜 중요한가
`가장 강한 모델 하나`보다 **각 모델이 잘하는 공격·분석 Task를 나눠 맡기는 Multi-model Agent System**이 실제 Enterprise Product로 상용화되고 있다는 점이 핵심이다. 보안 분야는 탐지 누락의 비용이 크기 때문에 Model Routing, 검증, Human Expert, Exploit Simulation을 하나의 Harness로 묶는 구조가 특히 잘 맞는다. Agent 시대의 경쟁력이 Model 자체보다 Orchestration Layer에 있다는 강한 사례다.

## 3. GitHub Copilot App, `OpenTelemetry` 지원 — Coding Agent도 이제 Trace로 본다

> 관련 이미지: [VS Code Agent Monitoring Guide](https://code.visualstudio.com/docs/agents/guides/monitoring-agents)

### 핵심 요약
GitHub가 9월 22일 Copilot App에 OpenTelemetry 설정 지원을 추가했다. Enterprise 관리자는 Agent Session 전체 흐름을 기존 Observability Backend로 내보내 Model Request, Tool Call, Token Usage, Unexpected Behavior를 Trace 단위로 분석할 수 있다. 설정은 Enterprise-managed Settings로 중앙 관리되며 Prompt와 Response Content는 기본적으로 수집하지 않는다.

Copilot이 내보내는 Telemetry는 Trace, Metric, Event로 구성된다. 예를 들어 `Model Call → readFile Tool → Model Call → Edit` 같은 Agent 실행 순서를 Jaeger, Grafana, Datadog 같은 OTel 호환 도구에서 그대로 볼 수 있다.

### 왜 중요한가
Coding Agent가 단순 Autocomplete를 넘어 Shell, MCP, Repository, Browser를 조작하기 시작하면서 `결과가 틀렸다`만 봐서는 원인을 찾기 어렵다. 이제 Agent에도 분산시스템과 같은 **Tracing, Cost Monitoring, Tool-level Audit, Latency Analysis**가 필요하다. AgentOps가 기존 DevOps·Observability Stack 안으로 흡수되는 흐름이 본격화되고 있다.

- 출처: [GitHub Changelog](https://github.blog/changelog/2026-09-22-opentelemetry-in-the-github-copilot-app/)
- 문서: [GitHub Docs — OpenTelemetry for agent monitoring](https://docs.github.com/en/copilot/concepts/enterprise/opentelemetry)

## 4. 🔥 `anthropics/financial-services` 약 36.7K Stars — 금융 업무를 Agent Template으로 패키징

> 관련 이미지: [Claude for Financial Services](https://www.anthropic.com/news/finance-agents)

### 핵심 요약
Anthropic의 Apache 2.0 저장소 `anthropics/financial-services`가 9월 23일 GitHub Trending 추적에서 다시 빠르게 주목받고 있으며 현재 약 36.7K Stars, 5.3K Forks 규모다. 이 저장소는 단순 Prompt Collection이 아니라 투자은행, Equity Research, Private Equity, Fund Administration, KYC 등에 필요한 **Agent, Skill, Slash Command, MCP Connector**를 실제 배포 가능한 형태로 제공한다.

Pitch Agent, Market Researcher, Earnings Reviewer, Model Builder, GL Reconciler, Month-End Closer, KYC Screener 같은 Agent가 포함되며 같은 정의를 Claude Cowork Plugin과 Claude Managed Agents API Template 양쪽에서 사용할 수 있다. FactSet, S&P Global, Morningstar, Moody's, LSEG, PitchBook, Box 등 금융 데이터 Connector도 묶여 있다.

### 왜 중요한가
기업용 Agent 시장의 경쟁 단위가 `범용 Chatbot`에서 **업무별로 이미 조립된 Workflow Package**로 내려가고 있다. Model보다 회사의 실제 프로세스, Skill, Connector, Approval Point를 파일로 표준화하는 것이 더 큰 자산이 될 수 있다는 뜻이다. 특히 Markdown·JSON 기반으로 Agent Workflow를 배포한다는 점은 기업의 고유 작업방식을 코드처럼 관리하는 방향과 맞닿아 있다.

- GitHub: [anthropics/financial-services](https://github.com/anthropics/financial-services)

## 5. 🔥 `Univer` — Spreadsheet·Docs·Slides를 하나의 `Office Harness for AI Agents`로

> 관련 이미지: [Univer 공식 사이트](https://univer.ai/)

### 핵심 요약
Apache 2.0 오픈소스 `dream-num/univer`가 9월 23일 TypeScript GitHub Trending 추적에서 두드러지고 있으며 현재 약 16K Stars 규모다. 기존 Office SDK를 최근 **The Office Harness for AI Agents**로 명확히 재정의해 Spreadsheet, Docs, Slides, Canvas, Relational Table, PDF를 하나의 Runtime에서 다루도록 확장하고 있다.

Agent는 Structured API로 Office Content를 수정하고, Screenshot·Layout Diagnostics로 결과를 다시 검증할 수 있다. 여러 Agent가 같은 파일을 동시에 작업할 때는 Git처럼 각각 Isolated Worktree에서 수정한 뒤 사람이 Review·Merge하는 방식도 제공한다. Browser와 Node.js에서 같은 Runtime을 쓸 수 있고 Self-hosting도 지원한다.

### 왜 중요한가
Coding Agent에는 Git과 IDE가 있었지만 Knowledge Worker Agent에는 아직 표준적인 `작업장`이 없다. Univer가 흥미로운 이유는 Excel·Word·PowerPoint를 단순 File Format으로 보는 것이 아니라 **Agent가 읽고 수정하고 검증하고 사람과 Merge하는 실행환경**으로 재설계한다는 점이다. Agent가 Software Engineering을 넘어 회계, 분석, 보고서, 발표자료 제작으로 확산될수록 이런 Office Harness 계층이 중요한 Infrastructure가 될 수 있다.

- GitHub: [dream-num/univer](https://github.com/dream-num/univer)
- 공식 사이트: [Univer — The Office Harness for AI Agents](https://univer.ai/)

## 이번 회차의 핵심

이번 회차는 다음 흐름으로 연결된다.

**AutoOmni 2.0 → Edge Agent Intelligence**  
**Unit 42 → Multi-model Security Harness**  
**GitHub Copilot OTel → Agent Observability**  
**Anthropic Financial Services → Domain Agent Package**  
**Univer → Knowledge-work Agent Runtime**

공통점은 Model 자체보다 **Agent가 실제 환경에서 일하게 만드는 주변 시스템**의 가치가 빠르게 커지고 있다는 것이다. 앞으로의 경쟁은 `더 똑똑한 LLM`뿐 아니라 **어디에서 실행하고, 어떤 도구를 연결하고, 어떻게 관찰하고, 어떤 업무 Workflow를 재사용 가능한 자산으로 만드는가**에서 크게 갈릴 가능성이 높다.
