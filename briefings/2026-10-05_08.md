## 1. AMD, Fei-Fei Li의 World Labs를 약 82억 달러에 인수

**관련 이미지·자료:** https://newsroom.amd.com/news/amd-acquire-world-labs/

### 핵심 요약
AMD가 World Labs를 약 82억 달러 규모의 전액 주식 거래로 인수하기로 했다. World Labs는 Fei-Fei Li가 이끄는 AI 연구소로, 텍스트·이미지·비디오에서 상호작용 가능한 3D 환경을 생성·재구성·시뮬레이션하는 spatial intelligence와 robotic learning 기술을 개발한다. 거래는 규제 승인 등을 거쳐 2026년 말까지 마무리될 예정이며, 이후 Fei-Fei Li는 AMD EVP 겸 Chief Scientist로 Lisa Su에게 직접 보고한다.

### 왜 중요한지
AMD가 NVIDIA와 경쟁하기 위해 GPU 성능만이 아니라 모델 연구와 Physical AI workload 자체를 내부 역량으로 가져오려는 움직임이다. World Model과 로봇 시뮬레이션은 향후 GPU·CPU·메모리·네트워킹 설계 요구를 직접 만들어내는 분야이므로, AMD가 모델을 이해해 다음 세대 하드웨어 로드맵을 설계하려는 수직 통합 전략으로 볼 수 있다.

## 2. H Company Holo4 — GUI·코드·MCP·API를 한 모델이 다루는 오픈 웨이트 Computer-use Agent

**관련 이미지·자료:** https://huggingface.co/blog/Hcompany/holo4

### 핵심 요약
H Company가 Holo4 모델군을 공개했다. Holo4-27B dense와 Holo4-35B-A3B MoE, 그리고 Holotron4 Nano로 구성되며, 같은 모델이 Desktop·Web·Android·Code Sandbox·Business API를 넘나들면서 GUI 조작, 코드 실행, MCP와 API 호출을 모두 사용할 수 있다.

Holo4-27B는 H Company가 공개한 OSWorld 2.0 측정에서 61.7%를 기록했다. 이는 최고 수준의 폐쇄형 모델보다 낮지만, 훨씬 작은 모델로 실제 Computer-use workflow를 수행한다는 점이 핵심이다. 모델 weights는 BF16, FP8, NVFP4, 4-bit GGUF 형태로 공개됐고, 공개 benchmark의 agent trajectory도 함께 공개됐다.

### 왜 중요한지
Computer-use Agent가 GUI 전용 모델과 Tool-call 전용 모델로 갈라지는 대신, 하나의 모델이 상황에 따라 화면 조작·Shell·MCP·API를 선택하는 방향으로 진화하고 있다. 특히 weights와 trajectory가 공개됐다는 점은 기업이나 연구자가 자체 Agent Runtime에 맞춰 재현·튜닝·검증할 수 있다는 의미가 크다.

## 3. GitHub Security Lab Taskflow Agent — 오픈소스 AI 보안 Agent로 Android 취약점 24개 발견

**관련 이미지·자료:** https://github.blog/security/how-we-found-24-android-vulnerabilities-using-our-open-source-ai-security-agent/

### 핵심 요약
GitHub Security Lab은 오픈소스 Taskflow Agent와 Android 감사용 workflow를 이용해 실제 Android 앱에서 총 24개의 취약점을 찾아 보고했다고 공개했다. 이 Agent는 보안 연구자가 효과적인 prompt와 분석 절차를 단계별 workflow로 패키징해 재사용할 수 있도록 설계됐다.

GitHub는 중간 규모 repository의 분석이 한두 시간 정도 걸릴 수 있다고 설명한다. 동시에 LLM이 취약점 자체를 찾는 능력은 강하지만 심각도를 잘못 판단하거나 false positive를 낼 수 있어 최종 검토에는 보안 전문가가 필요하다고 명시한다.

### 왜 중요한지
Coding Agent의 가치가 코드를 생성하는 단계에서 실제 취약점 연구와 검증 가능한 보안 workflow로 확장되고 있다. 단순한 AI code review가 아니라 전문 연구자의 절차를 구조화해 반복 실행한다는 점에서 향후 DevSecOps 파이프라인에 전문 Agent가 들어갈 형태를 구체적으로 보여준다.

## 4. Tuskira AI Agent Gateway — MCP와 LLM 호출을 하나의 오픈소스 Control Plane으로

**관련 이미지·자료:** https://www.tuskira.ai/blog/open-source-ai-agent-gateway

### 핵심 요약
Tuskira가 AI Agent Gateway를 오픈소스로 공개했다. 하나의 Go binary가 MCP plane, Control plane, LLM plane을 제공하며 Agent가 어떤 MCP tool을 볼 수 있고 실행할 수 있는지 profile별로 통제한다. Credentials는 Gateway가 중앙에서 관리하고 실행 시점에 주입한다.

LLM 쪽은 Anthropic, OpenAI, Gemini, Bedrock 등의 provider-native API를 Gateway 뒤로 모으고 token 사용량과 예상 비용을 기록한다. Tool call과 LLM call을 중앙 log로 남기며 OpenTelemetry와 ClickHouse로도 내보낼 수 있다.

### 왜 중요한지
Agent 수가 늘어나면 모델보다 Credential, Permission, Tool Access, Audit Log가 분산되는 문제가 커진다. 이 구조는 MCP가 단순 연결 표준을 넘어 기업용 Agent의 API Gateway·IAM·Observability 계층과 결합되는 방향을 보여준다.

## 5. GitHub Trending: claude-mem — Agent의 장기 기억을 별도 Infrastructure로 분리

**관련 이미지·자료:** https://github.com/thedotmack/claude-mem

### 핵심 요약
thedotmack의 claude-mem이 10월 4일 GitHub Trending에 올라왔고 현재 약 9.6만 Star를 기록하고 있다. Apache 2.0 프로젝트로, Agent session의 행동을 수집·요약해 다음 session에 필요한 context를 다시 주입하는 persistent memory layer다.

구조는 lifecycle hook, local worker service, SQLite, Chroma 기반 hybrid semantic·keyword search로 구성된다. Claude Code뿐 아니라 OpenClaw, Codex, Gemini, Copilot, OpenCode 등 여러 Agent harness와의 연동을 지향하며, 민감한 내용을 저장에서 제외하기 위한 privacy tag도 제공한다.

### 왜 중요한지
장시간 일하는 Agent에서는 모델 context window 크기만으로는 충분하지 않다. 모든 대화를 다시 넣는 방식은 비용이 커지고 noise가 증가하기 때문에, 무엇을 기억하고 언제 불러올 것인가를 별도 memory infrastructure가 담당하는 패턴이 커지고 있다. claude-mem의 급상승은 Agent 경쟁의 다음 층이 model intelligence뿐 아니라 durable memory와 context engineering이라는 점을 보여준다.
