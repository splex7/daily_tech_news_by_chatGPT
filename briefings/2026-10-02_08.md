## 1. Decision Model 경쟁 본격화 — AWS Strands Decider 2B와 Cloudflare Clef

**관련 이미지·공식 페이지:** https://blog.cloudflare.com/clef-decision-models/

### 핵심 요약
10월 1일 AWS Strands 팀은 2B Parameter 오픈소스 Decision Model인 Strands Decider 2B를 공개했다. Qwen3.5-2B의 LM Head 대신 선택지를 점수화하는 Pointer Head를 사용하며, Weight뿐 아니라 학습 데이터와 Script까지 공개했다. AWS 측 측정에서 RTX 3090의 Median Decision Latency는 약 115ms였다. 주요 용도는 Model Routing, Tool Selection, Guardrail, Memory, Context Management, Policy Classification이다.

같은 날 Cloudflare도 Clef와 Clef-flash를 Workers AI에 출시하고 Apache 2.0으로 Weight를 공개했다. Clef는 Frozen Qwen3.8-27B, Clef-flash는 Qwen3.5-9B를 Backbone으로 사용하며, Clef는 Vision Encoder와 64k Context를 지원한다. Cloudflare 자체 Benchmark에서 Median Latency는 Clef 209.3ms, Clef-flash 38.8ms였다. 두 회사의 수치는 Hardware와 Serving 환경이 달라 직접 비교하기 어렵다.

### 왜 중요한지
Agent가 모든 판단마다 Frontier LLM을 호출할 필요가 없다는 방향이 구체화되고 있다. 답의 범위가 제한된 Routing·Tool Selection·Policy 판단은 작고 빠른 Decision Model이 처리하고 복잡한 추론만 Frontier LLM으로 넘기는 구조다. Agent Stack이 **Fast Decision Layer + Slow Reasoning Layer**로 분화되는 신호다.

## 2. Ai2 Olmo-core 3 — 1.2T MoE까지 겨냥한 완전 공개 Training Stack

**관련 이미지·공식 페이지:** https://allenai.org/blog/olmocore3

### 핵심 요약
Ai2가 10월 1일 차세대 Olmo를 위한 오픈소스 MoE Training Infrastructure인 Olmo-core 3를 공개했다. 이번 발표는 새 Model Checkpoint보다 Model Training System에 초점을 둔 Release다.

Ai2의 Preliminary Test에서 8개의 NVIDIA B300으로 47B MoE를 학습했을 때 GPU당 52,000 tokens/s를 기록해 기존 구현의 19,400 tokens/s보다 약 2.7배 높은 Throughput을 보였다. 또 512개의 B300에서 1.2T Total Parameters, Token당 58.36B Active Parameters 구성까지 Benchmark했고 최고 858 TFLOP/s/GPU를 기록했다. 1.2T 실험은 Random Routing 기반 System Performance Test이며 Model 품질 평가가 아니다.

### 왜 중요한지
오픈소스 AI의 핵심 자산이 Weight만이 아니라 Training System 자체로 확장되고 있다. Frontier급 MoE에서는 Expert Routing, GPU Communication, Parallelism, Optimizer State와 Memory Layout이 성능을 크게 좌우한다. “Open Model”의 기준이 **Weight 공개 → Data·Recipe·Training Infrastructure 공개**로 높아지는 흐름이다.

## 3. JetBrains Air in IDEs EAP — IDE가 Multi-Agent Control Surface로

**관련 이미지·공식 페이지:** https://blog.jetbrains.com/ai/2026/10/air-in-ides-eap/

### 핵심 요약
JetBrains가 10월 2일 Air in JetBrains IDEs의 Early Access Program을 열었다. Air는 Codex, Gemini, GitHub Copilot, Claude Agent, Junie와 ACP-compatible Agent를 IDE 안에서 연결하고 병렬 운영하는 Layer다.

여러 Project의 Agent Session을 한 화면에서 추적하고, Changed Files·Commit·Cost를 확인하며, Temporary Git Worktree로 Agent별 작업을 격리할 수 있다. JetBrains는 Third-party Agent 사용 시 Data가 JetBrains를 거치지 않고 해당 Provider로 직접 전달된다고 설명한다.

### 왜 중요한지
Coding AI의 UX 중심이 “IDE 안의 Chat 창”에서 “여러 Agent에게 작업을 위임하고 검토하는 운영 화면”으로 이동하고 있다. ACP 같은 공통 Protocol이 확산되면 개발자는 IDE와 Agent Provider를 독립적으로 선택할 수 있다. IDE 경쟁력도 Code Completion보다 **Agent Orchestration, Context, Review, Diff, Worktree, Cost Visibility**를 얼마나 잘 묶느냐로 이동할 가능성이 높다.

## 4. OpenAI, 대규모 Adversarial Distillation Campaign 대응 사례 공개

**관련 이미지·공식 페이지:** https://openai.com/index/disrupting-a-coordinated-model-distillation-campaign/

### 핵심 요약
OpenAI가 9월 30일 모델의 보호된 추론 정보를 대규모로 수집하려 한 Coordinated Adversarial Distillation Campaign을 공개했다. 회사에 따르면 활동은 7월 초 시작됐고, 7월 24～25일에는 4,000명 이상의 User에서 관련 Pattern을 사용한 약 16,000 Requests가 집중됐다. 추가 조사에서는 15,000명 이상의 User Cluster가 확인됐고 7월 28일까지 차단했다고 밝혔다.

OpenAI는 이번 사건이 Encryption이나 Database 침해가 아니라 Model Interaction을 악용한 사례라고 설명했다. 또한 일부 활동의 귀속에 대한 자체 평가를 공개했지만, 전체 활동이 단일 Actor에 의해 이뤄졌다고 단정하지 않았다.

### 왜 중요한지
Frontier Model의 보호 대상이 Weight만이 아니라 Reasoning Trace와 Model Output 자체로 확대되고 있다. 대규모 API 사용을 통한 Capability Transfer를 막으려면 Account Graph, Signup Abuse Detection, Cross-Workspace Isolation, Output Monitoring 같은 Security Layer가 필요하다. Model Security가 “Weight 보호”에서 **Capability Transfer 억제**까지 확장되는 흐름이다.

## 5. Google Project Suncatcher 첫 실험 발사 — TPU 4개가 실제 궤도로

**관련 이미지·공식 페이지:** https://blog.google/innovation-and-ai/models-and-research/google-research/google-project-suncatcher-facts/

### 핵심 요약
Google의 Project Suncatcher가 10월 1일 첫 실제 우주 실험 단계로 들어갔다. Wall Street Journal 보도에 따르면 Google과 Planet이 만든 Prototype Satellite가 SpaceX를 통해 발사됐으며 Google Trillium TPU 4개를 탑재했다.

목표는 TPU가 Launch Vibration, Radiation, Vacuum, Thermal 환경에서 장기간 동작할 수 있는지 검증하는 것이다. Google은 저궤도에서 장기적으로 AI Compute Cluster를 구성할 수 있는지 연구하고 있다. 다만 Cooling, Launch Cost, Inter-satellite Networking 등 해결되지 않은 Engineering·Economics 문제가 크다.

### 왜 중요한지
AI Infrastructure의 병목이 Chip 공급을 넘어 전력, 냉각, 부지로 이동하면서 Compute를 어디에 둘 것인가 자체가 기술 경쟁이 되고 있다. 당장 Space Data Center가 지상을 대체한다는 의미는 아니지만 TPU를 실제 궤도에서 검증하기 시작했다는 점에서 Space-based AI Compute가 Concept에서 Hardware Experiment 단계로 넘어갔다.
