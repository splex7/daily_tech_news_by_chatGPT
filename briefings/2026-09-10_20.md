# AI·LLM·에이전트 최신 브리핑

**2026년 9월 10일 20시 KST 기준**

직전 08시 브리핑의 GPT-6 Astra 업무 배포, Anthropic 사이버 평가 사고 분석, ChatGPT Images 2.5, Tencent teamai-cli, Analog Devices의 Alif 인수는 중대한 새 업데이트가 없어 제외했다. 이번 회차는 오늘 정식 출시된 DeepSeek V4.1 Flash를 중심으로, 오픈 멀티모달 Agent Gander, Generative UI 전용 오픈웨이트 모델 OUI-1, Red Hat AI 3.5, Visa·Mastercard·Ant International의 Know-Your-Agent 협력을 선정했다.

## 1. DeepSeek `V4.1 Flash` 정식 출시 — 552B MoE지만 입력 8B·출력 16B만 활성화하는 비대칭 구조

**관련 이미지:** [DeepSeek V4.1 Flash 관련 보도](https://www.reuters.com/world/asia-pacific/chinas-deepseek-launches-v41-flash-model-2026-09-10/)

**핵심 요약:** DeepSeek이 9월 10일 `DeepSeek-V4.1-Flash`를 정식 출시했다. Reuters에 따르면 DeepSeek은 이를 새로운 Architecture Family의 가장 작은 모델로 소개하며, 더 높은 성능 상한과 빠른 추론, 높은 Throughput, 더 큰 모델로의 확장성을 목표로 설계했다고 밝혔다.

공개된 사양에 따르면 V4.1 Flash는 총 552B 규모의 MoE에 새로운 `Causal-Encoder-Decoder` 비대칭 구조를 사용한다. 입력을 읽는 단계에서는 약 8B, 출력을 생성하는 단계에서는 약 16B만 활성화한다. Native Visual Understanding을 지원하며 1M Context를 유지한다. DeepSeek은 이전 세대보다 KV Cache가 크게 줄어 HBM 요구량은 약 4분의 1, SSD 요구량은 약 8분의 1 수준이라고 설명했다. 모델 Weight와 기술자료도 Hugging Face에 공개됐다.

DeepSeek 자체 Benchmark에서는 Terminal-Bench 2.1 90.6, DeepSWE v1.1 74.2, Automation-Bench 54.8 등을 제시하며 V4 Pro를 넘어섰다고 주장한다. 이 수치는 출시사 자체 평가이므로 독립 평가와 구분해서 볼 필요가 있다.

**왜 중요한지:** 핵심은 단순히 Parameter가 커졌다는 점이 아니다. Agent는 긴 Context를 반복해서 읽고 짧은 Action을 여러 번 생성하는 경우가 많다. 따라서 **입력 단계의 Active Parameter와 KV Cache를 줄이는 것**은 Agent Cost와 동시 처리량에 직접 영향을 준다.

V4.1 Flash의 방향을 단순화하면 `큰 Weight + 작은 Active Compute + 작은 Cache`다. Frontier급 성능을 유지하면서 Agent Runtime Cost를 낮추려는 경쟁이 Model Architecture 수준으로 내려가고 있다는 신호다.

## 2. 🔥 Tencent `Gander` — 말하고 보는 동안 Background Agent가 계속 일하는 오픈 Full-Duplex Agent

**관련 이미지:** [Gander 공식 프로젝트](https://omni-interaction-gander.github.io/)

**핵심 요약:** Tencent Hunyuan Speech Team이 9월 9일 `Gander`를 공개했고 9월 10일 GitHub 공개 범위를 계속 확대하고 있다. Gander는 음성·영상·텍스트를 하나의 Streaming Context로 처리하면서 사용자가 대화를 계속하는 동안 별도의 Reasoning Agent가 장기 작업을 비동기로 수행하는 End-to-End Omni Interaction Agent다. 코드와 모델은 Apache 2.0으로 공개됐다.

구조는 `Cerebellum-Brain`으로 나뉜다. Front Cerebellum은 실시간 Audio·Video를 받아 Listen, Speak, Interrupt, Tool Call을 판단한다. Agent Orchestration Runtime은 Background Task와 Permission, Progress를 관리하고, Back Brain은 Codex 같은 외부 Reasoning Agent를 Plugin처럼 사용해 긴 작업을 수행한다. 사용자는 Agent가 작업하는 도중에도 음성으로 요구사항을 수정하거나 진행상황을 묻고 취소할 수 있다.

Front Cerebellum은 MiniCPM-o 4.5에서 시작하며 약 270만 개 Interaction Example로 학습됐다. Full-Duplex-Bench v3에서 Gander는 적절한 Turn-taking 100%, Premature Interruption 8.0%를 기록했다. 다만 전체 Agent Task Pass@1은 0.400으로 일부 상용 Baseline보다 낮아, 실시간 상호작용 품질과 복잡한 Task 성공률은 별도로 볼 필요가 있다.

**왜 중요한지:** 지금까지 Voice Agent는 보통 `말을 듣는다 → 답을 생성한다 → 말을 한다`가 한 번에 하나씩 진행됐다. Gander는 이를 **대화와 장기 작업이 동시에 진행되는 구조**로 바꾼다.

사람과 실제로 함께 일하는 Agent라면 사용자가 중간에 말을 걸거나 화면을 보여주고 요구사항을 바꾸더라도 Background Task가 끊기지 않아야 한다. Gander는 향후 Personal Agent와 Desktop Agent가 단순 Voice Chatbot에서 `항상 듣고 보고 일하는 동료형 Runtime`으로 발전할 가능성을 보여준다.

**출처:** [Gander 공식 프로젝트](https://omni-interaction-gander.github.io/) · [GitHub — Omni-Interaction-Gander/Omni-Interaction-Agent](https://github.com/Omni-Interaction-Gander/Omni-Interaction-Agent)

## 3. `OUI-1` — 4B Active Parameter로 UI를 직접 생성하는 첫 Generative UI 전용 오픈웨이트 모델

**관련 이미지:** [OpenUI — OUI-1 공식 발표](https://www.openui.com/blog/oui-1)

**핵심 요약:** Thesys가 9월 8일 `OUI-1`을 공개했다. OUI-1은 Google의 DiffusionGemma를 Fine-tuning한 26B-A4B 모델로 전체 Parameter는 약 26B지만 Token당 약 4B만 활성화된다. 일반 Chat 대신 `openui-lang`으로 실제 UI Component Tree를 생성하도록 특화됐으며 Weight는 Hugging Face에 공개됐다. 라이선스는 Apache 2.0이 아니라 Gemma Terms of Use를 따른다.

Diffusion 방식이라 일반 Auto-regressive LLM처럼 한 Token씩 생성하지 않고 256 Token Block을 동시에 다듬는다. Thesys는 RTX 5090 FP8 환경에서도 실행 가능하도록 설계했다고 밝혔다. 자체 Generative UI Benchmark에서 OUI-1은 71.7%를 기록해 Base DiffusionGemma의 13.0%보다 크게 향상됐고 Gemma 4 31B의 46.7%도 넘어섰다. 다만 Qwen3.8 27B의 78.8%보다는 낮다.

**왜 중요한지:** Agent UI의 미래가 항상 `Chat Window + Markdown`일 필요는 없다. 사용자가 호텔을 찾으면 호텔 Card와 Map이, 비용을 분석하면 Chart와 Filter가, 설정을 요청하면 Form이 즉석에서 생기는 방식으로 Interface 자체가 Agent의 Output이 될 수 있다.

OUI-1은 이 작업을 거대한 Frontier Model이 아니라 **작고 전문화된 Local Model**에 맡길 수 있다는 점이 중요하다. 앞으로 Agent Stack에서 Reasoning은 Frontier Model, UI 생성은 OUI-1 같은 Specialized Model에 맡기는 Routing이 자연스러워질 수 있다.

**출처:** [OpenUI — Introducing OUI-1](https://www.openui.com/blog/oui-1)

## 4. Red Hat `AI 3.5` GA — Kubernetes 운영 방식이 AI Agent의 Safety·GPU·Observability 계층으로 확장

**관련 이미지:** [Red Hat AI 3.5 공식 발표](https://www.redhat.com/en/about/press-releases/red-hat-puts-safety-and-observability-core-enterprise-ai-red-hat-ai-35)

**핵심 요약:** Red Hat이 9월 9일 `Red Hat AI 3.5`를 GA로 공개했다. 이번 버전은 새 Foundation Model보다 **기업이 여러 Model과 Agent를 실제 Production에서 운영하는 Control Plane**에 초점을 맞춘다.

EvalHub를 통해 배포 전 Model·RAG·Agent의 Safety Benchmark와 Compliance Report를 만들 수 있고, Inference Health·GPU Utilization·Model Performance·사용자별 Token Consumption을 Dashboard에서 관찰할 수 있다. Shared GPU 환경에는 Fair-share Scheduling과 Priority-aware Serving을 추가했다. Responses API, Built-in RAG와 NeMo Guardrails도 GA로 제공하며 AutoRAG, Code Review·Document Processing·Research용 Agent Template도 포함한다.

또한 CPU Offloading은 GA, Storage Offloading은 Developer Preview로 제공하고, vLLM Omni 기반 Text·Audio·Image 통합 Serving을 Early Access로 지원한다. llm-d Distributed Inference는 OpenShift뿐 아니라 CoreWeave CKS와 Microsoft Azure에서도 GA로 확장됐다.

**왜 중요한지:** 기업에서 Agent를 수십 개 만드는 것보다 어려운 일은 그 Agent들을 **같은 GPU Cluster에서 안전하게 운영하고 비용과 성능을 측정하는 것**이다.

Kubernetes가 Application 운영에 `Resource Limit + Scheduling + Isolation + Observability`를 가져왔다면, Red Hat AI 3.5는 같은 개념을 Model과 Agent에 적용하고 있다. Agent가 Production Infrastructure가 될수록 AI Platform 팀의 업무도 MLOps에서 **AgentOps + GPU Platform Engineering**으로 확장될 가능성이 높다.

**출처:** [Red Hat — Red Hat AI 3.5 공식 발표](https://www.redhat.com/en/about/press-releases/red-hat-puts-safety-and-observability-core-enterprise-ai-red-hat-ai-35) · [Red Hat — Scaling and governing AI agents in production](https://www.redhat.com/en/blog/red-hat-ai-35-scaling-and-governing-ai-agents-production)

## 5. Visa·Mastercard·Ant International, `Know-Your-Agent` 공동 프레임워크 — Agent Commerce의 KYC 계층을 만든다

**관련 이미지:** [Mastercard Agent Pay](https://www.mastercard.com/global/en/business/artificial-intelligence/mastercard-agent-pay.html)

**핵심 요약:** Visa, Mastercard, Ant International이 9월 10일 AI Agent의 신원을 여러 결제망에서 상호 확인하기 위한 `Know-Your-Agent` KYA Interoperability Framework 공동 개발을 발표했다. Agent가 상품을 추천하는 수준을 넘어 실제 구매를 완료하기 시작하면서, 결제망과 Merchant가 `이 Agent가 누구를 대신해 어떤 권한으로 행동하는가`를 확인할 공통 Trust Layer가 필요해졌기 때문이다.

KYA는 세 축을 중심으로 개발된다. Agent를 검증된 사용자·기업과 연결하는 Cross-network Operator Traceability, 보안·행동 기준을 확인하는 Shared Certification Requirements, Identity와 Transaction Signal을 함께 보는 Continuous Transaction Monitoring이다. 기존 Visa Trusted Agent Protocol, Mastercard Verifiable Intent, Ant International Agentic Mobile Protocol을 기반으로 상호운용 원칙을 만들며 싱가포르 MAS가 주도하는 BuildFin.ai를 통해 협력을 진행한다.

현재는 구현이 끝난 표준이 아니라 공동 Framework를 설계하는 단계다. 구체적인 Certification 규칙, Liability, Revocation, Merchant Pilot 일정 등은 아직 공개되지 않았다.

**왜 중요한지:** Agent가 실제 돈을 쓰는 순간 가장 중요한 질문은 Model 성능이 아니라 **Identity, Authorization, Intent, Liability**다.

사람의 온라인 Commerce에는 KYC와 Payment Authentication이 있다. Agent Commerce에는 여기에 `누가 만든 Agent인가`, `누구의 위임을 받았는가`, `어디까지 결제할 수 있는가`, `권한이 취소됐는가`라는 새로운 계층이 필요하다. Visa와 Mastercard가 동시에 같은 Interoperability 논의에 들어왔다는 것은 Agentic Commerce가 Demo를 넘어 Payment Infrastructure의 정식 문제로 이동하고 있다는 신호다.

## 이번 회차의 핵심 흐름

오늘 다섯 소식은 Agent Stack의 각 계층이 동시에 전문화되고 있음을 보여준다.

**DeepSeek V4.1 Flash** → 긴 Context와 반복 Agent Call을 위한 Model Architecture 최적화  
**Gander** → 대화와 장기 Task를 동시에 처리하는 Full-Duplex Agent Runtime  
**OUI-1** → Text가 아니라 UI 자체를 생성하는 Specialized Model  
**Red Hat AI 3.5** → Agent의 Safety·GPU·Observability를 운영하는 Enterprise Control Plane  
**Know-Your-Agent** → Agent가 돈을 쓸 때 필요한 Identity·Authorization Infrastructure

이번 회차에서 특히 중요한 것은 **DeepSeek V4.1 Flash와 Know-Your-Agent**다. 한쪽에서는 Agent의 반복 호출 비용을 줄이기 위해 Model Architecture가 바뀌고 있고, 다른 한쪽에서는 Agent가 현실의 경제활동을 수행할 수 있도록 결제망의 Identity Architecture가 바뀌고 있다.

> Agent 시대의 경쟁은 더 이상 가장 똑똑한 LLM 하나의 경쟁이 아니다. Model Efficiency + Realtime Interaction + Specialized Model + Operations + Identity가 하나의 Stack으로 결합되고 있다.
