## 1. TypeSafe `Jev` — 말을 생성하지 않고 소프트웨어 안에서 바로 판단하는 AI

**관련 이미지·출처:** [TypeSafe 공식 발표](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

### 핵심 요약

TypeSafe AI가 9월 15일 첫 공개 `System One Model`인 **Jev**를 Early Access로 내놨다. 일반 LLM처럼 문자열을 한 토큰씩 생성하는 대신, 프로그램이 정의한 typed question을 입력받아 **typed decision + probability + confidence**를 한 번에 반환한다. 회사는 이를 `frontier-intelligence function call`이라고 표현한다.

학습 방식도 RLHF나 RLVR과 달리 회사가 `Reinforcement Learning for Calibrated Decisions`, RLCD라고 부르는 방법을 사용한다. 공식 가격은 **입력 10억 Token당 $42**, 즉 100만 Token당 $0.042이며 출력 Token 과금은 없다. TypeSafe 자체 Workflow 평가에서는 기존 LLM 대비 최대 **193.6배 빠르고 444.6배 저렴하다**고 주장한다. 다만 이 수치는 출시사 자체 평가이며 System One 유형의 구조화된 판단 Task에 한정된 비교다.

또 `문자열을 생성하지 않기 때문에 환각할 수 없다`는 회사의 표현도 좁게 해석해야 한다. **Schema에 없는 문자열을 만들어내는 종류의 환각과 타입 오류는 구조적으로 제거할 수 있지만, 잘못된 판단 자체가 불가능해지는 것은 아니다.**

### 왜 중요한지

지금까지 AI를 Software에 넣는 대표 패턴은 `LLM → 자연어 또는 JSON 생성 → 검증 → 프로그램이 해석`이었다. Jev는 아예 자연어 생성을 제거하고 AI를 **확률적 if문처럼 직접 프로그램 내부에 넣는 방향**을 제안한다.

이 접근이 실제 Production에서 통한다면 모든 문제에 거대한 생성형 LLM을 쓰는 대신, **Chat·Reasoning은 LLM, 빠른 분류·Routing·정책결정은 System One Model**처럼 AI Model 자체가 역할별로 분화될 가능성이 있다.

- [TypeSafe 공식 발표](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- [TypeSafe API 문서](https://docs.typesafe.ai/api)

## 2. Anthropic `one Claude` + Claude Docs·Slides — Chat과 Agent Workspace의 경계를 없앤다

**관련 이미지·출처:** [Reuters 보도](https://www.reuters.com/business/media-telecom/anthropic-fold-claude-ai-features-into-one-interface-launches-document-tools-2026-09-16/)

### 핵심 요약

Anthropic이 9월 16일 **Claude Chat과 Cowork를 하나의 Claude 경험으로 통합**한다고 발표했다. 사용자가 `이건 질문이니 Chat`, `이건 긴 작업이니 Cowork`처럼 모드를 직접 고르는 대신 Claude가 작업의 성격을 판단해 필요한 Context, Skills, Connectors와 장시간 Agent 실행 기능을 자동으로 사용한다.

동시에 **Claude Docs와 Claude Slides**를 Beta로 출시하고 Claude Design도 일반 Conversation 안으로 통합했다. Docs는 대화 안에서 문서를 만들고 공동 편집한 뒤 Google Docs나 Microsoft Word로 내보낼 수 있고, Slides는 Presentation을 만들고 직접 발표하거나 PowerPoint·PDF로 Export할 수 있다. 우선 Pro·Max 사용자에게 Web, Desktop, Mobile에서 순차 배포되고 이후 Team·Free로 확대된다.

### 왜 중요한지

AI 제품의 UI가 `Chatbot`, `Agent`, `문서 생성기`, `디자인 도구`처럼 기능별로 분리되어 있던 단계에서 벗어나고 있다. 사용자는 **무슨 Tool을 써야 하는지 고르는 대신 목표만 말하고**, Runtime이 질문인지 장시간 작업인지 판단해 적절한 능력을 불러오는 방향이다.

이 구조가 자리 잡으면 AI 제품의 핵심 인터페이스는 앱 메뉴가 아니라 **하나의 Conversation → 자동 Tool·Agent 선택 → 실제 업무 결과물**이 된다. Microsoft 365와 Google Workspace의 기존 Application 단위 UX를 AI 업체가 직접 재구성하려는 경쟁이 더 강해졌다.

## 3. Google `Home MCP` Early Access — Claude·OpenClaw 같은 외부 Agent가 집을 직접 제어

**관련 이미지·출처:** [Google Home MCP 공식 문서](https://developers.home.google.com/mcp/home)

### 핵심 요약

Google이 **Google Home MCP Server**를 Early Access로 공개했다. MCP-compatible AI Client가 Google Home의 실제 Smart Home 환경과 연결돼 집 구조와 Device를 조회하고, 실시간 상태를 읽고, 과거 Event를 분석하며, 실제 Device Action까지 실행할 수 있다.

공식 MCP Tool은 `list_homes`, `list_home_resources`, `list_home_states`, `list_home_history`, `run_home_actions`다. Google 문서에는 Antigravity, Claude Cowork, OpenClaw 연결 방법이 직접 제공돼 있다. Google은 실제 집에 Agent를 연결하는 위험을 명시하면서 Rate Limit과 Safety Protection을 적용하고 있으며 **문 잠금 해제 같은 민감 Action은 금지**한다. Familiar Faces 데이터는 별도 명시적 동의가 필요하다.

초기 접근은 미국 Google Home Premium Advanced 가입자 중심으로 순차 확대되고 있다.

### 왜 중요한지

MCP가 파일·DB·SaaS를 연결하는 개발자 Integration Protocol에서 **물리 세계 Action Protocol**로 넘어가기 시작했다.

지금까지 Smart Home은 Google Assistant나 Alexa처럼 Platform 사업자의 Assistant가 중심이었다. Home MCP는 반대로 **집을 하나의 Tool Server로 만들고 여러 Agent가 Client가 되는 구조**다.

이 패턴이 확장되면 앞으로 자동차, 로봇, 공장 설비, IoT에서도 `Vendor Assistant`보다 **표준 Agent Protocol + Permission + Physical Action Policy**가 더 중요한 Architecture가 될 수 있다.

- [Google Home MCP 공식 문서](https://developers.home.google.com/mcp/home)
- [MCP Reference](https://developers.home.google.com/reference/home/mcp)

## 4. OpenAI `Sponsored Agents` — 광고를 클릭하면 브랜드 Agent와 바로 대화

**관련 이미지·출처:** [OpenAI 공식 발표](https://openai.com/index/reimagining-advertising-with-ai/)

### 핵심 요약

OpenAI가 9월 16일 ChatGPT Ads의 새 기능으로 **Sponsored Agents** 테스트를 시작했다. 사용자가 ChatGPT 안에서 광고를 본 뒤 관심이 있으면 해당 기업이 후원한 Agent와 **명확히 광고임이 표시된 별도 Conversation**을 시작해 제품이나 서비스에 대해 추가 질문할 수 있다. 현재 미국의 일부 광고주를 대상으로 테스트 중이다.

광고주 측 Workflow도 Agent화한다. ChatGPT Work의 Ads Manager Plugin에서 자연어 Prompt만으로 Campaign 생성·수정·성과 분석을 수행할 수 있고, Ads Manager에는 Copy와 Image 제안 기능이 추가된다. OpenAI는 첫 CRM Partner로 **HubSpot**, 첫 Ecommerce Partner로 **Shopify**를 연결했다.

### 왜 중요한지

검색광고의 기본 단위는 `Keyword → Link → Website 방문`이었다. Sponsored Agents는 이를 **Intent → Conversation → 상담 → 구매 전환** 구조로 바꾼다.

즉 AI Agent가 단순한 Productivity Tool뿐 아니라 **새로운 광고 Format과 Sales Channel 자체**가 되기 시작했다. 사용자가 웹사이트를 직접 탐색하기보다 Agent와 대화해 비교·문의·구매 결정을 내리면, 기업의 경쟁력도 Landing Page 최적화에서 **브랜드 Agent의 데이터·응답 품질·Transaction 연결성**으로 이동할 수 있다.

- [OpenAI 공식 발표](https://openai.com/index/reimagining-advertising-with-ai/)
- [Reuters 보도](https://www.reuters.com/business/media-telecom/openai-tests-advertiser-sponsored-agents-expands-ai-tools-chatgpt-ads-2026-09-16/)

## 5. 🔥 GitHub `dream-loop` — 이미지 생성 → 구현 → Vision Critic을 반복하는 Agent Skill

**관련 이미지·출처:** [dream-loop GitHub](https://github.com/achimala/dream-loop)

### 핵심 요약

9월 7일 생성된 MIT 오픈소스 프로젝트 `achimala/dream-loop`가 약 9일 만에 **1.3K+ Stars와 140+ Forks**를 모았다. 프로젝트 자체는 새로운 Foundation Model이 아니라 Coding Agent에 설치하는 `SKILL.md` 기반 Workflow다.

동작 방식은 단순하지만 흥미롭다.

1. Image Generation으로 만들고 싶은 고품질 Target Screenshot을 먼저 생성한다.
2. Coding Agent가 Three.js·Blender 등을 이용해 실제 Scene이나 App을 만든다.
3. 별도의 Vision-enabled Critic Agent가 Live Screenshot과 Target을 비교한다.
4. 차이를 Feedback으로 돌려 구현을 반복한다.
5. 필요하면 현재 결과를 바탕으로 더 좋은 Target 자체를 다시 생성한다.

`npx skills add achimala/dream-loop`로 설치할 수 있고 Image Generation, Vision Input, 가능하면 Subagent가 필요하다. 작성자는 현재 GPT-6 Astra의 Codex 환경에서 주로 검증했다고 명시한다.

### 왜 중요한지

Vibe Coding의 약점 중 하나는 `기능은 동작하지만 시각적 품질이 일정 수준에서 멈춘다`는 점이다. dream-loop는 사람이 계속 `좀 더 예쁘게`라고 Feedback하는 대신 **Target Image를 Objective로 만들고 Critic Agent가 자동으로 차이를 평가**한다.

이는 Coding Agent의 다음 패턴을 잘 보여준다.

**Prompt → 한 번 생성**이 아니라 **Goal Artifact → Build → Observe → Critique → Iterate**다.

Agent Skill이 단순 Prompt 모음이 아니라 **평가와 재시도를 포함한 작은 Workflow Program**으로 진화하고 있다는 점에서 주목할 만하다.

## 이번 회차의 핵심

이번 다섯 소식은 AI가 `무엇을 생성하는가`에서 **어떻게 실제 시스템 안에서 판단하고 행동하며 결과를 반복 개선하는가**로 이동하고 있음을 보여준다.

- **Jev** → 자연어 생성 없이 Software 내부에서 바로 판단
- **one Claude** → 사용자가 Chat과 Agent Mode를 구분할 필요가 없어짐
- **Google Home MCP** → Agent Protocol이 실제 물리 Device까지 연결
- **Sponsored Agents** → Agent가 광고와 Sales Channel 자체가 됨
- **dream-loop** → Agent가 자신의 결과를 Vision Critic으로 평가하며 반복 개선

가장 큰 공통점은 **LLM 하나를 호출하는 것만으로는 더 이상 제품이 완성되지 않는다는 것**이다.

> **Decision Model → Unified Agent Runtime → MCP Tools → Business Channel → Critic Loop**

AI 제품의 경쟁 단위가 점점 `좋은 답변을 생성하는 모델`에서 **목표를 이해하고, 적절한 Tool을 고르고, 현실에 Action을 취하고, 그 결과를 다시 관찰해 개선하는 전체 Loop**로 확장되고 있다.
