## 1. OpenAI `GPT-6 Sol·Luna` 출시 — Frontier Intelligence의 가격을 절반으로

> 관련 이미지·발표 비주얼: [OpenAI 공식 발표](https://openai.com/index/introducing-gpt-6-sol-and-luna/)

### 핵심 요약
OpenAI가 9월 22일 GPT-6 Astra의 기술을 더 저렴한 계층으로 확장한 `GPT-6 Sol`과 `GPT-6 Luna`를 공개했다. API 가격은 Sol이 100만 입력 Token당 **$2**, 출력 **$10**, Luna가 입력 **$0.10**, 출력 **$0.50**으로 GPT-5.6 계열 대비 약 50% 낮아졌다. Cached Input은 90% 할인된다.

OpenAI 자체 평가에서 Sol은 DeepSWE v1.1 최대 **68.8%**, Agents’ Last Exam 최대 **56.4%**, OSWorld 2.0 Offline xhigh **60.5%**를 기록했다. Luna도 DeepSWE v1.1 최대 **66.6%**를 기록해 대량 Agent Task에 초점을 맞춘 가격대비 성능을 내세운다. 두 모델은 ChatGPT Work와 Codex, API에서 순차 제공된다.

### 왜 중요한가
Agent 경제성의 핵심 지표가 `Token당 가격`에서 **Task 하나를 끝내는 데 드는 총비용**으로 바뀌고 있다. 긴 Coding·Computer-use Agent는 Context를 반복적으로 읽기 때문에 Model 가격과 Cache Hit Rate가 실제 운영비를 크게 좌우한다. Frontier급 성능이 이 가격대로 내려오면 지금까지 비용 때문에 제한했던 상시 Agent와 대규모 병렬 Agent 운용이 훨씬 현실적이 된다.

- 출처: [OpenAI 공식 발표](https://openai.com/index/introducing-gpt-6-sol-and-luna/)

## 2. Anthropic `Claude Opus 5.5` — Fable급 성능을 더 낮은 비용과 강화된 안전장치로

> 관련 이미지·보도 비주얼: [Reuters 보도](https://www.reuters.com/business/anthropic-unveils-claude-opus-55-2026-09-22/)

### 핵심 요약
Anthropic이 9월 22일 `Claude Opus 5.5`를 공개했다. Anthropic은 대부분의 작업에서 상위 모델 Fable 5.1에 가까운 성능을 제공하면서 Opus 5보다 Typical Workload 기준 운영비를 약 **40% 낮췄다**고 설명한다. API 가격은 100만 입력 Token당 **$4**, 출력 **$20**으로 Opus 5보다 20% 저렴하다.

안전 측면에서도 Frontier Design과 METR의 외부 검증을 거쳤으며, Anthropic의 전용 평가에서는 Opus 5 또는 Mythos 5.1보다 Containment Boundary를 우회하려는 행동이 약 **85% 적었다**고 보고했다. AWS, Google Cloud, Microsoft Azure에서도 제공된다.

### 왜 중요한가
OpenAI와 Anthropic이 같은 날 내놓은 메시지는 거의 같다. 이제 Frontier 경쟁은 단순 최고 Benchmark가 아니라 **비슷한 수준의 Intelligence를 얼마나 싸고 안정적으로 반복 실행할 수 있는가**의 경쟁이다. 특히 Coding Agent나 Knowledge-work Agent는 한 번의 답변보다 수십～수백 번의 Tool Loop를 돌기 때문에 작은 비용 차이도 대규모 서비스에서는 큰 차이가 된다.

## 3. 🔥 Xiaomi `MiMo-V2.6-Pro-RL` — 1.02T MoE·1M Context·Native Omnimodal을 MIT로 공개

> 관련 이미지·Architecture: [Hugging Face Model Card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL)

### 핵심 요약
Xiaomi MiMo 팀이 `MiMo-V2.6-Pro-RL`을 MIT License로 공개했다. Sparse MoE 구조로 **총 1.02T Parameter 중 42B만 활성화**하며, Text·Image·Video·Audio를 하나의 모델에서 처리하고 Context Length는 **1M Token**이다.

가장 흥미로운 부분은 Post-training 방식이다. Xiaomi는 Coding, General Agent, Visual Agent, Cybersecurity를 별도 RL로 나누지 않고 한 번의 Mixed RL Run에서 학습하는 `You Only RL Once` 전략을 사용했다. 한 Step에 1,568 Prompt × 16 Rollout을 사용하는 Fully Asynchronous GRPO와, 통과한 Trajectory끼리도 품질을 비교하는 Groupwise Agentic Grading을 적용했다.

출시사 평가에서 Pro 모델은 DeepSWE v1.1 **71.9**, AutomationBench **53.1**, OSWorld-Verified **82.0**을 기록했다. 이 수치는 Xiaomi 측 평가이므로 독립 Benchmark와 구분해서 볼 필요가 있다.

### 왜 중요한가
오픈웨이트 경쟁이 단순히 `큰 Base Model Weight 공개`에서 **RL Environment·Harness·Grader·Agent Trajectory를 어떻게 설계하는가**로 이동하고 있다. 1M Context와 Native Omnimodal까지 MIT로 공개된 것도 의미가 크다. 기업이나 연구팀이 Frontier Agent Model을 자체 환경에서 Fine-tuning하고 검증할 수 있는 선택지가 빠르게 늘고 있다.

- 출처: [Xiaomi MiMo Hugging Face](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL)

## 4. 🔥 `vLLM v0.30.0` — GPU에 Weight를 남겨두고 Engine만 재시작하는 `Fast Start`

> 관련 이미지·Release Page: [vLLM GitHub Release](https://github.com/vllm-project/vllm/releases/tag/v0.30.0)

### 핵심 요약
오픈소스 LLM Serving Runtime vLLM이 9월 22일 `v0.30.0`을 공개했다. 이번 Release는 **315명 Contributor의 762개 Commit**을 포함한다. DeepSeek-V4.1-Flash, GLM-5.3-Flash, K2-Horizon, Cohere Compass 등 최신 Model 지원이 대거 추가됐다.

핵심 기능 `Fast Start`는 Post-quantized·Tensor-parallel Sharded Weight를 GPU Memory에 상주시키는 별도 Daemon을 두고, Engine 재시작 시 Disk에서 Model을 다시 읽는 대신 CUDA IPC로 Weight를 Mapping한다. FP4와 Multi-node TP도 지원한다. 또한 Sparse MLA의 KV Page를 Host Pinned Memory로 내리는 `HiSparse`, Gumbel-max Watermarking, Model Runner V2 최적화가 들어갔다. Release Note 기준 H200에서 CUDA Graph Capture는 **12초 → 2초**, Engine Init은 **28.9초 → 8.2초**로 줄었다.

### 왜 중요한가
LLM Serving은 더 이상 `Model을 GPU에 한 번 올려놓고 오래 실행`하는 단순 구조만으로 운영되지 않는다. Agent Traffic, Model Routing, RL Workload, Rolling Deployment에서는 Engine을 자주 재시작하거나 Model을 교체해야 한다. Weight와 Engine Lifecycle을 분리하면 **Cold Start와 Deployment 비용을 크게 줄이는 Serverless-like LLM Runtime**에 가까워진다.

- 출처: [vLLM v0.30.0 GitHub Release](https://github.com/vllm-project/vllm/releases/tag/v0.30.0)

## 5. Snorkel AI, `$350M` 조달·기업가치 `$3.5B` — AI 경쟁의 병목이 `Model`에서 `Data + Environment`로

> 관련 이미지·발표 비주얼: [Snorkel AI 공식 발표](https://snorkel.ai/blog/data-2-0-and-the-research-era-of-ai-data/)

### 핵심 요약
Snorkel AI가 9월 22일 **$350M Series E**를 유치해 **$3.5B 기업가치**를 인정받았다고 발표했다. Insight Partners와 S32가 Round를 주도했다. 회사는 Data-as-a-Service 사업을 시작한 뒤 약 1년 만에 18배 성장했고, 이번 주 Annualized Revenue Run Rate가 **$375M**을 넘었다고 밝혔다.

Snorkel의 제품 범위도 단순 Labeling에서 벗어나고 있다. Frontier Lab과 기업에 전문 Dataset뿐 아니라 **RL Environment, Evaluation Framework, Agentic Data Development**까지 제공한다. Coding, 법률, 의료처럼 전문성이 필요한 Domain의 Human Expertise와 AI Automation을 결합하는 형태다.

### 왜 중요한가
Frontier Model을 만드는 데 GPU와 Algorithm만 필요한 것이 아니다. Agent를 실제 업무에 투입하려면 좋은 Training Data, 실제와 유사한 Environment, 강한 Grader와 Evaluation Set이 필요하다. Open-weight Base Model이 풍부해질수록 차별화 자산은 오히려 **고유 Data + Environment + Evaluation Loop** 쪽으로 이동할 가능성이 높다. Snorkel의 급격한 매출 성장은 이 계층이 독립적인 대형 산업으로 성장하고 있음을 보여준다.
