**2026-09-24 08 KST**

직전 브리핑에서 다룬 GPT-6 Sol·Luna, Claude Opus 5.5, MiMo-V2.6-Pro-RL, vLLM v0.30.0, Snorkel AI, AutoOmni 2.0, Unit 42 Continuous Frontier AI Defense, GitHub Copilot OpenTelemetry, Anthropic financial-services, Univer 등은 중대한 추가 업데이트가 없어 제외했다.

## 1. Amazon `Seller Assistant Workflows` — 쇼핑몰 운영 Agent가 24시간 스스로 일한다

> 관련 이미지·발표 비주얼: [Amazon 공식 발표](https://www.aboutamazon.com/news/innovation-at-amazon/seller-assistant-plugin-amazon-quick-claude)

### 핵심 요약
Amazon이 Seller Assistant를 단순 질의응답형 도우미에서 **항상 실행되는 Agent Workflow**로 확장했다. 새 Workflow는 재고, 가격, Account Health 같은 조건을 지속적으로 모니터링하고 판매자가 설정한 Guardrail 안에서 조치할 수 있다. 모든 Action에는 Audit Trail이 남고, 판매자는 추천만 받도록 하거나 실제 Action까지 허용할 수 있다.

Seller Assistant에는 판매자의 가격 패턴, 재고 사이클, 성장 목표를 기억하는 Persistent Memory도 추가됐다. 동시에 Amazon Selling Partner Plugin을 Amazon Quick에 정식 연결하고 Anthropic Claude에서는 Beta로 제공한다. 판매자는 Claude 같은 외부 Agent에서 Amazon Listing, 실시간 성과, 재고, 판매 Analytics를 읽는 것뿐 아니라 승인 후 실제 Action까지 실행할 수 있다.

### 왜 중요한가
Agentic Commerce가 추천 Chatbot 단계를 넘어 **상시 감시 → 판단 → 승인 → 실행 → 감사기록**을 갖춘 실제 Business Automation으로 들어가고 있다. 더 중요한 변화는 Amazon이 자체 UI에 Agent를 가두지 않고 Claude 같은 외부 Agent에 Seller Action Interface를 열기 시작했다는 점이다. 앞으로 SaaS와 Marketplace의 경쟁력 중 하나는 사람이 쓰는 화면뿐 아니라 **Agent가 안전하게 행동할 수 있는 표준 Action Surface**가 될 가능성이 크다.

- 출처: [Amazon 공식 발표](https://www.aboutamazon.com/news/innovation-at-amazon/seller-assistant-plugin-amazon-quick-claude)

## 2. Tether `QVAC Genesis III` — 191.43B Token의 공개 STEM 추론 데이터셋

> 관련 이미지·프로젝트 비주얼: [QVAC Genesis](https://qvac.tether.io/products/genesis)

### 핵심 요약
Tether AI Research가 `QVAC Genesis III`를 공개했다. 규모는 **191.43B Token, 159.6M Document, 19개 STEM Domain**이며 고등학교부터 대학·전문가 수준까지 커리큘럼에 맞춘 추론 데이터를 제공한다. 목표는 모델을 더 크게 만드는 대신 작은 모델이 더 좋은 Reasoning Data를 학습하도록 해 Laptop, Phone, Local Server에서도 과학·수학·기술 문제를 더 잘 처리하게 하는 것이다.

Tether의 통제된 실험에서는 Option-Level 데이터로 학습한 1.7B 모델이 Benchmark 응답의 **99.45%에서 유효한 답 형식**을 만들었고 여러 STEM Benchmark에서 Cosmopedia-v2 기반 모델보다 개선됐다고 보고했다. 해당 연구는 COLM 2026 발표가 예정돼 있다. 데이터는 Hugging Face `qvac/GenesisIII`에서 제공되며 **CC BY-NC 4.0**이라 연구·교육에는 열려 있지만 상업적 자유 사용 License는 아니다.

### 왜 중요한가
Open-weight Model이 많아질수록 희소한 자산은 Weight보다 **좋은 학습 데이터와 Reasoning Trajectory**가 된다. Genesis III는 Frontier Lab이 독점하던 대규모 Synthetic Reasoning Corpus를 외부 연구자도 실험할 수 있게 만든다는 점에서 의미가 있다. 특히 Edge·Local AI에서 Parameter 수를 키우지 않고 Data Quality로 성능을 끌어올리는 전략을 보여준다.

- 출처: [Tether 공식 발표](https://tether.io/news/tether-releases-genesis-iii-to-train-ai-to-explain-not-just-answer-stem-problems/)
- 데이터: [QVAC Genesis](https://qvac.tether.io/products/genesis)

## 3. 🔥 Nokia `AnyJev` — 기존 Open LLM을 Fine-tuning 없이 Decision Model처럼 사용

> 관련 이미지·프로젝트: [AnyJev GitHub](https://github.com/nokia-applied-research/AnyJev)

### 핵심 요약
Nokia Applied Research가 Apache 2.0 오픈소스 `AnyJev`를 공개했다. 핵심 아이디어는 Qwen 같은 기존 Open LLM에게 자연어를 생성시키는 대신 **Choice, Boolean, Score 같은 Typed Decision과 확률 분포**를 직접 읽는 것이다. 별도의 Gradient Fine-tuning이나 Text Generation·Parsing 없이 Next-token Distribution과 Hidden State를 활용한다.

L0는 Label 없이 Position Bias와 Label Prior를 보정하고, L1은 100～500개 Label로 Probability Calibration을 적용한다. L2는 100～300개 Label로 질문별 Closed-form Head를 수초 안에 만들며 Base Model Weight는 수정하지 않는다. 프로젝트가 공개한 Qwen3-8B·BANKING77 300개 샘플 실험에서는 5% 이하 오류 조건에서 자동화 가능한 비율이 Raw Logit 7.7%에서 L1 52.0%까지 올라갔다. 이는 프로젝트 자체의 제한된 Benchmark이며 범용 성능 수치로 해석하면 안 된다.

### 왜 중요한가
최근 Jev가 보여준 `LLM은 문장을 생성하고 Decision Model은 판단값을 반환한다`는 방향을 **이미 존재하는 Open LLM 위에서도 구현할 수 있는가**를 실험하는 프로젝트다. 별도의 소형 Decision Model을 새로 학습하지 않고 기존 Local LLM의 내부 확률과 Hidden State를 재활용할 수 있다면 Routing, Tool Safety, 완료도 판정 같은 Agent 반복 의사결정의 배포 장벽이 낮아질 수 있다.

- 출처: [Nokia Applied Research AnyJev GitHub](https://github.com/nokia-applied-research/AnyJev)

## 4. 🔥 Unreal Labs `Unreal Agent` — Tool을 기다리지 않는 Async-first Agent Harness

> 관련 이미지·Benchmark: [Unreal Labs 공식 발표](https://unreallabs.ai/blog/unreal-agent/)

### 핵심 요약
Unreal Labs가 MIT 오픈소스 `Unreal Agent`를 공개했다. 일반적인 Agent Loop는 Model이 Tool을 호출하면 결과가 돌아올 때까지 기다린 뒤 다시 추론하지만, Unreal Agent는 Tool Call을 즉시 `in-progress` Event로 기록하고 실제 Tool은 Background에서 실행한다. Model은 기다림·Polling·Heartbeat 관리에 Token을 쓰지 않고 다른 작업을 계속할 수 있다.

Unreal Labs는 GPT-6 Astra 기반 Coding·Science Benchmark와 Production Workload에서 Codex 대비 **최대 40% 비용 절감**을 보고했다. 이는 출시사 측 평가지만, Repository에는 Harness Library, Runner, Benchmark Runner가 함께 공개돼 있어 구조와 실험을 직접 검증할 수 있다.

### 왜 중요한가
Agent 비용은 Model 가격만의 문제가 아니다. Tool이 수초～수분 걸리는 동안 Model Loop가 어떻게 상태를 관리하는지도 Cost per Task를 크게 좌우한다. Unreal Agent는 **Model Intelligence가 동일해도 Harness Architecture만으로 비용·응답성을 개선할 수 있다**는 점을 보여준다. Agent 경쟁이 모델에서 Runtime·Scheduler 설계까지 내려오고 있다는 또 하나의 사례다.

- 출처: [Unreal Labs 공식 발표](https://unreallabs.ai/blog/unreal-agent/)
- 코드: [Unreal Agent GitHub](https://github.com/unreallabsai/unreal-agent)

## 5. 🔥 `Prismor` — Claude Code·Codex의 Tool Call을 실행 전에 차단하는 Agent Security Control Plane

> 관련 이미지·Architecture: [Prismor 공식 사이트](https://www.prismor.dev/)

### 핵심 요약
PrismorSec가 Apache 2.0 오픈소스 `Prismor`를 공개했다. Claude Code, Codex, Cursor, LangChain 등 Agent와 실제 Tool 사이에 위치해 **모든 Tool Call을 실행 전에 Policy로 검사**하고 `allow`, `warn`, `block` 결정을 내린다. Shell Command, File Access, Secret Leakage, Prompt Injection, Package Supply-chain Risk, MCP Tool Call, Network Egress 등을 대상으로 한다.

기본은 Observe Mode로 Agent Action을 Local Dashboard에 기록하고, 필요한 Rule부터 Enforcement로 전환할 수 있다. MCP Gateway를 사용하면 여러 MCP Server 앞단에 하나의 Policy Layer를 두고 Tool Request뿐 아니라 Tool Response의 Injection도 검사한다.

### 왜 중요한가
Coding Agent가 실제 Shell, Credential, Package Manager와 MCP를 다루기 시작하면서 기존 Endpoint Security만으로는 부족해지고 있다. 중요한 것은 Agent가 위험한 행동을 **한 뒤 탐지하는 것**이 아니라 실행 직전에 의도와 Context를 보고 막는 것이다. Prismor는 Agent 시대의 보안 경계가 `Prompt Filter`에서 **Runtime Action Policy + Audit + Human Approval**로 이동하는 흐름을 보여준다.

- 출처: [Prismor 공식 문서](https://www.prismor.dev/docs/prismor)
- 코드: [Prismor GitHub](https://github.com/PrismorSec/prismor)

## 이번 회차의 핵심

이번 회차를 연결하면 다음과 같다.

**Amazon Seller Assistant → Persistent Business Agent**  
**QVAC Genesis III → Open Reasoning Data**  
**AnyJev → Typed Decision Layer**  
**Unreal Agent → Async Agent Harness**  
**Prismor → Runtime Action Security**

오늘 새롭게 확인된 흐름은 모델 자체보다 **Agent가 계속 일하고, 싸게 판단하고, 비동기로 Tool을 실행하며, 실제 Action을 안전하게 통제하는 시스템 계층**에서 더 강하게 나타났다. Frontier Model의 성능 향상이 Agent 제품으로 전환되려면 결국 `Data + Decision + Harness + Permission + Audit`이 함께 필요하다는 방향이 더 선명해지고 있다.
