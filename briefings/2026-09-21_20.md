# AI·LLM·에이전트 최신 브리핑

**2026년 9월 21일 20시 KST 기준**

직전 9월 21일 08시 브리핑의 Step 5 Preview, Qwen-Image-2.1, Needle 3, Qwen3.8-LiveTranslate, Naive AI는 중대한 추가 업데이트가 없어 제외했다. 이번 회차는 새 오픈소스 컴퓨터 사용 모델, 대규모 추론 벤치마킹, Agent-native 개발 협업, Browser Agent 보안, AI 칩용 첨단 패키징 공급망을 중심으로 선정했다.

## 1. Cua `CUA-S1-FORMS` — 706K 파라미터·2.8MB로 웹 폼 판단을 한 번에

**핵심 요약:** Cua가 MIT 라이선스로 `CUA-S1-FORMS`를 공개했다. 706,048개 학습 파라미터와 2.8MB 체크포인트를 가진 초소형 모델로, 일반 LLM처럼 문장을 생성하지 않는다. 웹 폼의 각 요소와 문서에서 추출된 후보 값을 입력받아 `fill`, `check`, `click`, `skip` 중 어떤 행동을 할지 한 번의 forward pass에서 확률로 선택한다. byte-level embedding과 2-layer Transformer encoder를 사용하며, 모델·학습 코드·합성 데이터 생성기·평가 코드가 공개됐다.

Cua 자체 평가에서는 form-disjoint synthetic test에서 99.95% top-1, 실제 3개 폼과 3개 PDF로 만든 196개 decision에서 100%를 보고했다. 다만 실제 평가 표본이 매우 작고 영어 중심 label vocabulary에 맞춰져 있으므로 일반적인 웹 자동화 성능으로 해석해서는 안 된다.

**왜 중요한지:** Jev 이후 등장한 `System One Model` 아이디어가 실제 오픈소스 컴퓨터 사용 모델로 빠르게 확장되고 있다. Agent가 모든 클릭과 선택을 Frontier LLM에게 물어보는 대신, 계획은 큰 모델이 맡고 반복적이고 범위가 좁은 판단은 수 MB급 전문 모델이 맡는 구조다. Agent 비용과 지연시간을 줄이는 가장 현실적인 방향 중 하나가 `큰 Planner + 작은 Action Model + deterministic executor` 조합일 수 있음을 보여준다.

- Model Card: https://huggingface.co/cua-ai/cua-s1-forms
- Cua: https://cua.ai/

## 2. NVIDIA `AIPerf` — GenAI-Perf를 대체하는 대규모 LLM 추론 벤치마커

**핵심 요약:** NVIDIA가 9월 18일 `AIPerf`를 본격 소개했다. Apache 2.0 오픈소스이며 GenAI-Perf의 공식 후속 도구다. 기존 단일 프로세스 벤치마커가 높은 동시성에서 Python GIL과 Client 자체 성능에 막히는 문제를 피하기 위해 worker와 result processor를 분리한 multiprocess 구조와 ZMQ를 사용한다.

AIPerf는 Chat, Responses, Embeddings, Audio, Image 등 15개 이상의 endpoint 유형을 지원하고 ShareGPT와 Mooncake·Baseten·WEKA AgentX trace replay를 사용할 수 있다. Constant, Poisson, Gamma arrival pattern과 burstiness를 조절할 수 있으며 TTFT, ITL, request latency, output-token throughput의 percentile과 GPU power·utilization·memory telemetry도 함께 수집한다.

**왜 중요한지:** AI 서비스 비용 경쟁의 중심이 학습보다 추론으로 이동하면서 `모델이 빠른가`가 아니라 `수천～수만 동시 요청에서 실제 서비스가 얼마나 안정적으로 처리되는가`를 측정하는 일이 중요해졌다. Agent는 긴 세션과 반복 Tool Call 때문에 트래픽 패턴도 일반 Chat API보다 복잡하다. 따라서 현실적인 traffic replay와 tail latency를 측정하는 벤치마킹 도구가 Model Runtime 선택과 GPU Capacity Planning의 핵심 인프라가 되고 있다.

- NVIDIA Technical Blog: https://developer.nvidia.com/blog/benchmarking-llm-inference-at-scale-with-aiperf/
- GitHub: https://github.com/ai-dynamo/aiperf

## 3. Zed `Delta` Public Beta — Pull Request 대신 Agent Thread에서 구현·리뷰·병합

**핵심 요약:** Zed가 9월 16일 `Delta`를 Public Beta로 전환했다. Delta는 Agent와 함께 코딩한 conversation, worktree, review를 하나의 thread에서 공유하는 multiplayer 개발환경이다. 다른 개발자가 thread에 들어오면 원래 Agent가 어떤 판단을 거쳐 코드를 만들었는지 그대로 볼 수 있고, 별도의 review subthread와 격리된 worktree에서 Agent와 수정 작업을 이어갈 수 있다.

기반 기술인 DeltaDB는 Git의 commit 사이에서 발생한 human·agent message와 edit를 delta 형태로 보존한다. Commit 자체는 여전히 Git checkpoint로 유지돼 기존 CI나 Git repository와 호환된다. Zed는 Delta 자체 repository에서 Pull Request를 끄고 이 방식으로 개발 중이며, 발표 시점에 33명이 main에 570개 change를 land했다고 밝혔다.

**왜 중요한지:** Agent가 생성하는 코드량이 커지면서 기존 `branch → commit → PR → diff review` 방식은 왜 그런 코드가 나왔는지에 대한 context를 잃기 쉽다. Delta는 코드 결과만 리뷰하는 대신 `요청 → Agent reasoning context → 구현 → 리뷰 → 수정 → merge` 전체를 협업 단위로 만들려 한다. Coding Agent가 발전할수록 Git 자체보다 Pull Request와 Code Review UX가 먼저 재설계될 수 있다는 강한 사례다.

- Zed 공식 발표: https://zed.dev/blog/delta-public-beta
- Delta: https://delta.dev/

## 4. BrowserSkill에 `CVE-2026-94111` — 로그인된 실제 브라우저를 다루는 Agent의 신뢰 경계 문제

**핵심 요약:** 9월 19일 브리핑에서 다룬 Tencent BrowserSkill에 중대한 보안 업데이트가 생겼다. 9월 20일 공개된 `CVE-2026-94111`은 BrowserSkill 0.3.0까지의 Local WebSocket daemon이 접속한 Chrome Extension의 Origin이 단순히 `chrome-extension://` 형태인지 확인할 뿐 실제 BrowserSkill Extension ID인지는 확인하지 않는 문제다. CVSS v4 기준 6.9이며 GitHub Issue #273은 현재도 Open 상태다.

악성 또는 공급망 공격을 받은 다른 Browser Extension이 같은 Profile에 설치되어 있으면 BrowserSkill client인 것처럼 local daemon에 연결해 Agent에게 전달되는 DOM, Page Content, Screenshot을 가로채거나 조작할 수 있다. BrowserSkill이 이미 로그인된 Browser Session을 사용한다는 특성 때문에 잘못된 perception이 곧 실제 계정에서의 잘못된 Action으로 이어질 수 있다.

**왜 중요한지:** Browser Agent의 보안 경계는 `localhost라서 안전하다`로 끝나지 않는다. Agent가 현실의 로그인 상태와 결제·메일·사내 시스템을 사용할수록 `Extension Identity → Pairing Credential → Tool Permission → Human Approval → Audit`을 명시적으로 설계해야 한다. 이번 취약점은 Browser Agent에서 perception channel 자체가 공격받으면 모델 정렬이나 Prompt Guardrail만으로는 막을 수 없다는 점을 보여준다.

- VulnCheck Advisory: https://www.vulncheck.com/advisories/tencent-browserskill-through-0.3.0-origin-validation-error-in-local-websocket-daemon
- GitHub Issue #273: https://github.com/Tencent/BrowserSkill/issues/273

## 5. 대만, TSMC 중심 `Advanced Packaging Park` 착공 — AI Chip 경쟁의 병목이 패키징으로

**핵심 요약:** 대만이 9월 21일 Kaohsiung의 Baipu Industrial Park에서 첨단 패키징 산업단지 착공식을 열었다. TSMC는 이곳에 기술 검증 Lab과 인력 교육 Centre 등 두 개 시설을 세울 예정이며 운영 목표는 2029년 4분기다. 전체 단지는 약 88.7ha이며 이 가운데 약 53.6ha가 산업용 부지다.

이 단지는 TSMC의 첨단 패키징 장비와 소재 공급사가 한곳에서 연구·시험·검증을 수행해 새로운 기술의 양산 전환 시간을 줄이는 것을 목표로 한다. TSMC의 첨단 패키징은 NVIDIA, AMD, Broadcom의 고성능 AI Chip 생산에 사용된다.

**왜 중요한지:** AI Chip 성능은 더 이상 GPU Die만으로 결정되지 않는다. HBM과 여러 Compute Die를 높은 Bandwidth로 연결하는 Advanced Packaging이 실제 공급량과 성능을 좌우하는 핵심 병목이 됐다. 대만이 제조 Fab뿐 아니라 장비·소재·검증·인력까지 패키징 생태계를 한 지역에 집적하는 것은 AI 반도체 경쟁이 `설계 → Foundry → HBM → Packaging → Power` 전체 공급망 경쟁으로 확장되고 있음을 보여준다.

- Reuters: https://www.reuters.com/world/asia-pacific/taiwan-breaks-ground-advanced-packaging-park-anchored-by-tsmc-2026-09-21/

## 이번 회차의 핵심

이번 다섯 소식은 한 흐름으로 연결된다.

**CUA-S1-FORMS → 작은 전문 Action Model**  
**AIPerf → 대규모 Inference Measurement**  
**Delta → Agent-native Software Collaboration**  
**BrowserSkill CVE → Agent Runtime Trust Boundary**  
**TSMC Packaging Park → Physical AI Compute Supply Chain**

Agent 경쟁의 초점이 `더 좋은 LLM 하나`에서 벗어나고 있다. 실제 제품에서는 작은 전문모델이 반복 행동을 처리하고, 대규모 추론 부하를 정확히 측정하며, Agent가 만든 결과를 새로운 방식으로 협업·리뷰하고, Browser와 Credential 경계를 방어하고, 마지막에는 이를 돌릴 AI Chip의 패키징 공급망까지 확보해야 한다.
