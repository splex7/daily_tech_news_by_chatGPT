## 1. NVIDIA `SoL-Pi` — AI가 Agent Harness 자체를 연구해 토큰 비용을 줄인다

![SoL-Pi](https://raw.githubusercontent.com/NVlabs/SoL-Pi/main/assets/sol-pi-hero.png)

### 핵심 요약

NVIDIA Research가 공개한 `SoL-Pi`가 주말 동안 빠르게 주목받고 있다. GitHub 저장소는 9월 2일 생성됐고 9월 14일 확인 시점 약 1.7K Stars를 기록했다. MIT 라이선스이며 Pi coding agent 위에 설치하는 독립 확장이다.

SoL-Pi의 핵심은 사람이 Harness 최적화 아이디어를 직접 설계한 것이 아니라, 수백 개의 실행 가능한 환경과 Auto-Research Loop를 만들어 **Agent가 Agent Harness를 개선하도록 한 것**이다. 연구팀은 152개 후보 방향을 탐색했고 최종적으로 네 가지 메커니즘을 남겼다.

- `Action Fusion`: 코드 수정 뒤 예상 가능한 Test·Build 명령을 같은 Tool Call 안에서 실행
- `ObservationPack`: 큰 Tool 결과를 Stable Handle로 보관하고 필요한 부분만 다시 읽기
- `Evidence-Preserving Reducer`: 긴 Log를 값싼 Agent가 먼저 읽되 인용한 근거를 원본과 검증
- `Online Context Compact`: 완료된 Subtask 경계에서 Context를 압축

NVIDIA의 자체 EdgeBench 평가에서는 Pi 대비 약 45～49% 적은 Token을 사용하고 비용을 약 3분의 1 줄였다고 보고했다. Native Codex·Claude Code Harness와 비교해서도 공식 API 가격 기준 50～54% 낮은 비용을 제시했다. 이 수치는 프로젝트 자체 평가라는 점은 감안해야 한다.

### 왜 중요한지

Agent 경쟁의 다음 단계가 단순히 **더 좋은 모델을 고르는 것**에서 **모델을 감싸는 Harness 자체를 자동으로 개선하는 것**으로 이동하고 있음을 보여준다.

특히 장시간 Coding Agent에서는 같은 Context를 반복해서 읽고, 수정 후 다시 Test를 요청하고, 긴 Log를 매번 Frontier Model이 읽는 비용이 누적된다. SoL-Pi는 이 비효율을 모델 성능이 아니라 Runtime 설계 문제로 본다.

`더 강한 모델 → 더 좋은 Agent`뿐 아니라 `더 좋은 Harness → 같은 모델로 더 많은 일을 처리`라는 별도의 Scaling 축이 생기고 있다.

## 2. DeepSeek `DeepSelect` + `deepseek-recipe` — V4.1 이후 핵심 추론·API 계층까지 오픈소스화

![DeepSeek Sparse Attention](https://raw.githubusercontent.com/deepseek-ai/DeepSelect/main/assets/perf_bf16.png)

### 핵심 요약

DeepSeek이 V4.1 계열 모델 자체에 이어 실행 인프라의 하위 계층까지 공개하기 시작했다. 9월 10일 공개된 `DeepSelect v1.0.0`은 DeepSeek Sparse Attention, DSA와 Sampling에 쓰이는 TopK CUDA Kernel 구현이다.

DeepSeek은 특정 지원 조건에서 일반 `torch.topk` 대비 **2～20배 빠르다**고 밝히고 있다. DSA의 Lightning Indexer와 약 128K vocabulary를 사용하는 sampling path를 직접 최적화한다. 성능 수치는 DeepSeek 자체 Benchmark다.

함께 공개된 `deepseek-recipe`는 Rust Library와 Python Binding으로, OpenAI 계열의 Messages·Chat Completions·Responses 요청을 공통 Conversation 형식으로 변환하고 DeepSeek V4·V4.1 Prompt로 Encoding한 뒤 모델 출력을 다시 각 API 응답 형식으로 변환한다. Text, Image, Thinking, Client Tool Call과 `apply_patch` Tool도 지원한다.

### 왜 중요한지

이번 움직임은 9월 10일 브리핑에서 다룬 V4.1 Flash 모델 출시의 반복이 아니라 **모델을 Production에 올리기 위한 실행 계층의 추가 공개**다.

오픈웨이트 모델의 실제 경쟁력은 Weight 하나만으로 결정되지 않는다.

`Model Weight → Kernel → Prompt Encoding → API Compatibility → Tool Calling → Serving Runtime`

이 Stack이 같이 공개돼야 다른 Cloud나 자체 GPU에서 효율적으로 사용할 수 있다. DeepSeek은 이제 모델 Architecture뿐 아니라 **Inference Infrastructure의 Reference Implementation**까지 생태계에 제공하고 있다.

## 3. Atlassian `Governed Agent Loops` — Jira Backlog가 항상 켜져 있는 Coding Agent 작업 큐로

![Jira Coding Agent](https://images.ctfassets.net/zsv3d0ugroxu/wLY3MNwyzgeiBe77TL3ZY/6944bd533fc00ea29f9884b33e338b34/image-jira-coding-agent-selection)

### 핵심 요약

Atlassian이 9월 10일 Jira 중심의 `Governed Agent Loops` 전략을 공개했다. 핵심은 개발자가 Coding Agent에게 매번 Prompt를 보내는 방식이 아니라, Jira가 잘 정의된 미할당 Work Item을 지속적으로 탐색해 Agent에게 맡기고 Test 후 Ready-to-review PR까지 만드는 **상시 Agent Loop**다.

`Code Context`는 Teamwork Graph를 이용해 여러 Repository와 Jira·문서·조직 Context를 Agent에게 제공하고, `Agent Context Controls`는 어떤 Agent가 어떤 Context를 볼 수 있는지 제한한다. 조직의 Coding Standard를 Repository에 연결하는 `Standards`, 모든 PR을 사람보다 먼저 검사하는 `AI Review`, Agent 사용량과 효과를 보는 Dashboard도 함께 제시했다.

현재 Code Context는 Paid 고객 대상으로 Open Beta가 순차 배포 중이고 Agent Loops, Standards, AI Review는 Private Early Access다.

### 왜 중요한지

Coding Agent의 운영 단위가 **한 번의 Session**에서 **지속적으로 돌아가는 Software Delivery Loop**로 이동하고 있다.

이 단계에서는 모델 Benchmark보다 다음이 더 중요해진다.

`Shared Context → Permission → Work Queue → Parallel Execution → Test → Review → Audit`

즉 Jira가 단순 Issue Tracker에서 **사람과 Agent가 함께 사용하는 Work Orchestrator**로 진화하려는 것이다. 기업에서 Agent를 수십～수백 명의 개발자에게 확장하려면 이런 Governance Layer가 핵심 인프라가 될 가능성이 높다.

**Source**  
https://www.atlassian.com/blog/jira/governed-agent-loops

## 4. OpenAI `ChatGPT for Financial Services` — 모델 + 유료 금융데이터 + 회사 템플릿을 하나의 제품으로

![Financial AI workflow](https://blog.hops.pub/en/img/en/blog/2025-02-13-ai-automation-examples/morgan_stanley.png)

### 핵심 요약

OpenAI가 9월 10일 `ChatGPT for Financial Services`를 출시했다. GPT‑6 Astra의 Reasoning에 Daloopa, PitchBook, LSEG News 같은 Premium Financial Data를 기본 탑재해 Investment Research, Financial Model, Client Material을 생성하도록 만든 ChatGPT Work의 금융 특화 제품이다.

Morgan Stanley와 Evercore가 Design Partner로 참여했다. OpenAI가 Premium Data를 직접 Index하고 Hosting해 세부 Citation을 제공하며, 기존 FactSet·S&P Global·Preqin·Datasite 같은 Data Provider 연결도 지원한다.

관리자는 회사의 Excel, Word, PowerPoint Template과 Style Guide를 배포할 수 있고, SAML SSO, SCIM, Role-based Access Control, Retention Policy, Compliance Log Export 같은 규제산업용 통제 기능도 포함한다.

### 왜 중요한지

기업 AI 경쟁이 범용 `ChatGPT Enterprise`를 판매하는 단계에서 **산업별 완제품**으로 이동하고 있다.

금융에서는 모델 자체보다도 `신뢰할 수 있는 데이터`, `출처`, `회사의 계산 방식`, `문서 형식`, `권한과 감사`가 중요하다. 따라서 경쟁력은 자연스럽게 다음 조합으로 옮겨간다.

`Frontier Model + Licensed Data + Domain Workflow + Firm Template + Compliance`

이는 향후 법률, 의료, 반도체, 제조 등에서도 비슷한 Vertical AI 제품이 늘어날 가능성을 보여준다.

## 5. Fortaegis `$50M` 조달 — AI 보안을 Software가 아니라 Silicon의 고유 Fingerprint에서 시작

### 핵심 요약

Financial Times가 9월 13일 네덜란드 Deep-tech Startup `Fortaegis`가 **$50M**을 조달해 Encrypted Silicon 기술을 2027년까지 상용화한다고 보도했다. 투자자에는 Serendipity Capital과 Tokyo Electron의 Venture Arm 등이 포함된다.

Fortaegis의 접근은 각 Silicon Chip의 물리적 고유 특성을 Digital Fingerprint로 사용해 Key를 만들고, 이를 기반으로 분산된 Compute Node 사이의 신뢰를 Hardware Level에서 구축하는 것이다. 회사는 Defense, Space, Telecom, Data Center 분야의 약 25개 기업·정부기관과 협력 중이며, ASML 및 Eindhoven University와 Autonomous AI System을 위한 Security Framework도 연구하고 있다.

### 왜 중요한지

Agent와 Physical AI가 현실 세계에서 더 많은 권한을 갖게 되면 보안의 기준점도 Application Layer보다 아래로 내려가야 한다.

특히 Drone Swarm, Autonomous Vehicle, Edge AI, 분산 Inference Cluster에서는 각 Node가 **정말 신뢰할 수 있는 Hardware인지**를 검증하는 문제가 중요하다.

AI Security Stack이

`Prompt Guardrail → Runtime Permission → Network Security → Trusted Hardware`

까지 확장되고 있다는 신호다. AI 인프라 투자에서 Security Silicon이 독립적인 시장으로 커질 가능성도 있다.

## 이번 회차의 핵심

이번 다섯 소식은 모델 자체보다 **모델을 실제로 계속 일하게 만드는 주변 계층**이 빠르게 발전하고 있다는 공통점을 가진다.

- **SoL-Pi** → Agent가 Harness 자체를 자동 연구·최적화
- **DeepSelect + deepseek-recipe** → Open Model의 Kernel·Protocol Layer 공개
- **Atlassian** → Agent를 조직의 상시 업무 Loop에 편입
- **ChatGPT for Financial Services** → 모델을 산업 데이터와 Workflow에 결합
- **Fortaegis** → AI Runtime의 Trust를 Hardware까지 확장

가장 주목할 흐름은 `Model Scaling` 다음에 **Harness Scaling과 Workflow Scaling**이 독립적인 경쟁축으로 자리 잡고 있다는 점이다.

> **같은 Frontier Model을 쓰더라도 Context를 덜 반복하고, Tool을 더 효율적으로 호출하며, 조직의 업무와 데이터에 더 깊게 연결하고, 실행 환경을 더 안전하게 만드는 쪽이 실제 생산성을 결정하기 시작했다.**
