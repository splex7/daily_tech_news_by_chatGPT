## 1. Perceptron Mk1.5 — 현실 세계를 제어하는 Embodied Agent 모델

**핵심 요약:** Perceptron이 9월 25일 Perceptron Mk1.5를 공개했다. 텍스트·이미지·비디오·오디오를 입력으로 받고 텍스트뿐 아니라 point, box, polygon, clip, object track을 출력한다. Native Audio, Video Tracking, Web Search, Sub-agent 호출, Tool Calling을 지원하며 회사는 드론, quadruped, 스마트글라스, 스마트폰에 별도 플랫폼별 재학습 없이 적용했다고 설명한다. 회사 자체 측정에서 Tool 사용 시 MMSearch가 36.1%p 개선됐고, Mk1 대비 End-to-end 완료시간은 workload에 따라 약 2～5배, 최대 4.7배 빨라졌다고 보고했다. 32K Multimodal Context이며 API 가격은 100만 Token당 입력 $0.15, 출력 $1.50이다.

**왜 중요한가:** 멀티모달 모델이 사진을 설명하는 단계를 넘어 현실 세계를 인식하고 Tool을 골라 물리적 행동까지 수행하는 Control Model로 이동하고 있다.

출처: https://www.perceptron.inc/blog/introducing-perceptron-mk1-5

## 2. Fireworks Ember-1 — Kimi K3의 긴 생각을 줄이는 Reasoning-Efficiency 모델

**핵심 요약:** Fireworks Research가 Kimi K3 기반 Ember-1을 공개했다. Fireworks 자체 평가에서는 Kimi K3와 비슷한 품질을 유지하면서 전체 Token을 약 40% 줄였고, 여러 Benchmark와 Production A/B Test에서도 Reasoning을 35～50% 줄일 수 있었다고 보고했다. Ember-1은 1.04M Context, Image Input, Function Calling을 지원하며 Research Preview로 제공된다.

**왜 중요한가:** Agent Cost는 Token 단가뿐 아니라 Task 하나를 끝낼 때 생성하고 다시 읽는 Reasoning Token의 양에 좌우된다. Reasoning Efficiency가 독립적인 모델 성능 축으로 자리 잡을 가능성이 커지고 있다.

출처: https://fireworks.ai/blog/ember-1

## 3. paperclipai/paperclip — GitHub Trending 1위, AI Agent를 회사처럼 관리한다

**핵심 요약:** paperclipai/paperclip이 9월 26일 GitHub Trending에서 가장 강한 상승세를 보이고 있다. Paperclip은 Claude Code, Codex, Cursor, OpenClaw 같은 기존 Agent를 한 조직 안에서 운영하는 Open-source Control Plane이다. Agent별 역할과 조직도, 목표, Ticket, Heartbeat, 승인과 Review Gate, Budget, Cost Tracking, RBAC, Audit Log 등을 제공한다.

**왜 중요한가:** Agent 수가 늘면 핵심 문제는 모델 성능보다 누가 무엇을 하고 있는지, 얼마를 쓰는지, 누가 승인하는지가 된다. Multi-Agent 시대의 조직 운영 계층이 별도 소프트웨어 범주로 형성되고 있다.

출처: https://github.com/paperclipai/paperclip
트렌드: https://gitnova.dev/en/day/2026-09-26

## 4. Google AX — 오래 실행되는 Agent를 위한 Distributed Runtime 재부상

**핵심 요약:** Google의 Apache 2.0 오픈소스 AX, Agent Executor가 이번 주 GitHub에서 다시 빠르게 상승하고 있다. AX는 Agent Framework가 아니라 Agent를 오래 실행하는 Runtime으로, Controller와 Event Log를 중심으로 Agent·Skill·Tool·Sandbox를 격리된 Actor로 실행하고 Durable Execution, Snapshot, Failure Recovery, Connection Resume, Session Consistency, Trajectory Branching을 제공한다.

**왜 중요한가:** Agent가 수시간～수일 동안 일하기 시작하면 기존 Web Server와 다른 Runtime 문제가 생긴다. Agent Infra가 LLM Loop Library에서 Stateful Distributed Runtime으로 이동하고 있다는 신호다.

출처: https://cloud.google.com/blog/products/ai-machine-learning/agent-executor-googles-distributed-agent-runtime/
GitHub: https://github.com/google/ax

## 5. MemTensor MemOS 공급망 사고 — Agent Memory 계층의 보안 위험이 현실화

**핵심 요약:** Socket과 Semgrep은 MemTensor의 Agent Memory 관련 npm·PyPI 패키지 일부 릴리스가 공격으로 변조돼 사용자 환경의 민감 정보와 Agent 입력 데이터가 노출될 수 있었던 공급망 사고를 분석했다. 공격 코드는 일반 설치 단계보다 실제 모듈 사용 시점에 실행되도록 설계돼 전통적인 설치 단계 검사만으로 탐지하기 어려웠다.

**왜 중요한가:** Agent의 Plugin, Skill, MCP, Memory Module은 Repository, API Key, Prompt, 장기 Memory 등 많은 자원에 접근할 수 있다. Agent Supply Chain에서는 Package Version 관리뿐 아니라 Runtime Network 정책, Credential Isolation, Artifact 검증, Permission Review가 기본 보안 요소가 되어야 한다.

출처: https://socket.dev/blog/memtensor-compromise
출처: https://semgrep.dev/blog/2026/the-ai-ecosystem-has-worms-now-inside-the-memtensor-compromise/
