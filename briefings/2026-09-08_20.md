## 1. OpenBMB `MiniCPM5-2B` 공개 — 2.5B 모델에 Agent·Coding 성능과 학습 데이터까지 담았다

> 관련 이미지: [OpenBMB MiniCPM5 공식 게시물](https://x.com/OpenBMB/status/2058903449379717319)

### 핵심 요약
OpenBMB가 9월 8일 `MiniCPM5-2B`를 공개했다. 실제 파라미터 수는 약 25.17억, 42-layer의 표준 `LlamaForCausalLM` 구조이며 native context는 131,072 tokens다. 로컬 Assistant, Coding Agent, Tool-use, Reasoning을 목표로 설계됐고 Apache 2.0 라이선스로 제공된다.

OpenBMB 자체 비교에서는 34개 Benchmark 평균 53.9로 동급 2B 모델군 최상위였고, 일부 4B급 비교 모델의 평균도 넘어섰다. 특히 SWE-bench Verified 46.4, GAIA Text-103 88.7, BrowseComp-ZH 43.5 등 Agent·Tool 영역이 강점으로 제시됐다. 다만 상당수 점수는 OpenBMB 내부 재현 결과이므로 독립 Benchmark와는 구분해서 볼 필요가 있다.

이번 공개에서 더 중요한 점은 Weight만이 아니다. OpenBMB는 `UltraX`, `UltraData-Code`, Agent용 50만 샘플 `UltraData-SFT-Agent-2609`, 수학·코드·지식·장문 추론을 포함한 8만+ RL 샘플 `UltraData-RL-2609`도 함께 공개했다. GGUF, MLX 4bit, GPTQ 4bit, LiteRT-LM, speculative decoding용 DSpark draft model도 제공한다.

### 왜 중요한지
초소형 모델의 경쟁이 단순 Chat 품질에서 **Agent 실행 능력**으로 이동하고 있다. 2B급 모델이 Tool-use, Coding Agent, Search Agent까지 실용 수준으로 올라오면 모든 요청을 Frontier API에 보낼 필요가 없다.

구조적으로는 다음과 같은 배치가 현실적이 된다.

`Local 2B Model → 분류·검색·간단한 Tool Call → 어려운 문제만 Frontier Model`

또한 학습 데이터와 여러 Training Stage checkpoint까지 함께 공개한 점은 단순 Open Weight보다 재현성과 후속 연구 가치가 높다.

`Model → Compute → Data Control → Deployment Control → Geopolitical Supply Chain`

특히 Samsung과 EU 자본이 동시에 들어온 것은 AI Sovereignty가 기술 철학을 넘어 실제 대규모 자본 배분 기준이 되고 있음을 보여준다.

## 3. GitHub 급상승 `DeepSeek Harness` — 21.5만+ Stars, Agent Runtime을 전부 Plugin으로 분해

> 관련 이미지: [DeepSeek Harness 관련 이미지](https://note.com/ai_observatory_/n/n1a0b908f990a)

### 핵심 요약
DeepSeek의 오픈소스 `deepseek-harness`, 즉 `dsh`가 GitHub에서 21.5만+ Stars를 기록하며 Agent Infrastructure 프로젝트 중 가장 빠르게 커지는 저장소 중 하나가 됐다. MIT 라이선스이며 현재 Developer Preview다.

핵심 철학은 `Everything is a Plugin`이다. Model, Tool, Skill, Session, Sandbox, Storage, Agent Loop, UI 같은 Harness 구성요소를 Core에 고정하지 않고 교체 가능한 Plugin으로 취급한다. 기반 설계는 DeepSeek의 `Cordis` composability architecture다.

실행도 단순하다.

```bash
npx @deepseek-ai/dsh web
```

다만 DeepSeek가 명시하듯 아직 Developer Preview이며 compatibility-breaking change가 계속 발생할 수 있다.

### 왜 중요한지
같은 LLM을 사용해도 Claude Code, Codex, Hermes, OpenClaw 등의 결과가 다른 가장 큰 이유 중 하나는 모델 바깥의 **Harness**다.

DeepSeek Harness가 주목받는 이유는 Agent Runtime을 특정 제품의 단일 구현으로 보지 않고 다음 계층을 서로 교체 가능한 Architecture로 보기 때문이다.

`Model + Session + Memory + Tools + Sandbox + Loop + UI`

Kubernetes가 Container 실행방식을 표준화했듯 Agent 생태계에서도 모델과 실행 Harness를 분리하는 방향이 강해지고 있다.

## 4. `OpenViking 0.4.18` — Agent Memory·RAG·Skill을 하나의 `viking://` 파일시스템으로

> 관련 이미지: [OpenViking 관련 이미지](https://www.aitoolnet.com/openviking)

### 핵심 요약
Volcengine의 `OpenViking`이 9월 8일 `v0.4.18`을 배포했다. 현재 GitHub Stars는 약 3.6만이다. OpenViking은 Agent의 Memory, 외부 Resource, Skill을 별도 시스템으로 분리하지 않고 `viking://` Virtual Filesystem 아래에서 하나의 Context Database로 관리한다.

Agent는 Vector DB를 Black Box처럼 호출하는 대신 `ls`, `tree`, `find`와 비슷한 방식으로 Context를 탐색한다. 데이터는 L0 Abstract, L1 Overview, L2 Detail 세 단계로 저장되어 필요한 깊이만 읽는다. Retrieval 과정의 Directory 경로도 남아 어떤 Context가 답변에 들어갔는지 추적할 수 있다.

Claude Code, Codex, OpenClaw, Hermes, Cursor, OpenCode, pi, MCP Client, LangChain·LangGraph 등과 통합할 수 있다. 본체는 AGPLv3이며 일부 CLI·예제 구성요소는 Apache 2.0이다.

### 왜 중요한지
오전 브리핑의 ContextPilot이 `모델이 무엇을 기억하고 버릴 것인가`를 학습하는 접근이었다면, OpenViking은 그 Context를 **모델 밖의 지속 가능한 Database**로 만드는 접근이다.

장시간 Agent에서는 Context Window를 계속 키우는 것보다 다음 구조가 더 현실적일 수 있다.

`Session → 압축된 Memory → 계층형 Context DB → 필요한 부분만 Retrieval`

특히 Memory·Resource·Skill을 같은 Namespace로 두면 모델을 Claude에서 Codex나 Local Model로 바꿔도 Context 자산은 그대로 남는다.

## 5. OpenAI, Firmus와 말레이시아 Compute 장기계약 — 계약 Capacity 900MW 돌파

> 관련 이미지: [Firmus Data Center 관련 이미지](https://www.medcom.id/teknologi/news-teknologi/Dkq1e4pk-nvidia-bangun-pusat-data-ai-di-batam-proyek-360-mw-siap-beroperasi-2027)

### 핵심 요약
NVIDIA가 투자한 호주 AI Infrastructure 기업 Firmus가 OpenAI와 다년 계약을 체결해 말레이시아 Data Center 두 곳의 Compute Capacity를 공급한다. 이 계약으로 OpenAI가 Anchor Customer가 됐으며 Firmus의 전체 고객 계약 Capacity는 900MW를 넘어섰다.

Firmus는 현재 호주와 싱가포르에서 AI Data Center 두 곳을 운영하고 있고, Asia-Pacific에서 추가 다섯 곳을 개발 중이다. 향후 NVIDIA Vera Rubin Processor도 지역 전반에 대규모 배치할 계획이다. 계약 금액은 공개되지 않았다.

### 왜 중요한지
Frontier AI의 경쟁은 이제 GPU를 사는 문제가 아니라 **수년 전부터 전력과 Data Center Capacity를 예약하는 문제**가 되고 있다.

`Power → Data Center → GPU → Model Training·Inference → Agent Service`

OpenAI가 미국이 아니라 말레이시아에서 장기 Capacity를 확보한 것은 동남아시아가 AI Compute 공급망의 중요한 축으로 편입되고 있음을 보여준다. 동시에 말레이시아 Data Center의 전력 사용이 급증하고 있어 Compute 확장의 병목이 반도체에서 전력·냉각·Grid로 이동하고 있다는 점도 분명해지고 있다.

## 이번 회차의 핵심 흐름

이번 5개를 연결하면 AI 산업이 `더 큰 모델` 하나로 설명되지 않는 단계에 들어섰다.

- **MiniCPM5-2B** → 작은 모델도 Agent·Tool-use를 수행
- **DeepSeek Harness** → 모델 바깥의 Agent Runtime을 모듈화
- **OpenViking** → Context와 Memory를 모델 밖의 자산으로 지속
- **Mistral** → Open-weight + Sovereign Infrastructure에 대형 자본 투입
- **OpenAI·Firmus** → Frontier AI가 전력·Data Center Capacity를 장기 선점

이번 회차에서 특히 중요한 조합은 **MiniCPM5-2B + DeepSeek Harness + OpenViking**이다. 모델 자체는 점점 더 작고 교체 가능해지는 반면, Harness와 Memory·Context는 계속 남는 방향이 선명해지고 있다.

> **Agent 시대의 장기 자산은 특정 LLM 하나보다 Data + Context + Skill + Harness + Compute에 가깝다.**
