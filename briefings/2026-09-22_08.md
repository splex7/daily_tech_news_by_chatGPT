## 1. SpaceXAI `Grok 4.7` — 장시간 Coding·Agent Task를 정면으로 겨냥

> 관련 이미지 및 공식 발표: https://x.ai/news/grok-4-7

### 핵심 요약

SpaceXAI가 9월 21일 `Grok 4.7`을 출시했습니다. Grok 4.6보다 더 큰 Base Model을 사용하고, 수시간이 걸리는 문제에 비중을 둔 더 긴 Reinforcement Learning을 적용했습니다. 모델 스스로 작업을 검증하는 능력과 Long-context 관리도 강화했습니다.

API 모델 `grok-4.7`은 Text와 Image 입력, Text 출력을 지원하며 Context Window는 500K입니다. 200K Prompt Token 이하 기준 가격은 입력 $2, Cached Input $0.50, 출력 $6 per 1M Token이며 Reasoning Effort는 low, medium, high, xhigh를 지원합니다.

SpaceXAI 자체 Benchmark에서는 CursorBench 4.0 46.3%, DeepSWE v1.1 71.0%, AA Briefcase 1657을 기록했습니다. 독립 평가기관 Artificial Analysis에서도 Intelligence Index 46으로 Grok 4.6보다 2점 상승했고, Grok Build를 이용한 Coding Agent Index는 47에서 56으로 상승했습니다.

### 왜 중요한지

이번 출시는 단순 Chat Model 업그레이드보다 `오래 실행되는 Agent가 얼마나 안정적으로 작업을 이어가고 스스로 결과를 확인하는가`에 초점이 맞춰져 있습니다.

Coding Agent 경쟁의 기준이 단일 문제 정답률에서 **Long-horizon Task + Harness + Self-verification + Cost** 조합으로 이동하고 있다는 신호입니다. Grok 4.7이 500K Context와 비교적 낮은 API 가격을 유지하면서 Coding Agent 성능을 끌어올렸다는 점도 가격 경쟁에 압력을 줄 가능성이 있습니다.

## 2. Aikido `Altar` — 1.51TB GLM-5.3을 328GB로 줄인 보안 특화 Open-weight Model

> 관련 이미지 및 공식 발표: https://www.aikido.dev/blog/aikido-altar-open-weight-ai-sovereign-security

### 핵심 요약

벨기에 Cybersecurity 업체 Aikido가 9월 21일 첫 Open-weight Security Model `Altar`를 공개했습니다. 기반 모델은 Z.AI의 GLM-5.3이며, Quantization과 MoE Expert Pruning을 조합해 Full BF16 기준 1,506.7GB의 Weight를 328GB까지 줄였습니다.

GLM-5.3의 각 Backbone Expert Layer에 있던 256개 Routed Expert 가운데 168개를 유지하고 88개를 제거했습니다. Aikido 자체 CVE Benchmark에서는 30개 Repository의 32개 실제 취약점을 대상으로 Altar가 평균 Recall 60.4%를 기록했고, 3회 실행 중 한 번 이상 발견한 취약점은 23개였습니다. Quantized GLM-5.3 AWQ의 61.5%와 거의 비슷한 수준입니다.

Aikido는 Altar를 4개의 NVIDIA H200이 있는 Node에서 vLLM으로 운영할 수 있다고 설명하며, Aikido Machine처럼 인터넷과 완전히 분리된 Air-gapped 환경에도 배포할 수 있도록 설계했습니다.

### 왜 중요한지

기업 보안 Agent가 실제 Source Code, 미수정 취약점, 내부 Architecture를 다루기 시작하면서 `데이터를 외부 Frontier API로 보낼 수 없는 조직`이 큰 시장이 되고 있습니다.

Altar는 거대한 범용 Open Model을 그대로 배포하는 대신 **특정 업무에서 많이 쓰는 Expert만 남겨 Domain Model로 압축**하는 접근입니다. 앞으로 법률·금융·의료·보안처럼 규제와 데이터 주권이 중요한 분야에서는 `범용 Frontier Model API`와 별도로 **조직 내부에서 구동되는 Specialist Open-weight Model** 시장이 커질 가능성이 있습니다.

## 3. Google `AX v0.3.0` — Kubernetes에 Agent용 Control Plane을 만든다

> 관련 이미지 및 배경 설명: https://cloud.google.com/blog/products/ai-machine-learning/agent-executor-googles-distributed-agent-runtime/

### 핵심 요약

Google의 Apache 2.0 Open-source Agent Runtime `AX`, Agent Executor가 9월 20일 `v0.3.0`을 공개했습니다. AX는 Agent를 일반 Stateless Microservice나 Batch Job이 아니라 **상태를 오래 유지하고 중단·복구가 필요한 새로운 Workload**로 취급합니다.

구조는 Kubernetes와 매우 유사합니다. `Task`, `Workspace`, `Gateway`, `Model` 네 가지 Declarative Primitive를 YAML로 정의하고 `ax apply`, `ax get`, `ax watch`, `ax ssh`, `ax suspend`, `ax resume` 같은 kubectl 형태의 CLI로 제어합니다.

각 Agent Task는 Sandbox에서 격리되고 CPU·Memory Limit을 가질 수 있습니다. Workspace에는 Git Repository, MCP Server, Skill을 미리 연결할 수 있고 Gateway는 Agent가 접근할 수 있는 외부 Host를 Allowlist로 제한합니다. 중단된 Agent는 Suspend 후 상태를 유지한 채 Resume할 수 있습니다.

### 왜 중요한지

Agent가 수분이 아니라 수시간～수일 동안 동작하기 시작하면 기존 Kubernetes의 `Pod를 실행한다`만으로는 충분하지 않습니다. Agent에는 **Workspace State, Network Permission, Credential, Cost Control, Suspend·Resume, Audit**가 필요합니다.

AX는 이 문제를 Kubernetes 위의 별도 Agent Control Plane으로 정의합니다. 향후 Agent Infra가 성숙하면 Kubernetes가 Container의 표준 Runtime이 된 것처럼, 그 위에 **Agent Task를 선언하고 격리·중단·복구하는 별도 Orchestration Layer**가 자리 잡을 가능성이 있습니다.

## 4. `Strands Harness SDK 0.1` — AWS에서 출발했지만 Any Model·Any Cloud Agent Harness로

> 관련 이미지 및 프로젝트: https://github.com/strands-agents/harness-sdk

### 핵심 요약

Strands Agents가 9월 21일 늦게 전용 `Harness SDK` 패키징을 시작하며 Python `harness-python/v0.1.0`과 TypeScript `harness-typescript/v0.1.0`을 공개했습니다. Python은 곧이어 `v0.1.1`로 업데이트됐습니다.

Strands Harness SDK는 자체 Hosted Control Plane이 아니라 Application Process 안에서 Agent Loop를 실행하는 Apache 2.0 SDK입니다. Turn Limit, Token Budget, Cancellation, Tool·Structured Output, MCP, Multi-agent Pattern, Memory·Session, Streaming, Guardrail, Tracing, Evaluation을 하나의 Runtime에서 제공합니다.

기본 Model Provider는 Amazon Bedrock이지만 Anthropic, OpenAI, Gemini, Ollama 등으로 교체할 수 있으며 프로젝트는 이를 `Any model, any cloud` 구조로 설명합니다. GitHub 저장소는 현재 약 7.4K Stars 규모입니다.

### 왜 중요한지

최근 Agent 제품의 차이는 LLM 자체보다 **Context 관리, Tool Loop, Memory, Guardrail, Evaluation, Multi-agent Orchestration을 어떻게 묶는가**에서 커지고 있습니다. 이 계층을 일반적으로 `Harness`라고 부르기 시작했습니다.

Strands가 AWS 전용 Framework가 아니라 Model과 Cloud를 교체할 수 있는 독립 Harness SDK를 명시적으로 내세운 것은 Agent Framework 경쟁의 중심이 `모델 호출 Library`에서 **Agent Runtime의 제어권**으로 이동하고 있음을 보여줍니다.

## 5. AMD, 사상 첫 `$1T` 기업가치 돌파 — NVIDIA 외 AI Compute 생태계에 대한 시장의 베팅

> 관련 이미지: https://www.amd.com/en/products/software/rocm.html

### 핵심 요약

Reuters에 따르면 AMD가 9월 21일 사상 처음으로 시가총액 $1T를 넘어섰습니다. 장중 주가는 약 9.6% 상승해 사상 최고가인 $613대까지 올랐으며, 2026년 들어 AMD 주가는 약 185% 상승했습니다.

AMD는 개별 GPU 판매에서 벗어나 Accelerator, CPU, Networking, ROCm Software를 묶은 **전체 AI System** 전략을 강화하고 있습니다. 시장에서는 AMD가 NVIDIA에 가장 직접적으로 도전할 수 있는 AI Accelerator 공급자이자 Intel의 Server CPU 점유율을 가져오는 사업자로 평가받고 있습니다.

### 왜 중요한지

$1T라는 숫자 자체가 기술력을 증명하는 것은 아니지만, AI Infrastructure 투자가 NVIDIA 한 회사만의 이야기에서 **복수의 Compute Platform 경쟁**으로 확대될 것이라는 자본시장의 기대를 보여줍니다.

AI Data Center가 계속 확대되려면 단일 Vendor의 GPU만으로는 가격·공급량·Power·고객 협상력 측면에서 한계가 있습니다. AMD가 Hardware뿐 아니라 ROCm과 System-level Platform까지 경쟁력을 확보할 수 있다면 AI Compute 시장은 `NVIDIA 독주`에서 **여러 Accelerator Stack이 경쟁하는 구조**로 조금씩 이동할 수 있습니다.

## 이번 회차의 핵심

이번 회차는 AI 경쟁의 범위가 모델에서 실행환경과 물리적 Compute까지 동시에 넓어지는 모습을 보여줍니다.

**Grok 4.7 → Long-horizon Frontier Agent Intelligence**  
**Aikido Altar → Sovereign Specialist Open-weight Model**  
**Google AX → Kubernetes-native Agent Control Plane**  
**Strands Harness → Portable Agent Runtime**  
**AMD $1T → Multi-vendor AI Compute Economy**

특히 중요한 흐름은 `좋은 모델 하나를 API로 호출하는 것`만으로 Agent 제품을 만들던 단계가 끝나가고 있다는 점입니다. 앞으로의 경쟁력은 **Model + Harness + Sandbox + Network Policy + Memory + Evaluation + Compute Infrastructure** 전체 Stack을 얼마나 효율적으로 설계하느냐에 더 크게 좌우될 가능성이 있습니다.
