## 1. Alibaba, Qwen을 5～10조 파라미터까지 키우고 `Zhenwu V900`으로 Full-stack AI 승부

![Alibaba T-Head AI infrastructure](https://chinabizinsider.com/wp-content/uploads/2026/05/alibaba-t-head-ai-chip-roadmap.jpg)

**핵심 요약:** Alibaba가 9월 22일 Apsara Conference에서 차세대 Qwen 모델을 **5～10조 파라미터** 규모까지 확장하는 로드맵을 공개했다. 현재 플래그십 Qwen 3.8 Max보다 최대 약 4배 큰 규모다. 동시에 자체 반도체 조직 T-Head의 `Zhenwu V900` AI 가속기를 공개했으며, 기존 제품 대비 약 3배 성능을 목표로 하고 2027년 초 양산을 계획하고 있다. Alibaba Cloud는 2032년까지 글로벌 데이터센터 용량을 **20GW 이상**으로 확대한다는 목표도 제시했다.

Reuters에 따르면 Alibaba는 모델, 칩, 슈퍼노드, 데이터센터를 한 회사 안에서 함께 설계하는 방향을 분명히 했다. 발표 당일 주가는 5.1% 상승했다.

**왜 중요한지:** AI 경쟁의 단위가 모델 하나에서 **Model → Accelerator → Supernode → Data Center → Agent** 전체 Stack으로 확대되고 있다. Alibaba가 NVIDIA나 외부 Cloud에 전적으로 의존하지 않고 이 전체 계층을 수직 통합할 수 있다면 중국 AI 생태계의 가장 강력한 대안 Stack 가운데 하나가 된다. 특히 5～10조 파라미터 모델은 단순 규모 경쟁보다 장시간 Agent 작업과 복잡한 Reasoning을 위한 Compute Architecture까지 함께 바꿀 수 있다는 점이 중요하다.

## 2. Meta `Muse`, Amazon은 차단하고 Shopify는 결제 통합 — Agentic Commerce의 첫 플랫폼 전쟁

![Meta Muse](https://www.socialsamosa.com/h-upload/2026/09/10/1500x900_1816714-meta-muse.webp)

**핵심 요약:** Meta의 개인 AI Agent `Muse`가 출시 2주 만에 전자상거래 플랫폼의 상반된 대응을 동시에 맞았다. Amazon은 Muse가 사용자 대신 Amazon에서 쇼핑하는 기능을 차단했다. Amazon은 Muse가 Agent임을 명확히 식별하지 않은 채 사이트를 이용하고, 고객 계정과 Credential을 다룬다는 점을 보안·프라이버시 문제로 제기했다. 반대로 Shopify는 9월 22일 Muse에 **Shop Pay Agentic Checkout**을 통합하기로 했다.

Meta의 공식 설명에 따르면 Muse는 전용 Secure VM과 Browser에서 동작하고, 구매·메일 전송 같은 민감한 행동 전에는 사용자 승인을 요청하며 별도의 Sentinel Agent가 외부 통신을 검사한다.

**왜 중요한지:** Agentic Commerce의 핵심 경쟁이 `AI가 제품을 잘 추천하는가`를 넘어 **누가 Agent에게 사이트 접근권과 결제권을 허용할 것인가**로 이동하고 있다. Shopify처럼 Agent를 새로운 판매 채널로 보는 플랫폼과, Amazon처럼 고객 관계·광고·Credential 통제를 지키려는 플랫폼이 갈리기 시작했다. 앞으로 웹의 기본 전제도 `사람이 Browser로 방문한다`에서 **Agent가 사용자를 대신해 협상하고 구매한다**로 바뀔 수 있다.

## 3. China Telecom `Xing4.0-29B-A4B` — 29B 모델이 Token당 4B만 쓰고 소비자 GPU까지 노린다

![Xing4.0-29B-A4B](https://opengraph.githubassets.com/1/XingChen-AGI/Xing4.0-29B-A4B)

**핵심 요약:** China Telecom AI가 `Xing4.0-29B-A4B`를 공식 발표했다. 총 **29B Parameter**의 MoE 모델이지만 Token당 활성화되는 Parameter는 **4B**에 불과하다. Native Context는 **256K**, 최대 **512K**까지 확장할 수 있으며 Multi-step Planning, Tool Calling, 긴 Reasoning Chain을 겨냥한 Agent-oriented Architecture를 사용한다.

특히 이 모델은 학습 전체를 **Huawei Ascend NPU + MindSpore**에서 수행했다. 공식 Repository는 vLLM, SGLang, KTransformers, LLaMA-Factory와 OpenCode·Claude Code·OpenClaw·Hermes 같은 Agent 환경과의 통합을 안내한다. 개발팀은 Quantization을 적용하면 단일 소비자급 GPU에서도 실행 가능한 배포 경로를 제공한다.

**왜 중요한지:** 이 모델의 의미는 Benchmark 하나보다 **Open Model + 중국산 Accelerator + 중국산 Framework + Agent Runtime**이 하나의 독립 Stack으로 연결됐다는 데 있다. 동시에 29B급 모델에서 실제 활성 Parameter를 4B로 줄인 설계는 Local Agent가 Cloud Frontier Model의 일부 업무를 가져갈 수 있는 현실적인 비용 구조를 보여준다.

- GitHub: https://github.com/XingChen-AGI/Xing4.0-29B-A4B

## 4. 🔥 Builder.io `agent-native`, GitHub Trending 1위 — UI와 Agent가 같은 Action을 공유한다

![BuilderIO agent-native](https://opengraph.githubassets.com/1/BuilderIO/agent-native)

**핵심 요약:** Builder.io의 MIT 오픈소스 TypeScript Framework `agent-native`가 9월 22일 GitHub Trending 전체 1위에 올랐고, 추적 서비스 기준 하루 **+607 Stars**를 기록했다. 현재 GitHub에서는 약 5.6K Stars 규모다.

핵심 아이디어는 Agent에게 UI를 클릭하게 하는 것이 아니다. 기능을 하나의 `Action`으로 정의하면 **Agent Tool과 React UI가 동일한 Validation·Permission·Implementation을 공유**한다. 같은 Action을 HTTP, MCP, A2A, CLI에도 노출할 수 있으며 Shared Data, UI State, Authentication, Skills, Memory, Automation, Agent Teams, PostgreSQL Backend까지 포함한다.

**왜 중요한지:** 지금까지 많은 Agent App은 기존 SaaS UI 위에 Chatbot을 붙이거나 Browser Agent가 화면을 대신 클릭하는 구조였다. Agent-native는 반대로 **UI와 Agent를 처음부터 동등한 Client로 설계**한다. 이 패턴이 확산되면 다음 세대 Business App은 `사람용 UI + Agent용 API`를 별도로 만드는 대신 하나의 Action Layer를 공유하는 구조로 바뀔 수 있다.

- GitHub: https://github.com/BuilderIO/agent-native

## 5. ⚠️ Z.ai `ZCode`, 무단 Codebase Upload 논란 뒤 기능 제거·오픈소스 전환

![ZCode](https://opengraph.githubassets.com/1/zai-org/ZCode)

**핵심 요약:** 중국 Z.ai의 Coding Agent `ZCode`가 사용자의 Local Repository를 명시적 동의 없이 Alibaba Cloud로 업로드했다는 사용자 보고 이후 일부 기능을 중단하고 사과했다. 문제는 기본 활성화돼 있던 Codebase Indexing·Repo Wiki 경로에서 발생한 것으로 알려졌으며, Z.ai는 v3.14.0에서 해당 기능과 Local Snapshot Upload 경로를 제거했다고 밝혔다.

이어 Z.ai는 ZCode의 Desktop·Web·Backend·Agent CLI·Runtime Source를 GitHub에 공개했고 현재 Repository에는 **Apache 2.0 License**가 적용돼 있다. 회사는 업로드된 Code가 학습에 사용되지 않았고 저장 데이터도 삭제됐다고 밝혔으며, 외부 기관의 점검 결과도 공개했다.

**왜 중요한지:** Coding Agent에게 가장 민감한 자산은 Prompt가 아니라 **Repository 자체**다. 자동 Indexing, RAG, Remote Agent 기능이 편리하더라도 개발자가 모르는 Network Egress가 존재하면 Source Code와 Git History 전체가 조직 밖으로 나갈 수 있다. Enterprise Agent의 기본 보안요건은 앞으로 **Explicit Opt-in → Repo Scope → Egress Policy → Credential Isolation → Audit Log → Deletion Proof**까지 포함해야 한다. Open-source 전환은 검증 가능성을 높이지만, 데이터 흐름을 처음부터 투명하게 설계해야 한다는 교훈 자체가 더 중요하다.

- 보도: https://indianexpress.com/article/technology/artificial-intelligence/chinas-z-ai-disables-ai-coding-assistant-features-after-security-issue-10888434/
- GitHub: https://github.com/zai-org/ZCode
