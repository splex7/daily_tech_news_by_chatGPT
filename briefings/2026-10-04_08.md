## 1. Aleph Alpha Kolibri — 78.1B MoE 오픈 웨이트 모델, 100만 토큰 컨텍스트

**관련 이미지·공식 발표:** https://aleph-alpha.com/en/blog/kolibri-has-landed-a-sovereign-open-weight-model/

### 핵심 요약
Aleph Alpha가 10월 3일 Kolibri를 공개했다. 영어·독일어 중심 Mixture-of-Experts Transformer로 총 78.1B parameters 가운데 token당 3.46B가 활성화된다. 최대 1M token context를 지원하며 전체 weight는 Hugging Face에 Apache 2.0 License로 공개됐다. 20T token pretraining, 50개의 all-MoE layer, layer당 384 experts, token당 6 active experts 구조를 사용하며 reasoning mode를 none, low, medium, high로 제공한다.

### 왜 중요한지
오픈 모델 경쟁이 parameter 수나 benchmark뿐 아니라 긴 context, sparse MoE 효율, self-hosting, 지역별 AI 주권으로 확장되고 있다. Apache 2.0 weight와 1M context 조합은 내부 문서·코드 기반 Agent를 자체 환경에서 구축하려는 기업에 의미가 크다.

## 2. Strands Decider 2B — Agent의 빠른 결정을 작은 모델로 분리

**관련 이미지·공식 발표:** https://strandsagents.com/blog/introducing-strands-decider/

### 핵심 요약
Strands Agents 팀이 10월 1일 Strands Decider 2B를 공개했다. 범용 LLM이 아니라 routing, tool selection, guardrail, policy classification처럼 선택지 사이에서 빠르게 판단하는 작업에 특화된 open-source decision model이다. Qwen3.5-2B 기반으로 GitHub에 model code, training data, training script를 공개하고 weights도 Hugging Face에서 제공한다. 공식 측정에서는 RTX 3090에서 median 약 115ms, M3 MacBook의 작은 task에서 약 153ms를 보고했다.

### 왜 중요한지
Agent가 모든 판단을 frontier LLM에 맡기면 latency와 token cost가 증가한다. 반복적인 routing과 policy 결정을 작은 local model에 맡기고 복잡한 추론만 큰 LLM에 보내는 multi-model Agent architecture가 현실적인 대안으로 부상하고 있다.

**출처**
- Strands Agents, 2026-10-01: https://strandsagents.com/blog/introducing-strands-decider/
- GitHub: https://github.com/strands-labs/strands-decider

## 3. OpenDots — 항상 켜져 있는 AI 동료를 오픈소스로 구현

**관련 이미지·공식 발표:** https://www.copilotkit.ai/blog/introducing-opendots

### 핵심 요약
CopilotKit이 10월 1일 OpenDots를 공개했다. persistent AI coworker 개념을 self-host할 수 있는 MIT License 오픈소스 프로젝트다. 각 Dot은 역할과 permission을 따로 가지며 필요하면 browser, file system, terminal을 포함한 computer를 사용할 수 있다. text, voice call, Slack, human approval, browser takeover, scheduled task, memory·automatic learning을 지원하고 AG-UI agent와 OpenAI-compatible model을 연결할 수 있다. GitHub 저장소는 10월 4일 오전 기준 약 2.4K stars를 기록했다.

### 왜 중요한지
Agent 제품이 채팅형 assistant에서 상태를 유지하고 자신의 computer를 가지며 여러 channel에서 계속 일하는 digital coworker로 이동하고 있다. OpenDots는 이 제품 형태를 self-host하고 수정할 수 있는 공개 stack으로 제공한다.

## 4. Uber MCP Gateway — 수백 팀의 Agent를 하나의 MCP 관리 계층으로

**관련 이미지·공식 발표:** https://www.uber.com/us/en/blog/designing-mcp-gateway/

### 핵심 요약
Uber가 10월 1일 사내 MCP Gateway 설계를 공개했다. 초기에는 각 팀이 MCP integration을 따로 만들었지만, 수백 팀으로 확산되면서 tool discovery, reliability, security, duplicated infrastructure 문제가 커졌다. Uber는 이를 해결하기 위해 AI Agent와 기존 HTTP, gRPC, TChannel service 및 native MCP server 사이에 중앙 Gateway를 두고 protocol translation, registry, observability, governance를 통합했다. AutoCrawler는 내부 IDL registry를 지속적으로 탐색해 기존 API를 MCP tool catalog에 자동 반영한다.

### 왜 중요한지
MCP가 개인 개발자의 몇 개 tool을 연결하는 수준에서 기업 전체의 agent-to-service control plane으로 이동하고 있다는 실제 대규모 사례다. 앞으로 기업 Agent 플랫폼의 경쟁력은 model뿐 아니라 tool registry, permission, routing, observability와 governance를 얼마나 잘 표준화하느냐에 달릴 가능성이 높다.

**출처**
- Uber Engineering, 2026-10-01: https://www.uber.com/us/en/blog/designing-mcp-gateway/

## 5. DeepSeek × Huawei Ascend — CUDA 의존도를 낮추는 오픈소스 AI 소프트웨어 스택

**관련 코드·원문:** https://github.com/deepseek-ai/DeepGEMM-Ascend

### 핵심 요약
DeepSeek가 9월 30일 Huawei Ascend 950용 DeepGEMM-Ascend를 공개하고, DeepEP-Ascend와 TileLang 등 Ascend용 AI 개발 stack을 확장했다. DeepGEMM-Ascend는 기존 DeepGEMM API와 호환되며 BF16, FP8, FP4 GEMM과 MegaMoE 등을 지원한다. 프로젝트는 Ascend의 저수준 matrix operation과 memory layout 복잡성을 감추면서 기존 DeepGEMM과 유사한 개발 workflow를 유지하도록 설계됐다.

### 왜 중요한지
NVIDIA의 우위는 GPU hardware뿐 아니라 CUDA를 중심으로 축적된 software ecosystem에서 나온다. DeepSeek와 Huawei가 GEMM, expert-parallel communication, kernel language까지 open-source로 채우기 시작했다는 것은 AI accelerator 경쟁이 chip 성능을 넘어 developer stack과 API compatibility 경쟁으로 이동한다는 의미다.
