## 1. 🔥 Browser Use `jev-ultrafast` — 4일 만에 10K Stars, Browser Agent를 “생성”보다 “Typed Decision” 중심으로

![Jev Ultrafast](https://raw.githubusercontent.com/browser-use/jev-ultrafast/main/docs/banner.svg)

### 핵심 요약

Browser Use가 9월 16일 공개한 MIT 오픈소스 `jev-ultrafast`가 확인 시점 약 **10.3K Stars, 625 Forks**까지 빠르게 성장했습니다. 이 프로젝트는 9월 17일 브리핑에서 다룬 TypeSafe `Jev` 자체의 후속 응용 사례입니다. 일반 LLM이 매 단계마다 자연어로 브라우저 행동을 생성하는 대신, **Jev가 현재 페이지의 인덱스화된 요소 가운데 어떤 Operation과 Target을 선택할지 Typed Decision으로 결정**하고, 실제 문자열 입력이 필요한 `TYPE_TEXT`에서만 작은 LLM을 사용합니다.

기본 Loop는 Screenshot을 모델에 보내지 않고 DOM 기반 Structured State를 읽습니다. 실행 가능한 Operation은 `CLICK`, `TYPE_TEXT`, `SELECT`, `SCROLL_UP`, `SCROLL_DOWN`, `WAIT`, `DONE`, `BLOCKED`로 제한되며, 모델 출력이 Selector·좌표·Shell Command·Executable JavaScript가 되지 않도록 경계를 둡니다.

공개된 Google Flights Zürich → London 데모는 **7.073초**에 완료됐습니다. 동일 설정을 번갈아 3회씩 실행한 소규모 비교에서 두 버전 모두 3/3 성공했고, 중앙값 Task Time은 **9.450초 → 7.092초**, Browser Protocol Call은 **1,092 → 101**로 줄었습니다. 개발팀도 이 수치가 단일 Task의 3회 반복일 뿐 일반 Reliability Benchmark는 아니라고 명시합니다.

### 왜 중요한지

Browser Agent의 병목은 반드시 더 큰 LLM이 필요한 문제가 아닐 수 있습니다. 클릭·선택·스크롤 같은 반복 행동은 **자연어 생성 대신 작은 Typed Decision Model로 처리하고, 언어 생성은 정말 필요한 순간에만 호출**하는 구조가 Latency와 비용을 크게 줄일 수 있습니다.

즉 Agent Architecture가 `한 Frontier LLM이 모든 것을 생성`에서 **Planner / Decision Model / Text Generator / Deterministic Executor**로 분화되는 흐름입니다. Jev가 실험적인 모델 출시에서 며칠 만에 실제 Browser Runtime으로 연결됐다는 점이 특히 주목할 만합니다.

출처: https://github.com/browser-use/jev-ultrafast

## 2. 🔥 Qwen `Qwen-MM-Plugins` — 오늘 `video-spatio` 합류, Agent가 3D 공간과 실제 하드웨어를 다룬다

![Qwen MM Plugins Architecture](https://raw.githubusercontent.com/QwenLM/Qwen-MM-Plugins/main/docs/assets/architecture.svg)

### 핵심 요약

QwenLM의 Apache 2.0 오픈소스 `Qwen-MM-Plugins`가 확인 시점 약 **2.9K Stars**를 기록하고 있으며, 9월 20일 **17:36 KST**에 `video-spatio` Spatial Reasoning Tool이 Main Branch에 Merge됐습니다. 프로젝트 목표는 Claude Code, Codex, OpenClaw, Qwen Code, Gemini CLI, DeepSeek Harness, Hermes Agent 등 기존 Agent Harness를 **Multimodal-native**하게 만드는 것입니다.

새 `video-spatio` Capability는 이미지와 비디오를 보고 **거리, 크기, 방향, 좌우·전후 관계, Camera Motion, 3D Counting** 같은 질문을 처리합니다. Perception은 Multimodal Model이 맡고, 실제 Geometry 계산은 Stateless Tool이 수행합니다.

또 다른 핵심 Capability인 `mhs`는 Model Hardware Standard Adapter를 통해 **Camera, Sensor, Lamp, Robot Arm, Lab Equipment** 같은 실제 장비를 MCP Tool처럼 제어합니다. Hardware Owner가 Adapter를 실행하고, Host-side Safety Limit과 Emergency Stop을 둡니다. Qwen 측 설명대로라면 MHS는 “MCP가 Software Tool에 하던 역할을 Hardware에 적용”하는 방향입니다.

### 왜 중요한지

Agent 생태계의 다음 단계는 Text Tool만 많이 붙이는 것이 아니라 **Image·Video·3D·Physical Hardware를 동일한 Skill·Tool Interface로 다루는 것**입니다.

특히 `video-spatio + MHS` 조합은 `카메라로 상황 인식 → 공간관계 계산 → 실제 장비에 Action`이라는 Physical Agent Loop를 구성할 수 있게 합니다. 중요한 점은 Safety Limit과 Emergency Stop을 Model Prompt가 아니라 **Host Runtime 쪽에 둔다는 것**입니다. Physical AI에서는 이런 Architecture가 모델 성능만큼 중요해질 가능성이 큽니다.

출처: https://github.com/QwenLM/Qwen-MM-Plugins

MHS 문서: https://qwenlm.github.io/qwen-mm-plugins-hub/plugins/mhs/

## 3. xAI `Grok Voice Transcribe 2.0` — Streaming STT 1위 주장, Loom이 Production에 채택

### 핵심 요약

xAI가 9월 18일 `Grok Voice Transcribe 2.0`을 공개했습니다. xAI는 Public Artificial Analysis Leaderboard에서 **32개 Streaming Speech-to-Text Model 가운데 Accuracy 1위**라고 밝혔으며, 자사 Short-phrase Multilingual Set에서는 Word Error Rate가 **20.6% → 6.8%**로 줄었다고 보고했습니다.

실전 기능도 Voice Agent에 맞춰져 있습니다. Batch와 Streaming을 모두 지원하고, **Word-level Timestamp, Speaker Diarization, 최대 8 Channel, 최대 100개 Key-term Biasing, Smart Turn Detection**을 제공합니다. Atlassian은 기존 솔루션보다 정확하다고 평가해 현재 **Loom의 모든 Video Transcription에 Grok Voice Transcribe 2.0을 사용**한다고 xAI가 밝혔습니다.

가격은 기존과 동일하게 **Batch $0.10 / audio hour, Streaming $0.20 / audio hour**입니다. 최신 API 문서에서는 `grok-voice-transcribe-2.0`이 기본 모델로 표시됩니다.

### 왜 중요한지

Voice Agent는 LLM 하나만 좋아져서는 충분하지 않습니다. 실제 사용자가 말한 **사람 이름, 제품명, 이메일, 전화번호, 억양, Noise, Speaker 전환**을 정확히 받아들이는 Front-end가 전체 Agent 품질을 결정합니다.

특히 Loom처럼 대규모 Production Service가 바로 채택한 것은 단순 Benchmark 발표보다 의미가 큽니다. 그리고 $0.10～$0.20/hour 가격이면 회의, Call Center, Video Archive를 대규모로 Agent-readable Text로 변환하는 비용 장벽도 크게 낮아집니다.

출처: https://x.ai/news/grok-voice-transcribe-2

문서: https://docs.x.ai/developers/models/speech-to-text

## 4. Alibaba `HappyOyster` — 완성된 Video가 아니라 “들어가서 바꿀 수 있는 세계”를 생성

### 핵심 요약

Alibaba Cloud가 9월 18일 문서와 API를 업데이트하며 `HappyOyster` Interactive Open-world Model Series를 국제 Model Studio에서 본격 제공하기 시작했습니다. Text와 First-frame Image에서 **실시간으로 참여 가능한 Video World**를 생성하며, 세 가지 Mode를 제공합니다.

`Adventure`는 First·Third-person으로 생성된 세계를 이동하고 싸우거나 탈것을 이용하며 1분 이상 계속 탐험합니다. `Directing`은 최대 **3분 Streaming Video**를 생성하면서 중간에 지시를 넣어 Character, Camera, Environment를 바꾸고 **Pause, Rewind, Branching**할 수 있습니다. `Acting`은 생성된 Character와 실시간으로 대화하면 표정·행동·Voice로 반응하며 3분간 Appearance와 Persona를 유지합니다. Acting은 현재 Invitation Preview입니다.

Directing에는 실제 `rewind` API까지 제공됩니다. 즉 단순히 Prompt를 다시 넣어 비슷한 Clip을 재생성하는 것이 아니라, 실행 중인 World State를 특정 시점으로 되돌려 다른 방향으로 진행시키는 구조입니다.

### 왜 중요한지

Video Generation 경쟁이 `더 사실적인 10초 Clip`에서 **Stateful, Controllable, Interactive World**로 이동하고 있습니다.

이 구조는 Game, Interactive Drama, AI Companion, Film Previsualization뿐 아니라 장기적으로 **World Model → Simulation → Embodied Agent Training**으로 연결될 수 있습니다. 생성형 Video와 Game Engine의 경계가 조금씩 흐려지고 있다는 신호입니다.

출처: https://www.alibabacloud.com/help/en/model-studio/happyoyster-overview

## 5. CXMT, 5세대 DRAM Platform 양산 — 중국 Memory 자립이 한 단계 전진

### 핵심 요약

Reuters에 따르면 중국 최대 DRAM 업체 CXMT가 9월 20일 **5세대 DRAM Technology Platform의 Mass Production 진입**을 발표했습니다. CXMT는 Memory Cell 핵심 Feature Spacing을 **11.95nm**까지 줄였고, Quadruple Patterning을 이용했다고 밝혔습니다.

같은 Platform으로 **24Gb LPDDR5X 두 제품**도 공개했습니다. 이전 동급 제품보다 저장용량이 50% 크고 이미 양산 중이며, 8Gb 기준 Gross Die Production per Wafer도 4세대 Platform보다 **최소 50% 증가**했다고 회사는 주장합니다. Reuters는 이 진전이 Samsung Electronics, SK hynix, Micron이 지배해온 Global DRAM Market에서 중국이 더 강한 경쟁자를 만들 수 있는 이정표라고 평가했습니다.

### 왜 중요한지

AI Infrastructure의 병목은 GPU만이 아닙니다. DRAM·HBM·NAND 같은 Memory 공급망도 Compute Expansion의 핵심 제약입니다. CXMT의 이번 발표가 곧바로 HBM 경쟁력으로 이어지는 것은 아니지만, 중국이 Advanced Memory Manufacturing에서 **해외 장비·공급망 의존도를 낮추면서 Yield와 Density를 함께 끌어올리고 있다는 신호**입니다.

최근 CXMT가 NAND 진출까지 검토하고 있다는 보도와 함께 보면, 중국의 Semiconductor 전략은 Logic Chip뿐 아니라 **DRAM + NAND + AI Accelerator** 전 영역의 자립으로 확장되고 있습니다.

## 이번 회차의 핵심

이번 다섯 소식을 연결하면 AI Stack의 경쟁 단위가 다시 넓어지고 있습니다.

**Jev Ultrafast → Typed Decision Agent**  
**Qwen MM Plugins → Multimodal·Physical Tool Layer**  
**Grok Voice Transcribe 2.0 → Real-world Audio Interface**  
**HappyOyster → Interactive World Model**  
**CXMT → Memory Supply Chain**

특히 눈에 띄는 방향은 **“모든 것을 거대한 생성형 LLM 하나가 처리한다”는 구조에서 벗어나는 것**입니다. 브라우저 행동은 작은 Decision Model로, 공간 계산은 Deterministic Geometry Tool로, 실제 장비의 Safety는 Host Runtime으로, Voice Input은 전문 STT Model로 분리됩니다. AI 제품의 성능은 점점 `가장 좋은 모델 하나`가 아니라 **각 역할을 어떤 Model·Tool·Runtime에 맡겨 전체 Loop를 얼마나 빠르고 안전하게 구성하는가**에 의해 결정되고 있습니다.
