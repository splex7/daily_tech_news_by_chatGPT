## 1. Google `Gemini 3.8 Live`·`Live Extended Thinking` — 말하면서 뒤에서 추론·Tool Call을 계속한다

![Gemini Live](https://www.humai.blog/content/images/2025/05/Stream-_-Google-AI-Studio.jpeg)

**핵심 요약:** Google DeepMind가 9월 15일 `Gemini 3.8 Live`와 `Gemini 3.8 Live Extended Thinking`을 공개했다. 두 모델은 Text·Image·Audio·Video를 입력받고 실시간 Audio·Text를 출력하는 Gemini Audio 계열이며 최대 약 128K Input Context와 64K Output을 지원한다. 기본 Live 모델은 낮은 Latency와 대규모 Voice Agent 배포를, Extended Thinking은 복잡한 Multi-step Reasoning을 목표로 한다.

특히 Extended Thinking은 음성 응답을 완전히 멈추고 추론이 끝나기를 기다리는 대신 **대화를 이어가면서 Background Reasoning과 비동기 Tool Call을 수행**한다. 예를 들어 여행 Agent가 "항공편을 확인하고 있습니다"라고 말하는 동안 여러 API를 호출하고 비교를 계속할 수 있다. Google의 Live API는 이를 위해 `interaction_status`로 전체 작업이 실제 완료됐는지를 별도로 추적한다. Gemini 3.8 Live는 동기·비동기 Function Calling을, Extended Thinking은 비동기 Tool 실행을 중심으로 설계됐다.

Google은 Extended Thinking이 자사 공개 평가에서 Speech-to-Speech Quality Index 82.6, τ-Voice 68.6%, τ-Voice-banking 35.1%를 기록했다고 밝혔다. 이 수치는 출시사 발표 기준이며 독립 평가와는 구분할 필요가 있다. 두 모델은 Gemini API와 Google AI Studio 등에 배포되고 있다.

**왜 중요한지:** Voice Agent의 구조가 `듣기 → 생각하기 → Tool 실행 → 침묵 → 말하기`에서 **말하기와 추론·행동이 동시에 진행되는 비동기 Agent Runtime**으로 이동하고 있다. 실제 고객지원·예약·현장지원에서는 Tool 응답이 수 초 걸리는 경우가 많기 때문에 이 변화는 단순 음질 개선보다 중요하다. Voice UX에서 모델 Intelligence뿐 아니라 Background Task, Tool Latency Masking, Session State가 핵심 기술이 되기 시작했다.

## 2. Salesforce `Koa` — Open-weight Nemotron에 27년 CRM 지식을 Post-training한 전용 Reasoning Model

![Salesforce Agentforce](https://cdn.prod.website-files.com/692ea911015699113c4f99bf/692ea911015699113c4fa0ad_AD_4nXddLybGia9bLRJUWQuB0cKnOH_OKFb9dpDr24sf2DlBG245PqGdtn_8JAhTtOVp8ohdtidu5HdPA5PbxkWYA4NE4UQ3i1PwPT11OidI885dL2FMoVhh9XmgGmefg5qbrIGrFLeD0g.png)

**핵심 요약:** Salesforce와 NVIDIA가 9월 15일 Salesforce의 첫 CRM 전용 Reasoning Model `Koa`를 공개했다. Koa는 NVIDIA의 Open-weight `Nemotron 3 Super`를 기반으로 Salesforce가 약 27년 동안 축적한 CRM 업무 지식을 반영한 **Synthetic Enterprise Workflow Dataset**으로 Post-training했다. 실제 고객 데이터는 Training에 사용하지 않았다고 Salesforce는 밝혔다.

Training은 SFT와 GRPO 기반 Reinforcement Learning을 결합했으며, Lead 생성·Opportunity Qualification·Case 처리 등 실제 CRM Agent가 수행하는 Tool-use 절차를 학습했다. Synthetic Scenario는 제조·금융·의료·여행 등 14개 이상의 산업 Workflow를 모델링한다. Salesforce는 Model Weight를 직접 통제하고 Post-training과 Inference를 자사 Trust Boundary 안에서 운영한다.

Salesforce 자체 CRM Benchmark에서는 Opportunity Update, Case Routing, Follow-up Scheduling 같은 작업에서 선도 모델과 비슷하거나 더 높은 성능을 내면서 오류를 3배 줄였다고 주장한다. 현재 일부 Agentforce 고객 대상으로 Pilot 중이며 미국 지역의 General Availability는 Winter 2026로 예정돼 있다.

**왜 중요한지:** 기업 AI의 현실적인 전략이 `Frontier API 하나를 모든 업무에 사용`하는 방식에서 **강력한 Open-weight Base Model + 기업의 Workflow Knowledge + Domain Post-training**으로 분화되고 있다. 특히 Salesforce처럼 수십 년의 업무 Process를 가진 SaaS 업체는 고객 원문 데이터를 Training에 넣지 않고도 Synthetic Workflow를 통해 고유한 Domain Intelligence를 모델 Weight에 내장할 수 있다. 기업 데이터의 경쟁력이 문서 RAG를 넘어 **훈련 Recipe와 Synthetic Task Design**으로 이동하는 사례다.

## 3. 🔥 GitHub `Gemini CLI v0.61.0-preview.0` — 10.7만 Stars 오픈소스 Agent, 간접 Prompt Injection과 Sandbox 경계 강화

![Gemini CLI](https://assets.apidog.com/blog-next/2025/06/Screenshot-2025-06-25-at-5.43.10-PM.png)

**핵심 요약:** Google의 Apache 2.0 오픈소스 Terminal Agent `google-gemini/gemini-cli`가 9월 16일 새벽 KST 기준 `v0.61.0-preview.0`을 공개했다. 확인 시점 저장소는 약 **107K Stars, 14.6K Forks** 규모다.

이번 Preview에서 가장 중요한 변화는 기능 추가보다 **Agent Runtime Security**다. Release Note에는 `build file modifications and untrusted flags`를 통한 **Indirect Prompt Injection 방지**, Sandbox의 Filesystem Boundary 강화 및 Runtime State 격리, AgentLoopContext 상태 보존 수정이 포함됐다. 즉 Repository 안의 Build Script나 설정값처럼 LLM이 읽게 되는 간접 입력이 Agent 행동을 오염시키는 경로를 직접 방어하고 있다.

**왜 중요한지:** Coding Agent는 사용자의 Prompt만 읽지 않는다. Repository의 README, Build File, Package Script, Test Output, Web Content까지 Context로 받아들이기 때문에 공격자가 코드베이스 내부에 Instruction을 심어 Tool 실행을 유도할 수 있다. 따라서 Agent 보안의 핵심은 `좋은 System Prompt`를 넘어 **Trusted/Untrusted Input 분리 + Filesystem Sandbox + Runtime State Isolation**으로 이동한다. 10만 Stars를 넘는 대표 오픈소스 Coding Agent가 이 문제를 Release 단위 핵심 수정으로 다룬다는 것 자체가 생태계의 우선순위 변화를 보여준다.

출처: [Gemini CLI GitHub](https://github.com/google-gemini/gemini-cli), [v0.61.0-preview.0 Release](https://github.com/google-gemini/gemini-cli/releases/tag/v0.61.0-preview.0)

## 4. Axelera AI, `Europa`로 AI Factory 공급계약 — 유럽산 Inference Accelerator가 Dell·Supermicro Server로

![Axelera Europa AIPU](https://mms.businesswire.com/media/20251021493990/en/2615745/22/Axelera-AI-Europa-AIPU-Top-View_2.jpg)

**핵심 요약:** Reuters에 따르면 네덜란드 AI 반도체 스타트업 Axelera AI가 9월 15일 여러 AI Factory 공급계약을 확보했으며, 2세대 `Europa` AIPU를 지정된 Dell·Supermicro 시스템에 넣어 Enterprise Inference 시장으로 확대하고 있다. 회사는 현재 600개 이상의 고객이 Axelera Chip을 사용하고 있고, 이미 체결한 계약은 수천만 달러 규모라고 밝혔다. 별도로 추적 중인 잠재 Sales Pipeline은 $1.5B이지만 이는 확정 주문이나 매출이 아니다.

Europa는 기존 Edge 중심의 Metis보다 무거운 Enterprise Server Workload를 겨냥한다. Axelera 공식 사양은 629 TOPS, 45W TDP, 128MB On-chip L2 SRAM을 제시하며 단일 Chip 최대 32B급, Multi-chip 구성에서 최대 100B급 LLM 활용을 목표로 한다. Axelera는 EU 지원 IT4LIA와 Luxembourg의 MeluXina AI Factory 프로젝트에도 참여하고 있으며, 후속 `Titania` Chiplet Architecture는 Data Center와 Supercomputer를 겨냥한다.

**왜 중요한지:** 유럽의 AI Sovereignty가 `유럽산 LLM`만으로는 완성되지 않는다. 실제 Agent와 Model을 돌릴 **Inference Silicon + Server OEM + AI Factory**가 함께 있어야 한다. Axelera가 Edge Accelerator에서 Dell·Supermicro 기반 Enterprise Server와 EU AI Factory로 올라가는 흐름은 NVIDIA를 바로 대체한다는 의미보다, 지역별로 **Inference 특화 Accelerator의 공급망이 다변화**되고 있음을 보여준다. Agent 사용량이 늘수록 Training Peak Performance보다 전력당·비용당 Inference Capacity가 더 큰 시장이 될 수 있다.

## 5. Factory, `$200M` 조달·기업가치 `$5B` — Coding Agent가 개발자 도구에서 `Software Factory`로

![Factory AI Coding Agent](https://cdn.aiidelist.com/api/image/21DaIuhjZe2_6RKBLDzq8.webp)

**핵심 요약:** Enterprise Coding Agent 업체 Factory가 9월 15일 **$200M**을 신규 조달하며 기업가치 **$5B**를 인정받았다. 4월의 $1.5B 평가에서 약 5개월 만에 3배 이상 상승한 것이다. Reuters에 따르면 투자자는 Blackstone, Khosla Ventures, Sequoia Capital, Insight Partners, Evantic Capital, Sound Ventures 등이다.

Factory는 기업 개발팀이 AI Agent로 Software를 Build·Test·Maintain하도록 하는 플랫폼을 제공한다. 회사는 개별 개발자가 Coding Assistant 하나를 쓰는 단계에서 벗어나 여러 Agent가 조직의 개발 Workflow 안에서 지속적으로 일하는 `Software Factory`를 지향한다. Factory 측 발표에 따르면 이번 투자까지 누적 조달액은 $400M을 넘는다.

**왜 중요한지:** Coding Agent 시장의 자본이 단순 `더 좋은 자동완성 IDE`보다 **개발 조직 전체 Workflow를 Agent화하는 Platform**에 몰리고 있다. Repository Context, Test, Review, Ticket, CI/CD, 권한, 비용 추적을 하나로 묶으면 Agent는 개발자의 보조도구가 아니라 Software Delivery Pipeline의 실행 주체가 된다. 최근 Jira Agent Loop, Durable Runtime, Multi-model Orchestration 흐름과 합치면 경쟁 단위는 모델 한 개보다 **Agent Workforce를 관리하는 운영체계**에 가까워지고 있다.

## 이번 회차의 핵심

이번 다섯 소식은 서로 다른 층에서 같은 변화를 보여준다.

- **Gemini 3.8 Live** → Voice Agent가 말하면서 동시에 추론·Tool 실행
- **Salesforce Koa** → Open-weight 모델에 기업 Workflow 자체를 Post-training
- **Gemini CLI** → Agent Security가 Prompt Guardrail에서 Runtime Isolation으로
- **Axelera Europa** → Agent Inference를 위한 지역·전용 Silicon 공급망 확장
- **Factory** → Coding Agent가 개인 도구에서 조직 전체 Software Factory로

결국 Agent 시대의 경쟁 단위는 다음처럼 확장되고 있다.

**Realtime Interface → Domain Model → Secure Runtime → Inference Silicon → Enterprise Agent Operations**

특히 이번 회차에서 눈에 띄는 것은 `모델이 답을 잘하는가`보다 **모델이 일을 계속하면서, 기업 고유 지식을 이해하고, 안전한 실행환경에서 Tool을 사용하며, 충분히 저렴한 Inference Hardware 위에서 대규모로 운영될 수 있는가**가 더 중요한 평가 기준이 되고 있다는 점이다.
