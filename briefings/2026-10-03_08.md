## 1. Meta Muse Gadgets — ESP32·Raspberry Pi를 Agent 하드웨어로

**관련 이미지·보도:** https://www.engadget.com/2276312/meta-muse-gadgets-open-source-smart-home-link/

### 핵심 요약
Meta가 10월 2일 Muse Gadgets를 공개했다. 오픈소스 ESP32 firmware와 Linux SDK로 Muse Agent를 E Ink display, HDMI dongle, touchscreen, sensor·actuator 등에 연결할 수 있다. Reference device인 Muse Home Link도 공개됐으며 미국의 활성 Muse 구독자 대상으로 5,000대가 제공될 예정이다. Muse 모델 자체가 오픈소스화된 것은 아니며 공개 범위의 핵심은 device firmware와 SDK다.

### 왜 중요한지
Agent 경쟁이 app과 browser를 넘어 physical interface와 community-built device 생태계로 확장되고 있다. ESP32와 Raspberry Pi 같은 보편적 maker platform을 쓰기 때문에 새로운 Agent hardware 실험의 진입장벽도 크게 낮아진다.

## 2. NVIDIA DGX Spark 64GB — Local Agent Compute를 더 낮은 진입점으로

**관련 이미지·공식 발표:** https://blogs.nvidia.com/blog/local-ai-dgx-spark-64gb-sync/

### 핵심 요약
NVIDIA가 10월 2일 DGX Spark의 64GB unified memory 구성을 발표했다. 10월 23일부터 Acer, ASUS, Dell, Gigabyte, HP, MSI를 통해 공급되며 GB10 Grace Blackwell, DGX OS와 NVIDIA AI stack을 유지한다. NVIDIA는 단일 시스템에서 최대 100B parameter 모델을 지원하며, 두 대를 NVIDIA Sync로 연결하면 128GB memory pool과 최대 200B 모델까지 확장할 수 있다고 밝혔다.

### 왜 중요한지
Local AI가 작은 모델 실험을 넘어 항상 켜져 있는 Agent를 자체 hardware에서 운영하고 필요하면 scale-out하는 형태로 발전하고 있다. Cloud API 비용과 data governance를 줄이면서도 강한 open model을 운영할 수 있는 선택지가 넓어진다.

## 3. Apple, macOS Full Disk Access 강화 — Agent 권한이 OS 보안 모델을 바꾸기 시작

**관련 보도:** https://techcrunch.com/2026/10/02/apple-says-its-tightening-macos-full-disk-access-controls-due-to-new-risks-from-ai-agents/

### 핵심 요약
Apple은 10월 2일 AI Agent 확산으로 Full Disk Access의 위험이 커졌다며 추가 통제를 도입하겠다고 밝혔다. 향후 이 강한 권한을 부여하려면 더 명시적인 사용자 행동을 요구할 계획이다. 구체적인 새 UI와 배포 시점은 아직 상세히 공개되지 않았다.

### 왜 중요한지
기존 Desktop OS의 권한 체계는 주로 App을 신뢰할지 묻는 구조다. 장시간 자율적으로 움직이는 Agent가 늘어나면서 앞으로는 task별 capability, 일시적 권한, 명시적 승인, audit 중심으로 permission 모델이 더 세분화될 가능성이 커졌다.

## 4. GitHub Copilot Code Review API — AI Review가 CI/CD 구성요소로

**관련 이미지·공식 발표:** https://github.blog/changelog/2026-10-02-copilot-code-review-api-support-and-new-default-effort-level/

### 핵심 요약
GitHub가 10월 2일 Copilot Code Review를 REST와 GraphQL API에서 직접 요청할 수 있게 했다. 요청별 review effort도 지정할 수 있고 Balanced가 기본값이 됐다. 이를 통해 내부 bot, script, CI workflow에서 조건에 맞춰 AI review를 자동 호출할 수 있다.

### 왜 중요한지
AI Code Review가 수동 assistant 기능에서 programmable software-delivery primitive로 이동한다. 조직은 변경 위험도에 따라 review 강도를 달리하고 Agent가 작성한 코드를 다른 AI가 검토한 뒤 사람이 승인하는 pipeline을 만들 수 있다.

**출처**
- GitHub Changelog, 2026-10-02: https://github.blog/changelog/2026-10-02-copilot-code-review-api-support-and-new-default-effort-level/

## 5. AWS Well-Architected Agent — Cloud Architecture Review에서 수정안 생성까지

**관련 이미지·공식 발표:** https://aws.amazon.com/blogs/aws/announcing-aws-well-architected-agent-an-ai-powered-intelligence-to-optimize-your-cloud-environment-preview/

### 핵심 요약
AWS Well-Architected Agent가 public preview로 공개됐다. 65개 이상의 AWS service에서 resource configuration, utilization metric, application topology와 business goal을 함께 분석해 cost, security, performance, resilience 개선안을 우선순위화한다. Terraform, CloudFormation, CDK를 분석해 수정 IaC, CLI command, console 절차 같은 remediation 방법도 제시한다.

### 왜 중요한지
Cloud 운영 AI가 단순 알림에서 architecture context를 이해하고 실제 변경안을 만드는 Agent로 진화하고 있다. IaC가 사람뿐 아니라 Agent도 읽고 수정하는 표준 실행 interface가 될 가능성이 더 커졌다.
