## 1. Shopify WebMCP Checkout — 브라우저 Agent가 상품 탐색부터 결제 제출까지

**핵심 요약:** Shopify가 9월 28일 WebMCP 지원을 Checkout까지 확대했다. 브라우저 기반 AI Agent는 구매자의 활성 Checkout Session 안에서 상태를 읽고, 지원되는 주문 정보를 수정하고, 구매자 확인 후 주문을 제출할 수 있다. 사람이 직접 입력해야 하는 인증이나 차단형 UI가 필요한 순간에는 제어권을 구매자에게 돌려준다. Storefront와 Cart Tool이 이미 제공되고 있어 Product Discovery부터 Cart, Checkout, Order Confirmation까지 Agent가 연속적으로 지원할 수 있다. 별도 신규 API나 Merchant 설정 없이 Checkout UI와 같은 상태를 사용한다.

**왜 중요한가:** Agent Commerce의 마지막 병목이던 결제 단계가 표준 Tool Interface로 열렸다. 완전 무인 결제가 아니라 Buyer Confirmation과 인증 같은 Human Gate를 남겨 둔 점도 중요하다. 쇼핑 사이트의 핵심 Client가 사람의 Browser뿐 아니라 Agent로 확장되면 Commerce UI, SEO, 광고, 결제 Authorization까지 다시 설계될 수 있다.

## 2. AutoTrust JEV-27B — System 1 판단과 System 2 추론을 한 모델에 통합

**핵심 요약:** AutoTrust가 Apache 2.0 오픈웨이트 JEV-27B를 공개했다. Qwen3.8-27B의 본체와 기존 LM Head는 그대로 두어 System 2의 일반 생성과 단계적 추론을 유지하고, 108.9M Parameter 규모의 System 1 Adapter와 Decision Head를 추가한다. 한 vLLM Engine 안에서 요청마다 일반 생성과 빠른 판단 경로를 선택할 수 있다. System 1은 Yes/No, 2～16개 선택지, 0～5 Score를 한 번의 Forward Pass로 처리하고 확률분포를 반환한다.

AutoTrust 자체 측정에서는 System 2의 HumanEval이 추가 전후 모두 78.0%로 유지됐고 System 1 단일 판단은 B200에서 Median 137ms였다. 추가 학습은 약 9.2 B200-hours였다고 밝혔다. TypeSafe Jev 1.13의 공개 Output Distribution을 학습한 독립 Student Model이며 TypeSafe와는 별도 프로젝트다. 성능과 지연 수치는 자체 평가이므로 독립 Benchmark와 구분해서 봐야 한다.

**왜 중요한가:** 최근 Decision Model이 별도 작은 모델로 분리되는 흐름과 달리, JEV-27B는 하나의 Frozen Backbone 안에 빠른 판단 Block과 깊은 추론 Block을 함께 두는 해법을 제시한다. Agent가 Tool Routing·승인·분류에는 System 1을 쓰고 복잡한 계획이나 Coding에는 System 2를 쓰면 두 모델을 따로 배포하고 Context를 넘기는 운영 복잡성을 줄일 수 있다.

## 3. GitHub Security Lab AI Agent, 실제 Android 앱에서 취약점 24개 발견

**핵심 요약:** GitHub Security Lab이 오픈소스 Taskflow Agent에 Android 전용 Audit Workflow를 적용해 실제 모바일 앱에서 24개의 취약점을 찾아 보고했다고 9월 28일 공개했다. Mobile Entry Point와 Android 특화 취약점 유형을 단계적으로 점검하도록 보안 연구자의 절차를 Taskflow로 구조화했다. GitHub는 일부 고위험 취약점도 포함됐다고 밝혔지만, LLM이 실제 Severity를 잘못 판단하거나 False Positive를 만들 수 있으므로 전문 보안 연구자의 검증이 필요하다고 명시했다.

**왜 중요한가:** 앞서 공개된 Fuzzing Taskflow가 보안 연구의 반복 Loop를 Agent에게 맡길 수 있다는 가능성을 보여줬다면, 이번 결과는 동일 계열 Framework가 실제 Android 앱에서 다수의 취약점을 찾아낸 실전 성과다. 핵심은 모델 하나의 취약점 탐지 능력보다 보안 전문가의 탐색 절차를 재사용 가능한 Agent Workflow로 패키징할 수 있다는 점이다. Security Knowledge 자체가 실행 가능한 Workflow로 배포되기 시작하고 있다.

## 4. mvschwarz/openrig — Claude Code와 Codex를 한 팀으로 운영하는 Multi-Agent Harness

**핵심 요약:** Apache 2.0 오픈소스 OpenRig가 9월 29일 GitHub Trend 추적에서 상위권으로 급상승하고 있다. Claude Code와 Codex Session을 YAML RigSpec으로 하나의 Team Topology로 정의하고 한 번에 실행할 수 있다. 각 Agent를 Stable Seat와 Pod로 관리하며 메시지 전송, Broadcast, Chatroom, Queue, Snapshot·Restore, 재부팅 후 복구를 지원한다. Local Daemon + CLI + TUI + MCP Server 구조이고 실제 Agent Session은 tmux에서 동작한다.

**왜 중요한가:** Coding Agent가 여러 개로 늘어나면 누가 어떤 Task를 맡았는지, 어떤 Agent가 검토했는지, 재시작 후 어디서 이어갈지가 새로운 운영 문제가 된다. OpenRig는 이 계층을 선언적 Team Topology로 다룬다. 최근 Paperclip이 조직·예산·Ticket 관점의 Control Plane을 보여줬다면 OpenRig는 실제 Coding Session Topology와 복구에 더 집중한다.

## 5. Anthropic IPO Prospectus — 기업가치 $2T 가능성 뒤에 $518B 인프라 의무

**핵심 요약:** Reuters가 확인한 Anthropic IPO Prospectus에 따르면 상장 시 기업가치가 $2T를 넘을 가능성이 거론된다. Anthropic의 2025년 Revenue는 약 $4.6B로 12배 성장했지만 Operating Loss는 $8.06B, Net Loss는 약 $42B였다. Net Loss에는 Financing 가치 재평가에 따른 약 $34B의 비현금성 Accounting Charge가 포함됐다. 2025년 Compute·Infrastructure 지출은 $7.33B였고, 향후 Cloud·Compute·Infrastructure 관련 의무는 총 $518B에 달한다.

**왜 중요한가:** Frontier AI 기업이 단순 Software Company가 아니라 Data Center·GPU·전력·Cloud 계약을 장기간 떠안는 초대형 자본집약 사업으로 바뀌고 있음을 보여준다. Anthropic IPO는 향후 OpenAI를 포함한 순수 AI 기업을 Wall Street가 어떻게 평가할지 기준점이 될 가능성이 높다. Revenue 성장률만큼 Compute Commitment와 Cost per Task가 기업가치의 핵심 변수가 되고 있다.
