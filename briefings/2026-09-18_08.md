## 1. Anthropic, Claude가 내부 AI R&D의 26%를 사실상 주도한다고 공개

**관련 이미지:** [Anthropic R&D Automation Index 공식 차트](https://www.anthropic.com/institute/measuring-pace-of-ai-development)

### 핵심 요약

Anthropic은 9월 17일 Frontier AI Lab 내부의 AI 개발 속도를 추적하기 위한 `Anthropic R&D Automation Index`를 처음 공개했다. Epoch AI의 AL0～AL5 자동화 척도를 기준으로, 2026년 8월 현재 Claude가 Anthropic AI R&D 업무의 **26%에서 AL4, 즉 사람이 높은 수준의 지시만 주고 Claude가 대부분의 작업을 End-to-end로 수행하는 수준**에 도달했다고 밝혔다. 2월에는 이 비율이 1% 미만이었다. AL3 이상의 `AI collaborates` 단계까지 포함하면 AI가 실질적으로 참여하는 업무 비중은 90%를 넘는다.

아직 AL5, 즉 사람이 개입하지 않는 완전 자율 AI R&D에 도달한 영역은 없다. 하지만 Anthropic의 가장 많이 쓰이는 내부 플랫폼에서는 8월 기준 약 **3만 개의 Agent가 동시에 연구·엔지니어링 업무**를 수행하고 있었다. 한 달 동안 10억 건 이상의 Agent Action을 분석했으며 Online Monitor가 약 0.002%, 대략 4만7천 건당 1건을 차단했다고 공개했다. 또한 7월의 한 주간 AI R&D Compute 가운데 약 6%, AI가 수행한 AI R&D Compute 가운데 약 12%가 Safety 관련 작업에 쓰였다고 밝혔다.

### 왜 중요한지

`AI가 AI를 얼마나 빨리 개선하고 있는가`가 추상적인 미래 논쟁에서 **측정 가능한 운영 지표**로 바뀌기 시작했다. 특히 26%라는 숫자보다 중요한 것은 2월 1% 미만에서 8월 26%까지 올라온 변화 속도다.

앞으로 Frontier Lab의 경쟁력을 평가할 때 Model Benchmark뿐 아니라 **AI R&D 자동화율, Agent Oversight Coverage, Safety Compute 비중** 같은 지표가 함께 논의될 가능성이 있다. Anthropic은 이 측정치를 제3자가 검증할 수 있는 형태로 발전시키고 다른 Lab도 유사 지표를 공개할 것을 제안했다.

## 2. GitHub, Copilot Agent Runtime을 80만+ 줄 Rust로 재작성 — 대부분의 Porting Code를 Agent가 작성

**관련 이미지:** [GitHub Copilot Runtime Rust Migration](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)

### 핵심 요약

GitHub가 Copilot CLI, Copilot App, Copilot SDK의 기반이 되는 Agent Runtime을 기존 TypeScript·Node.js에서 **80만 줄이 넘는 Production Rust**로 완전히 재작성했다고 공개했다. 실제로 Porting 대상이 된 기존 TypeScript Production Code는 약 43만 줄이었고, 변화는 128개의 PR로 나눠 `main`에 점진적으로 반영됐다.

가장 주목할 점은 **AI Agent가 코드의 대부분을 작성했다는 것**이다. GitHub의 Stephen Toub가 프로젝트를 중심적으로 이끌었으며, 과거 방식이라면 팀 전체가 1～2년 투입해야 해 경제성이 없었을 프로젝트를 수개월 동안 진행했다고 설명했다. 긴 Agent Session에서는 Context Compaction이 총 5,116회 발생했고, 일부 Session은 수일간 지속됐다.

성능 개선도 컸다. GitHub의 자체 측정에서 Client 생성부터 한 번의 Turn과 종료까지의 Lifecycle은 5.25초에서 In-process Rust 기준 약 55ms 수준으로 줄었고, 1,000개의 짧은 Session을 처리하는 Throughput은 초당 7.55개에서 120개로 늘었다. 10개 Client를 처리할 때 측정된 추가 Memory도 1,383MB에서 126MB로 감소했다. GitHub는 이 수치가 언어 변경만을 분리 측정한 결과는 아니며 같은 기간의 다른 최적화도 포함된다고 명시했다.

### 왜 중요한지

Agent Coding의 가장 큰 효과가 `사람이 쓰던 코드 몇 줄을 대신 작성한다`에서 **예전에는 비용 때문에 승인되지 않았을 대규모 구조 변경을 현실적인 프로젝트로 만든다**는 단계로 이동하고 있다.

Legacy Migration, 언어 전환, 대규모 Refactoring처럼 ROI가 애매해 계속 미뤄졌던 작업이 Agent로 인해 경제적으로 가능해질 수 있다. 소프트웨어 개발 생산성의 단위가 `개발자 한 명이 하루에 몇 줄 더 쓰는가`보다 **어떤 종류의 프로젝트를 새롭게 시도할 수 있게 되는가**로 바뀐다는 점에서 중요한 사례다.

**출처:** [GitHub Blog, 2026-09-16](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)

## 3. Claude Code `Projects` 재설계 — 하나의 Coordinator가 여러 Coding Agent를 병렬 지휘

**관련 이미지:** [Claude Code Projects 관련 보도](https://www.theverge.com/ai-artificial-intelligence/997134/anthropic-claude-code-projects)

### 핵심 요약

Anthropic이 Claude Code의 `Projects`를 Multi-Agent 구조로 다시 출시했다. 하나의 Project 안에서 여러 `Thread`가 서로 다른 작업을 병렬로 수행하고, 중앙 `Coordinator`가 Shared Goal, Memory, File·Artifact Library를 바탕으로 일을 분배하고 전체 진행상황을 관리한다.

각 Thread는 실제로 **자신만의 Branch와 Repository Copy를 가진 독립 Claude Code Cloud Session**이다. 여러 Thread가 같은 코드를 수정하면 일반적인 PR과 마찬가지로 Merge Conflict로 처리한다. 각 Thread는 필요할 경우 다시 Subagent, Loop, Workflow를 만들어 일을 더 잘게 나눌 수 있다. 사용자는 개별 Thread에 직접 들어가 개입하거나 Main Project Chat에서 전체를 관리할 수 있다.

현재 Thread는 Cloud에서 실행되며 Local Tool과 Local Code 지원은 추가될 예정이다. 우선 일부 Pro·Max 사용자에게 Beta로 제공되고 이후 Pro, Max, Team, Enterprise 등으로 확대될 예정이다.

### 왜 중요한지

Coding Agent UX가 **`한 Prompt → 한 Agent Session`에서 `한 Project → 여러 Agent → Coordinator`**로 이동하고 있다. 복잡한 개발작업은 한 Agent가 Context Window 하나 안에서 모든 것을 처리하는 것보다 Frontend, Backend, Test, Migration 같은 하위 작업을 독립 Context로 분리하는 것이 자연스럽다.

이 구조가 보편화되면 Coding Agent의 핵심 경쟁력도 단일 Model 성능에서 **Shared Memory, Task Decomposition, Branch Isolation, Merge Strategy, Human Oversight** 같은 Orchestration Layer로 이동할 가능성이 크다.

## 4. UN `System Data Commons` 출시 — 4,400만 데이터포인트를 MCP로 Agent에 직접 연결

**관련 이미지:** [UN System Data Commons](https://data.un.org/)

### 핵심 요약

UN과 Google이 9월 17일 `UN System Data Commons`를 공식 출시했다. Google의 오픈소스 Data Commons를 기반으로 UN 기관에 분산된 통계를 하나의 AI-ready Knowledge Graph로 통합하며, 현재 **26개 UN 기관이 참여하고 약 4,400만 개 데이터포인트**가 제공된다.

일반 사용자는 자연어로 통계를 검색하고 원본 UN 출처까지 추적할 수 있다. 더 중요한 것은 **MCP를 지원해 AI Agent가 권위 있는 UN 데이터를 직접 Query**할 수 있다는 점이다. Google은 Agent가 여러 지표를 연결해 Chart, Dashboard, Infographic, Draft Report를 만드는 Workflow도 시연했다.

이 프로젝트의 배경에는 LLM의 통계 검색 정확성 문제가 있다. UNICEF가 6개 주요 LLM을 대상으로 13만3천 건 이상의 글로벌 개발지표 질문을 시험한 결과 평균 정확도가 21.2%에 불과했고, 약 5개 중 3개의 응답은 사용할 수 있는 숫자를 제공하지 못했다고 TechCrunch가 보도했다. UN은 2027년까지 UN 시스템 통계 Dataset의 80%를 이 플랫폼에 포함하는 것을 목표로 한다.

### 왜 중요한지

RAG와 Agent 시대의 핵심 병목 가운데 하나는 `모델이 똑똑한가`가 아니라 **신뢰할 수 있는 원천 데이터가 Machine-readable·Agent-readable 형태로 존재하는가**다.

공공기관이 공식 데이터를 웹페이지에 게시하는 데서 그치지 않고 **Natural Language + Provenance + MCP**를 제공하면 Agent가 검색결과를 Scraping하는 대신 원천 데이터에 직접 연결될 수 있다. 정부, 통계기관, 금융정보 제공업체가 향후 데이터를 공개하는 방식의 하나의 Reference Architecture가 될 가능성이 있다.

## 5. 🔥 Anthropic, 30개+ 생명과학 오픈소스 모델을 Claude로 최적화하고 코드 전면 공개

**관련 이미지:** [Claude Biomolecular Modeling 공식 연구](https://www.anthropic.com/research/claude-uplifts-biomolecular-modeling)

### 핵심 요약

Anthropic이 Claude를 이용해 Protein Structure Prediction, Protein Design, Genomics, Protein Language Model 등 **30개가 넘는 오픈소스 생명과학 모델을 4주 미만에 최적화**한 결과와 코드를 공개했다. 평균 약 4배의 속도 향상을 얻었고, 출력이 완전히 동일한 `exact` 최적화만 비교해도 약 2배 수준의 개선을 보고했다.

Claude는 Pairformer 계열에서 큰 비용을 차지하는 Triangle Attention과 Triangle Multiplication을 위한 `FlashPairformer` GPU Kernel도 개발했다. Anthropic 측 결과에서는 기존 Field Standard 대비 Triangle Attention은 약 2.7～2.9배, Triangle Multiplication은 약 1.7～3.2배 빨랐다. 또한 `Big` Low-memory Mode를 만들어 단일 NVIDIA GPU Node에서 1만 Token이 넘는 대형 Biomolecular System을 정확하게 모델링할 수 있게 했다.

공개 저장소 `anthropics/uplifting-biomolecular-modeling`에는 36개의 Drop-in Optimization Kit가 포함돼 있으며 Apache 2.0 코드로 공개됐다. 구조예측, Cofolding, Binder·Sequence Design, Protein·Genomic Language Model 등 다양한 기존 도구를 대상으로 `exact`, `fast`, `big` Mode를 제공한다.

### 왜 중요한지

이 사례는 Coding Agent가 일반 Application Code를 작성하는 수준을 넘어 **GPU Kernel Engineering과 Scientific Computing Optimization** 같은 고도의 전문 엔지니어링 업무까지 확장되고 있음을 보여준다.

특히 중요한 점은 새로운 거대 Biology Model을 만든 것이 아니라 기존 오픈소스 생태계 전체의 실행비용을 낮췄다는 것이다. AI의 과학적 영향이 `논문을 읽고 아이디어를 제안하는 모델`에서 **실제로 과학 Software Stack을 개선해 더 큰 실험을 싸게 가능하게 하는 Engineering Agent**로 이동하고 있다.

## 이번 회차의 핵심

이번 회차에서 가장 강한 흐름은 `AI가 사람의 일을 돕는다`를 넘어 **AI가 다음 AI와 Software·Scientific Infrastructure 자체를 만드는 과정에 들어가고 있다**는 점이다.

Anthropic의 26% AI R&D 자동화율은 Frontier Model 개발 자체가 Agent Workflow로 바뀌는 속도를 보여준다. GitHub의 Rust Migration은 Agent가 대규모 Legacy Modernization의 경제성을 바꾸고 있음을 보여주며, Claude Code Projects는 개발 조직 자체가 Multi-Agent 구조로 바뀌는 UX를 제시한다. UN Data Commons는 Agent가 사용할 수 있는 신뢰 가능한 데이터 계층을, Anthropic의 Biomolecular Optimization은 Agent가 전문 과학 Software까지 직접 개선할 수 있음을 보여준다.

> **AI R&D → Multi-Agent Project → Massive Code Migration → Trusted MCP Data → Scientific Engineering**

앞으로의 경쟁력은 단순히 더 좋은 모델을 사용하는 데서 끝나지 않고, **AI에게 어떤 장기 작업을 맡길 수 있는지, 여러 Agent를 어떻게 조직하는지, 어떤 신뢰 가능한 데이터와 실행환경을 연결하는지**에 더 크게 좌우될 가능성이 있다.
