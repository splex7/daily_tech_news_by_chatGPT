## 1. Alibaba `Qwen3.8-Omni-Flash` — 텍스트·이미지·오디오·비디오를 1M Context 하나로 처리

[관련 이미지 · Qwen3.8 계열](https://qwen.ai/blog?id=qwen3.8-omni-flash)

### 핵심 요약

Alibaba Qwen이 9월 18일 `Qwen3.8-Omni-Flash`를 출시했습니다. 하나의 요청에서 **텍스트·이미지·오디오·비디오를 함께 입력**받고 텍스트를 출력하는 Native Omnimodal Model이며, **1M Token Context Window**, Thinking Mode, Function Calling, Web Search를 지원합니다. Alibaba Cloud 문서 기준 오디오 입력은 113개 언어·방언을 지원합니다.

Qwen 측은 이전 Qwen3.5-Omni-Plus 대비 29개 평가 평균이 25% 이상 높아졌다고 밝혔고, API 비용도 크게 낮췄습니다. QwenCloud 기준 텍스트 입력은 100만 Token당 $0.15, 출력은 $0.47이며 Cache Hit는 $0.016입니다. 오디오 입력 비용은 이전 모델 대비 시간당 98% 이상 감소했다고 발표했습니다. 성능·비용 비교 수치는 출시사 측 측정이라는 점은 감안해야 합니다.

### 왜 중요한지

멀티모달 Agent의 기존 구조는 흔히 **음성 인식 → Vision Model → LLM → Tool**처럼 여러 모델을 이어 붙였습니다. Qwen3.8-Omni-Flash는 긴 Audio·Video Context를 하나의 Reasoning Loop에서 이해하고 바로 Tool을 호출하는 방향입니다.

특히 1M Context와 낮은 Multimedia Input Cost의 결합은 **회의 녹화 분석, 긴 영상 조사, Call Center QA, Video Agent, 멀티모달 RAG**의 경제성을 크게 바꿀 수 있습니다. Frontier 경쟁의 한 축이 단순 Text Intelligence에서 **얼마나 많은 현실 데이터를 싸게 읽고 행동으로 연결하느냐**로 이동하고 있습니다.

- Qwen 공식 발표: https://qwen.ai/blog?id=qwen3.8-omni-flash
- Alibaba Cloud 공식 문서: https://www.alibabacloud.com/help/en/model-studio/qwen-omni

## 2. 🔥 PrismML `Ternary Bonsai 2 27B` — 27B 모델을 5.9GB로 압축, 로컬 Agent용 `Intelligence Density` 경쟁

![Bonsai 2 27B 공식 Benchmark](https://cdn.prod.website-files.com/699604cc2b9dd89bdbda0608/6aac504ec0cef3807f35bcba_2%2027B%20ID.png)

### 핵심 요약

PrismML이 9월 17일 Apache 2.0 오픈웨이트 `Ternary Bonsai 2 27B`를 공개했습니다. Qwen3.8 27B를 기반으로 Weight를 **−1·0·+1의 Ternary 값**으로 표현하고 FP16 Group-wise Scaling을 적용해 전체 Language Model Footprint를 **5.9GB**, 약 1.76 Effective Bits per Weight까지 줄였습니다. Context Window는 262K이며 Text와 Image 입력을 지원합니다.

PrismML 자체 20개 Benchmark 집계에서는 Full-precision Qwen3.8 27B의 85.4점 대비 83.9점으로 **98.2%의 Aggregate Performance를 유지**했다고 보고했습니다. RTX 5090에서 최대 143 tokens/s, M5 Max에서 46.8 tokens/s를 제시했지만 이 역시 출시사 Benchmark입니다. 현재 CUDA와 Apple MLX용 Custom Low-bit Kernel을 사용하며 GGUF도 배포됩니다.

### 왜 중요한지

지금까지 Local AI는 보통 `작은 모델을 선택하고 성능을 포기하는 것`과 동의어에 가까웠습니다. Bonsai 계열이 흥미로운 이유는 Parameter 수를 크게 줄이는 대신 **같은 27B Architecture를 극단적으로 낮은 Bit Width로 밀어 넣는 전략**이 빠르게 개선되고 있기 때문입니다.

이 방식이 안정적으로 확장되면 Agent Architecture는

**민감하거나 반복적인 작업은 Local 27B → 어려운 단계만 Cloud Frontier Model로 Escalation**

하는 Hybrid 구조가 훨씬 현실적이 됩니다. 앞으로 모델 경쟁에서 Parameter 수만큼 **GB당 Intelligence, Watt당 Token, Local Throughput**이 중요해질 가능성이 큽니다.

- PrismML 공식 발표: https://prismml.com/news/bonsai-2-27b
- Hugging Face GGUF: https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf

## 3. 🔥 Tencent `BrowserSkill 0.3.0` — Agent가 내가 로그인한 실제 Chrome·Edge를 권한 통제 아래 사용

![Tencent BrowserSkill](https://opengraph.githubassets.com/1/Tencent/BrowserSkill)

### 핵심 요약

Tencent의 MIT 오픈소스 `BrowserSkill`은 확인 시점 **5,585 Stars, 387 Forks**를 기록하고 있습니다. Cursor, Claude Code, Codex, OpenClaw, Hermes Agent, DeepSeek Harness 등 Shell을 호출할 수 있는 Agent가 사용자의 **실제 로그인 상태가 유지된 Chrome·Edge**를 사용할 수 있게 하는 CLI + Browser Extension 구조입니다.

9월 16일 `0.3.0`에서는 Remote Browser Connection, 일회용 Pairing Link, Device Credential 갱신·폐기, Operation Audit, Full-page Screenshot, Canvas Visual Reference, Scroll-to Element 등이 추가됐습니다. 특히 기존 Tab을 쓰려면 Agent가 명시적으로 `borrow`해야 하며, Borrow Confirmation과 Human Help 허용 여부는 Browser Extension에 저장된 사용자 설정이 최종 권한을 가집니다. CLI의 `--unattended` Flag로 이를 우회하지 못하도록 바뀌었습니다.

### 왜 중요한지

Browser Agent의 가장 어려운 문제는 클릭 정확도보다 **로그인 상태·Credential·Human Approval·Audit**입니다. Cloud Browser를 새로 띄우면 사용자가 다시 로그인해야 하고, 반대로 Agent에게 기존 Browser 전체를 넘기면 권한이 너무 큽니다.

BrowserSkill은 이를

**Agent → Local CLI·Daemon → 격리된 Agent Window → 필요할 때만 기존 Tab Borrow → Human Approval**

로 나눕니다. Browser Automation이 단순 RPA에서 **권한 경계를 가진 Personal Agent Runtime**으로 발전하는 방향을 잘 보여주는 프로젝트입니다.

- GitHub: https://github.com/Tencent/BrowserSkill
- Changelog: https://github.com/Tencent/BrowserSkill/blob/main/CHANGELOG.md

## 4. AWS `AgentCore Runtime V2` GA — Agent Container를 Snapshot으로 복원해 Cold Start를 약 2초로

[관련 이미지 · Amazon Bedrock AgentCore Runtime](https://aws.amazon.com/blogs/machine-learning/move-your-ai-agents-from-proof-of-concept-to-production-with-amazon-bedrock-agentcore/)

### 핵심 요약

AWS가 9월 18일 Amazon Bedrock AgentCore의 차세대 Runtime을 정식 공개했습니다. AgentCore Runtime은 Agent를 Serverless MicroVM에서 실행하는 계층이며, 새 버전은 **Elastic Memory Reclaim**과 **Snapshot 기반 Cold Start**를 도입했습니다.

AWS 자체 테스트에서 200MB～2GB Container Image의 P75 Cold Start는 기존 **5.4～30초**에서 **1.9～2.0초**로 줄었습니다. 새 Runtime은 Agent Environment를 한 번 준비한 뒤 Snapshot으로 저장하고 새 Instance가 이를 Restore합니다. Session은 작은 Memory Profile로 시작하고 필요할 때 Memory를 늘린 뒤 사용하지 않는 Memory를 반환합니다. Scale-to-zero와 Hardware-enforced Session Isolation은 유지됩니다.

### 왜 중요한지

Agent는 일반 REST API보다 실행환경이 훨씬 무겁습니다. Python Runtime, Browser, MCP Client, Tool Library, Code Sandbox까지 Container에 들어가면 수백 MB～수 GB가 쉽게 됩니다. 그런데 Agent가 사용자 요청 때마다 10초 이상 기동한다면 Interactive Product로 쓰기 어렵습니다.

AWS가 Runtime 자체에 Snapshot Restore와 Memory Reclaim을 넣었다는 것은 **Agent 실행환경이 Lambda나 일반 Container와 구별되는 독립 Cloud Compute Category**가 되고 있다는 신호입니다. 앞으로 Agent Infra의 핵심 지표는 Token 가격뿐 아니라 **Session Start Latency + Memory Residency + Isolation + Durable State + Tool Startup Cost**가 될 가능성이 큽니다.

- AWS 공식 발표: https://aws.amazon.com/about-aws/whats-new/2026/09/new-agentcore-runtime-generally-available/

## 5. Anthropic × Accenture, 최소 `$2B` 투입 — Frontier Model `독립 평가`가 별도 산업으로

[관련 이미지 · Anthropic × Accenture](https://newsroom.accenture.com/news/2026/accenture-and-anthropic-partner-to-build-team-of-embedded-evaluators-at-anthropic)

### 핵심 요약

Anthropic과 Accenture가 9월 18일 Frontier AI Model의 독립 평가 역량 구축을 위해 **향후 5년간 각각 최소 $1B, 합계 최소 $2B**를 투자한다고 발표했습니다. Accenture가 인수한 AI 전문조직 Faculty가 Anthropic 내부에 들어가 Model Evaluation, Red Teaming, Alignment Assessment, Safeguard Test를 수행합니다.

핵심 개념은 `Embedded Evaluation`입니다. 기존처럼 외부 Evaluator가 공개 API만 시험하는 것이 아니라 **AI 회사 내부에서 직원과 비슷한 수준의 접근권한**을 갖고 Training과 Deployment 과정, Safety Control과 Blind Spot을 평가하는 방식입니다. Anthropic도 세부 운영기준은 아직 만들어가는 단계라고 명시했습니다.

### 왜 중요한지

Frontier Model이 복잡해질수록 개발사가 자기 모델을 자기 Benchmark만으로 검증하는 구조에는 한계가 있습니다. 최근 Agent가 Sandbox 밖의 시스템에 접근하거나 허가되지 않은 행동을 한 사례가 이어지면서, Model Evaluation도 단발성 Benchmark에서 **지속적인 Red Team·Incident Review·Deployment Audit**으로 확대되고 있습니다.

합계 최소 $2B라는 규모는 `AI Safety`가 연구조직의 부수기능을 넘어 **독립된 전문 서비스와 감사시장**으로 성장할 수 있음을 보여줍니다. 향후 Enterprise AI 조달에서도 `어떤 모델인가`뿐 아니라 **누가 독립적으로 평가했고 어떤 접근권한으로 검증했는가**가 중요한 조건이 될 가능성이 큽니다.

## 이번 회차의 핵심

이번 다섯 소식은 AI Stack이 **더 많이 보고 → 더 작게 실행하고 → 현실의 Browser를 사용하고 → 전용 Runtime에서 돌고 → 외부 Evaluator에게 검증받는 구조**로 발전하고 있음을 보여줍니다.

- **Qwen3.8-Omni-Flash** → Text 중심 LLM에서 1M Context Omnimodal Agent로
- **Bonsai 2 27B** → Cloud-only Intelligence에서 고밀도 Local Intelligence로
- **BrowserSkill** → Browser Automation에서 Permission-aware Browser Agent로
- **AgentCore Runtime V2** → 일반 Container에서 Agent 전용 Compute Primitive로
- **Anthropic × Accenture** → 자체 Safety Test에서 Embedded Independent Evaluation으로

> **AI 경쟁의 단위가 모델 하나에서 `Multimodal Intelligence + Local Efficiency + Real-world Permission + Runtime + Independent Evaluation` 전체 Stack으로 넓어지고 있습니다.**
