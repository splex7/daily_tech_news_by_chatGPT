## 1. Claude Code `2.1.277` — `AGENTS.md` 지원으로 코딩 에이전트 프로젝트 지침이 한 파일로 수렴

![Claude Code](https://opengraph.githubassets.com/1/anthropics/claude-code)

### 핵심 요약

Anthropic은 9월 18일 Claude Code `2.1.277`을 공개하면서 프로젝트에 `CLAUDE.md`가 없을 경우 `AGENTS.md`를 프로젝트 지침 파일로 읽도록 변경했습니다. 사용자는 `/config`의 Project instructions에서 이를 바꿀 수 있으며, 현재 Bedrock·Vertex·Foundry 경로에서는 아직 지원되지 않습니다.

같은 릴리스에는 Claude Apps Gateway의 Egress Boundary 옵션, Headless·Agent SDK 세션 오류 처리 개선, Sandbox 명령 제외 규칙 강화 등 Agent Runtime 안정성과 보안 관련 수정도 포함됐습니다.

### 왜 중요한지

팀이 Codex, Claude Code, Cursor, Gemini CLI 같은 여러 Coding Agent를 섞어 쓰는 상황에서는 각 도구용 지침 파일을 따로 유지하는 것이 빠르게 부채가 됩니다. Claude Code가 `AGENTS.md`를 받아들이면서 Repository 안의 **Agent용 운영지침을 Vendor별 파일이 아니라 공통 프로젝트 자산으로 관리하는 방향**이 더 강해졌습니다.

이 변화는 Markdown 파일 하나가 단순 Prompt가 아니라 **설치법·테스트 명령·코딩 규칙·금지 영역·Workflow를 담는 Agent Interface**가 되고 있음을 보여줍니다.

- 공식 Changelog: https://code.claude.com/docs/en/changelog
- Claude Code GitHub: https://github.com/anthropics/claude-code

## 2. 🔥 Tencent `BrowserSkill 0.3.0` — AI Agent가 내가 로그인한 실제 브라우저를 안전하게 빌려 쓴다

![Tencent BrowserSkill](https://opengraph.githubassets.com/1/Tencent/BrowserSkill)

### 핵심 요약

Tencent의 MIT 오픈소스 `BrowserSkill`은 확인 시점 약 **5.5K Stars, 384 Forks**를 기록하고 있습니다. Cursor, Claude Code, Codex, OpenClaw, Hermes Agent, DeepSeek Harness 등 Shell을 실행할 수 있는 여러 Agent가 사용자의 **실제 Chrome·Edge 로그인 상태**를 재사용하도록 연결합니다.

9월 16일 `0.3.0`에서는 Remote Browser Connection, 일회용 Pairing Link, Device Credential 갱신·폐기, Operation Audit, Full-page Screenshot, Canvas Visual Reference, Scroll-to Element, Host-managed Daemon 등이 추가됐습니다. 특히 `--unattended` 같은 CLI Flag가 Browser Extension에 저장된 Borrow Confirmation·Human Help 설정을 우회하지 못하도록 바뀌었습니다.

### 왜 중요한지

Browser Agent의 실전 병목은 페이지를 클릭하는 능력보다 **로그인 상태·권한·사람 개입·감사기록**입니다. 별도 Cloud Browser를 띄우는 대신 사용자의 기존 Session을 제한적으로 빌리는 구조는 개인·기업 Agent 모두에 현실적인 패턴입니다.

구조는 다음에 가깝습니다.

**Agent → Local CLI·Daemon → 별도 Agent Window → 필요 시 기존 Tab Borrow → Human Approval**

즉 Browser Automation이 단순 RPA에서 **권한을 가진 Agent Runtime**으로 진화하고 있습니다.

- GitHub: https://github.com/Tencent/BrowserSkill
- Changelog: https://github.com/Tencent/BrowserSkill/blob/main/CHANGELOG.md

## 3. AWS `AgentCore Runtime V2` GA — Agent Container를 Snapshot으로 복원해 Cold Start를 약 2초로

### 핵심 요약

AWS가 9월 18일 Amazon Bedrock AgentCore의 차세대 Runtime을 GA로 공개했습니다. AgentCore Runtime은 Agent를 Serverless MicroVM 안에서 실행하는 계층이며, V2는 **Elastic Memory Reclaim**과 **Snapshot 기반 Cold Start**를 도입했습니다.

AWS 자체 테스트에서 200MB～2GB Container Image의 P75 Cold Start는 V1의 **5.4～30초**에서 V2의 **1.9～2.0초**로 줄었습니다. Session은 작은 Memory Profile로 시작하고 필요할 때 Memory를 늘린 뒤 사용하지 않는 Memory를 다시 반환합니다. Hardware-enforced Session Isolation과 Scale-to-zero 구조는 유지됩니다.

### 왜 중요한지

Agent는 일반 API Server보다 실행환경이 무겁습니다. Python Runtime, Browser, Tool, Library, MCP Client까지 포함하면 Container가 커지고, 사용자가 요청할 때마다 수십 초를 기다리는 구조는 제품화하기 어렵습니다.

AWS가 Agent Runtime에 Snapshot Restore와 Memory Reclaim을 넣었다는 것은 **Agent 실행환경이 Lambda·Container와 다른 독립적인 Cloud Compute Category**로 자리 잡고 있다는 신호입니다.

앞으로 Agent Infra의 핵심 지표는 단순 Token 가격만이 아니라 **Session Start Latency + Memory Residency + Isolation + Durable State + Tool Startup Cost**가 될 가능성이 큽니다.

- AWS 공식 발표: https://aws.amazon.com/about-aws/whats-new/2026/09/new-agentcore-runtime-generally-available/

## 4. Moonshot `Kimi K3` Amazon Bedrock GA — 2.8T 오픈웨이트 모델이 1M Context와 Prompt Cache까지

![Kimi K3](https://aireadily.com/assets/images/articles/kimi-k3-1m-context.webp)

### 핵심 요약

AWS가 9월 18일 Moonshot AI의 `Kimi K3`를 Amazon Bedrock에 정식 추가했습니다. AWS와 Moonshot 설명 기준 Kimi K3는 **2.8T Parameter 규모의 Open-weight MoE**, Native Vision, **1M Token Context Window**를 제공하며 Coding·Knowledge Work·장기 Agent Workflow를 겨냥합니다.

특히 Kimi K3는 Bedrock에서 **Explicit Prompt Caching을 지원하는 첫 Open-weight Model**입니다. 반복되는 System Prompt, 대형 Repository Context, 긴 RAG 문서를 재사용하는 Agent에서는 Input Cost와 Latency를 줄일 수 있습니다. Bedrock의 Access Control, Encryption, Audit Boundary 안에서 사용할 수 있고 Cross-Region Inference도 지원합니다.

### 왜 중요한지

Open-weight 모델의 약점 중 하나는 기업이 직접 Serving·Scaling·Security를 책임져야 한다는 점이었습니다. Kimi K3가 Bedrock 같은 Managed Platform에 들어오면 기업은

**Open-weight Model의 선택권 + Managed Cloud의 Governance**

를 동시에 얻습니다.

특히 1M Context와 Prompt Cache의 결합은 긴 Codebase·문서·Agent Memory를 반복해서 읽는 Workflow에서 경제성이 큽니다. 오픈모델 경쟁이 Benchmark를 넘어 **Cloud Distribution과 Inference Economics**로 이동하는 사례입니다.

- AWS 공식 발표: https://aws.amazon.com/about-aws/whats-new/2026/09/moonshot-ai-kimi-k3-on-amazon-bedrock/
- AWS Model Card: https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html

## 5. Anthropic × Accenture, 최소 `$2B` 투입 — Frontier Model `독립 평가`가 하나의 산업으로

### 핵심 요약

Reuters에 따르면 Anthropic과 Accenture는 Frontier AI Model의 독립 평가 역량을 구축하기 위해 향후 5년간 **각각 최소 $1B, 합계 최소 $2B**를 투입하기로 했습니다. Accenture의 전문 AI 사업부 Faculty가 Model Evaluation, Red Teaming, Alignment Assessment, Safeguard Test를 주도합니다.

핵심 개념은 Anthropic이 말하는 `Embedded Evaluation`입니다. 외부 Evaluator가 단순 공개 API만 테스트하는 것이 아니라 AI 회사 내부에서 직원과 비슷한 수준의 접근권한을 갖고 운영방식·Safety Commitment·Blind Spot을 평가하는 방식입니다.

### 왜 중요한지

Frontier Model이 복잡해질수록 개발사가 자기 모델을 자기 Benchmark로만 평가하는 구조는 한계가 있습니다. 특히 최근 Agent가 Sandbox 밖의 실제 시스템에 접근하거나 허가되지 않은 행동을 한 사례가 이어지면서, **독립 평가 자체가 별도 Infrastructure와 전문인력을 필요로 하는 산업**이 되고 있습니다.

AI 산업의 새로운 공급망은 다음처럼 확장되고 있습니다.

**Model Lab → Independent Evaluator → Red Team → Incident Reporting → Enterprise·Regulator**

$2B 규모의 공동 투자는 `AI Safety`가 연구팀의 부수 기능이 아니라 **대규모 상업 서비스와 감사시장**으로 커지고 있음을 보여줍니다.

- Accenture × Anthropic: https://www.accenture.com/gb-en/services/ecosystem-partners/anthropic

## 이번 회차의 핵심

이번 다섯 소식은 Agent 생태계가 **표준 → 실행권한 → Runtime → Model Distribution → 독립검증** 순서로 인프라를 갖춰가고 있음을 보여줍니다.

- **Claude Code** → Project Instruction을 `AGENTS.md`로 공통화
- **BrowserSkill** → 실제 로그인 Browser를 권한 통제 하에 Agent에 연결
- **AgentCore Runtime V2** → Agent 실행환경을 Cloud Compute Primitive로 최적화
- **Kimi K3 on Bedrock** → 초대형 Open-weight Model을 Managed Governance 안으로 이동
- **Anthropic × Accenture** → Model Safety를 독립 평가 산업으로 확장

> **Agent의 경쟁력은 이제 모델 하나보다 `Instruction Standard + Permission + Runtime + Model + Evaluation` 전체 Stack에서 결정되기 시작했습니다.**
