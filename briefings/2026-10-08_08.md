## 1. Anthropic Claude Haiku 5.5 — 소형 에이전트 모델의 비용 구조를 재설정

![Claude 로고 — Haiku 5.5 발표 관련 이미지](https://back.aist-ai.com/storage/assistants/5Q8imOMD4IGQy1DFEu7NkwMBxfpEnfuov0TxEuYZ.png)

**발표일:** 2026-10-07

### 핵심 요약
Anthropic이 Claude 5.5 제품군의 소형 모델 **Haiku 5.5**를 출시했다. API 모델 ID는 `claude-haiku-5-5`. **10만 토큰 이하 프롬프트**에 입력 100만 토큰 **$0.10**, 출력 **$0.50**을 부과한다. 이전 Haiku 4.5의 $1/$5보다 토큰당 90% 저렴하지만, 긴 프롬프트는 $0.50/$2.50으로 인상되며 토크나이저 차이도 있어 **통상 작업당 평균 약 75% 절감**이라는 제공사 설명과 구분해야 한다.

Anthropic 자체 평가에서 컴퓨터 사용 OSWorld 2.1 오프라인 부분집합 점수는 **15.7% → 72.4%**로 상승했고 Terminal-Bench 4.0에서는 39.2%를 기록했다. Sonnet 5.5의 캐시 읽기 가격도 100만 토큰당 $0.20 → $0.10으로 내려가, Anthropic은 대부분의 에이전트 업무 비용이 약 20% 감소한다고 설명했다.

### 왜 중요한지
대규모 Agent는 호출 횟수가 많아 **분류·검색·요약·하위 에이전트 작업은 Haiku급**, 복잡한 결정과 긴 코딩 작업은 **Sonnet·Opus급**으로 분산해야 경제성이 높다. 모델 정확도만 아니라 **성공 작업당 비용과 지연시간**이 핵심 경쟁 지표가 된다.

## 2. 미국 National Compute Grid — 남는 GPU를 공유하는 계산 자원망 출시

![National Compute Grid 관련 Axios 보도 삽화 — 전력·컴퓨트 자원의 연결](https://images.axios.com/0JG2raVFqOZnM7Uh3TT480xDC-Q%3D/0x0%3A8000x4500/1920x1080/2026/01/09/1767983530813.jpeg?w=3840)

**보도일:** 2026-10-07

### 핵심 요약
AI 스타트업·클라우드 사업자·연구자·투자자가 참여하는 **National Compute Grid**가 출범했다. 서로 다른 데이터센터·GPU 자원을 풀로 묶고 **공통 스케줄러**로 작업의 위치, 가격, GPU 종류, 사용률을 고려해 배분하려는 시도다. 출범 측은 현재 약 **760MW 규모의 인프라가 연계됐거나 후보로 파악된 상태**라고 설명했고, **2030년 2GW**를 목표로 제시했다. 760MW를 이미 완전히 가용한 GPU 전력으로 간주해서는 안 된다.

컨소시엄 백서에 따르면 특정 독립형·단일 임차 데이터센터의 평균 순 컴퓨트 활용률이 15% 미만일 수 있다. **전체 데이터센터 평균 활용률이나 검증된 전국 수치가 아니라 컨소시엄 측 평가**다. 초기 접근은 공공 부문 연구자·교육기관·국립연구소 등을 대상으로 제한된다.

### 왜 중요한지
GPU·전력의 신규 확보 외에 **기존 GPU의 유휴시간을 줄여 유효 공급량을 높이는** 제3의 대안이 등장했다. 분산 학습의 네트워크·데이터 이동·보안 병목은 여전하므로, 모든 대규모 훈련에 곧바로 적합한 해결책은 아니다.

## 3. GitHub OpenRig — Claude Code와 Codex를 장기 운영하는 오픈소스 Agent 팀

![OpenRig의 Agent 팀 토폴로지 TUI 스크린샷](https://ai-tldr.dev/tools-media/openrig-1.webp)

**확인일:** 2026-10-08 / **라이선스:** Apache-2.0

### 핵심 요약
오픈소스 **mvschwarz/openrig**가 GitHub에서 약 **5.7K Stars**를 기록했다. 9월 30일～10월 7일 추적 사이트 기준 약 **+3.1K Stars**로 관심이 빠르게 늘었다. YAML로 여러 Agent의 역할·팀 연결관계를 선언하고, tmux 기반 세션과 로컬 데몬·CLI·TUI·MCP 서버를 통해 **Claude Code·Codex·Pi**를 한 팀으로 운영한다. `starter` 팀은 구현 Agent와 검토 Agent를 분리한다. 종료 시 스냅샷을 남기고 재시작하면 토폴로지를 복원할 수 있다.

macOS·Linux 지원이며 Node.js와 tmux가 필요하다. 현재 프로젝트는 설치와 실행 과정에서 사용자 로컬 설정·프로바이더 권한·신뢰 기록에 변경을 가할 수 있어 **운영 전 dry-run·정책 점검이 필수**다.

### 왜 중요한지
각각의 Coding Agent를 개별 대화창에서 운영하던 방식을 **역할 분담 → 작업 소유권 → 검토 → 상태 보존**으로 승격한다. 모델을 직접 개발하지 않아도 여러 모델과 도구를 묶는 **Agent Harness·Control Plane**의 가치가 커진다는 신호다.

## 4. Claude for Google Workspace — Docs·Sheets·Slides 직접 편집 베타

![Claude와 Google Docs가 함께 표시되는 작업 화면 — 관련 UI 예시](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/69433656958ac4e8cb0beab9_product.png)

**공식 발표:** 2026-10-06 / **이번 회차 신규 선정: 직전 브리핑에서 미수록**

### 핵심 요약
Anthropic이 **Claude for Google Workspace** 공개 베타를 유료 Claude 플랜에 도입했다. Google Docs·Sheets·Slides 안에 Sidebar로 Claude를 열거나 Claude 인터페이스 안에서 **양방향 커넥터**로 Google 파일을 생성·수정할 수 있다. Sheets에서는 수식·피벗·차트 등, Slides에서는 기존 테마와 레이아웃을 활용한 편집을 지원한다. 수정 전 승인 카드가 기본값이며 사용자가 연속 변경 승인을 선택할 수도 있다.

Google 파일의 기존 공유 권한이 적용되며, 조직 사용자는 관리자 정책과 커넥터 설정을 확인해야 한다. 베타로 일부 기능은 제한될 수 있다.

### 왜 중요한지
업무 AI가 단순히 내용을 생성하는 것을 넘어 **실제 업무 파일에 접근해 수정하고 승인을 받는 실행 주체**가 되고 있다. Google Workspace 내부의 Gemini와 타사 Agent가 같은 문서 위에서 경쟁하면서 **문서 편집 권한·승인 UX·변경 이력**이 차별화 요인이 될 수 있다.

## 5. GitLab Governed Software Factory — Agent가 쓴 코드를 CI/CD·정책·보안으로 통제

![GitLab의 Agentic Orchestration 및 개발 수명주기 개념도](https://res.cloudinary.com/about-gitlab-com/image/upload/v1755762266/iwuugge3cxweiyvi0yjk.png)

**공식 발표:** 2026-10-06 / **이번 회차 신규 선정: 직전 브리핑에서 미수록**

### 핵심 요약
GitLab이 **Governed Software Factory**의 기반 기능을 공개했다. Duo Agent Platform의 `/goal`과 Custom Flows·Flow Triggers가 기획부터 코드·테스트·배포까지 Agent Workflow를 연결한다. **Dependency Firewall**은 패키지의 취약점·악성코드·라이선스 위반을 빌드 전에 검사·차단하며, **Artifact Central**은 패키지와 컨테이너 아티팩트를 단일 관리 면에 둔다.

GitLab에 따르면 Orbit은 베타 기간 동안 **3,500개 이상 조직, 28만 건 이상 Agent 질의**에 사용됐다. 재시도 45배 감소·토큰 4.5배 감소라는 성능 수치는 GitLab의 자체 설명이며 실제 환경에서 추가 검증이 필요하다. 전체 기능이 동시에 정식 출시된 것은 아니며 일부는 베타·얼리 액세스다.

### 왜 중요한지
Coding Agent가 코드를 더 빨리 만들어도 실제 생산 환경에는 **권한, 의존성 검증, 서명·승인, 비밀정보 보호, 비용·변경 추적**이 필요하다. 기업의 차별화는 좋은 Coding Model 도입 자체보다 **Agent 작업을 안전하게 운영체계에 편입하는 DevSecOps Control Plane**에서 나타날 가능성이 크다.
