## 1. Tencent `ContextPilot-14B` — Agent가 자기 Context를 스스로 정리하도록 RL로 훈련

![ContextPilot](https://opengraph.githubassets.com/1/Tencent/ContextPilot)

### 핵심 요약

Tencent가 공개한 `ContextPilot`은 장시간 Agent가 모든 대화·검색·Tool 결과를 계속 Context Window에 쌓는 문제를 정면으로 다룬다. Qwen3 기반 `ContextPilot-14B`와 8B, Gemma 기반 E4B Checkpoint가 공개됐고, Agent가 **계획, 검색, 구조화 Memory, Context 삭제·압축·Offloading**을 직접 선택하도록 훈련한다.

핵심은 단순한 Context Compression 규칙이 아니라 RL이다. `context-aware partial rollout`은 결과에 영향이 큰 Context 편집 지점에 탐색을 집중하고, `fine-grained credit assignment`는 최종 보상을 모든 중간 행동에 똑같이 주는 대신 어떤 Context 편집이 이후 결과에 기여했는지를 Snapshot 수준으로 학습한다.

논문 보고 기준 `ContextPilot-14B-RL`은 32K Working Context로 네 개 장문 QA Benchmark 평균 **72.20**을 기록했고, Tool 없이 128K Context를 사용하는 Qwen3-14B의 **53.26**보다 높았다. 다만 이 수치는 연구팀 보고 결과이며 아직 독립 재현은 제한적이다. Model Weight의 License도 일반적인 Apache 2.0 상업 이용과 동일하지 않으므로 실제 제품 적용 전 확인이 필요하다.

### 왜 중요한가

Agent가 수시간～수일 일하면 Context Window를 무한히 키우는 방식은 비용과 품질 양쪽에서 한계가 온다. ContextPilot의 핵심 아이디어는 **Context 관리 자체를 Agent가 학습해야 하는 행동**으로 본다는 것이다.

`긴 Context = 더 좋은 Agent`가 아니라

`필요한 증거를 남기고 → 중요하지 않은 기록을 외부화하고 → 필요할 때 다시 불러오는 Agent`

가 더 효율적일 수 있다는 방향이다. Agent Memory·RAG·Context Engineering이 별도 Middleware 기능을 넘어 **Model의 학습 대상**으로 들어가는 흐름이라는 점에서 중요하다.

## 2. Qwen Code `v0.23.1-preview.2` — Coding Agent가 Subagent·Workflow·Worktree를 운영하는 실행환경으로

![Qwen Code](https://opengraph.githubassets.com/1/QwenLM/qwen-code)

### 핵심 요약

Alibaba Qwen 팀의 오픈소스 Coding Agent `Qwen Code`가 9월 7일 `v0.23.1-preview.2`를 공개했다. Preview Release이지만 변화 방향이 뚜렷하다. Web Shell에서 **Dynamic Workflow Run을 시각화·관리**하고, 실행 중인 Subagent 상태를 Transcript에서 실시간으로 확인할 수 있게 됐다.

여기에 Session Resource Catalog, Session Turn Navigation, `worktree-isolated named tasks`, Conversation Writer용 Session Lease, Peer IPC 개선 등이 추가됐다. 특히 Git Worktree로 Named Task를 격리하는 기능은 여러 Agent가 한 Repository에서 병렬 작업할 때 서로의 Working Tree를 망가뜨리지 않도록 하는 운영 계층에 가깝다.

### 왜 중요한가

Coding Agent가 단순히 `Terminal에서 코드 한 번 생성`하는 도구에서 벗어나고 있다. 앞으로 필요한 것은

`Task → Subagent → 격리된 Worktree → 상태 관찰 → 결과 통합`

같은 Multi-Agent Software Engineering Runtime이다.

Qwen Code의 이번 Preview는 모델 성능 자체보다 **장시간·병렬 Coding Agent를 어떻게 관찰하고 격리하고 조율할 것인가**가 경쟁 영역이 되고 있음을 보여준다. Claude Code, Codex, Qwen Code 같은 도구가 점점 IDE Plugin보다 작은 Agent Operating Environment에 가까워지는 흐름이다.

## 3. 🔥 GitHub `HyperFrames` — HTML을 쓰면 Agent가 MP4를 만든다

![HyperFrames](https://opengraph.githubassets.com/1/heygen-com/hyperframes)

### 핵심 요약

HeyGen의 오픈소스 `HyperFrames`가 오늘 GitHub Daily Trending 최상단에 올랐다. 확인 시점 기준 **45,671 Stars**, 하루 **+734 Stars**다. 프로젝트의 메시지는 단순하다. `Write HTML. Render video. Built for agents.`

HyperFrames는 HTML·CSS·Media·seekable animation을 **결정론적으로 MP4로 렌더링**한다. Agent는 기존에 잘하는 HTML 작성 능력을 그대로 사용하고, `/hyperframes` Skill을 통해 영상 기획 → HTML 작성 → Animation 연결 → Media 추가 → Lint → Preview → Render까지 수행한다. Claude Code, Cursor, Gemini CLI, Codex 등 Skill을 지원하는 Coding Agent에서 사용할 수 있으며 Apache 2.0이다.

9월 6일 공개된 `v0.8.30`에서는 Website Capture 시 페이지가 선언한 Icon과 Asset을 더 안정적으로 보존하고, File Handling과 느린 Scan을 제한하는 Hardening 작업이 추가됐다.

### 왜 중요한가

Video Generation이 꼭 `거대한 Text-to-Video Model 하나`로만 발전할 필요는 없다. 기업용 설명 영상, Chart Animation, Product Demo, 코드 Walkthrough처럼 구조가 명확한 영상은 오히려

`Agent → HTML/CSS/JS → Deterministic Renderer → MP4`

방식이 수정·재현·자동화에 유리하다.

특히 같은 Source를 Git으로 관리하고 CI에서 다시 렌더링할 수 있으므로 **영상도 Code Artifact처럼 다룰 수 있다.** Agent가 문서·코드뿐 아니라 시각 콘텐츠 제작 Workflow까지 직접 실행하는 방향을 잘 보여주는 프로젝트다.

## 4. `llama.cpp v0.4.0` — 최신 Open Model을 Local에서 돌리는 공통 Runtime이 Video·Sparse Attention까지 확장

![llama.cpp](https://opengraph.githubassets.com/1/ggml-org/llama.cpp)

### 핵심 요약

Local LLM Runtime의 핵심 프로젝트 중 하나인 `llama.cpp`가 9월 4일 `v0.4.0`을 공개했다. 이번 버전은 Qwen3.8-Flash-Next와 NVIDIA Nemotron-3-Puzzle-75B-A9B 초기 지원, **Lazy Tensor Reading**, Per-slot Context Limit, Video Input, Sparse Flash Attention, Apple RDMA Transport 등을 포함한다.

`--lazy-mode`는 Model Tensor를 시작 시 모두 읽어들이는 대신 필요한 시점에 읽도록 하며, Quantizer RAM Cap·Row-slab Streaming·Load 시 RAM Peak 억제도 추가됐다. Multimodal 쪽에서는 Video Parameter와 DeepSeek-V4-Flash-Vision-Exp 지원이 들어갔고, `ggml 0.23.0`은 Sparse Attention과 Async/RPC Backend 작업을 확대했다.

### 왜 중요한가

Open Model 생태계에서 Model Weight만큼 중요한 것이 **공통 실행 계층**이다. 최신 Qwen·DeepSeek·Nemotron이 나와도 실제 개인 PC나 Edge Device에서 안정적으로 실행할 Runtime이 없으면 활용이 어렵다.

이번 Release에서 특히 주목할 부분은

`더 큰 모델을 전부 RAM에 올린다`

보다

`필요한 Tensor만 읽고 → Sparse하게 계산하고 → 여러 Device/Backend에 분산한다`

는 방향이다. Local AI가 작은 모델 Demo를 넘어 더 큰 Multimodal·Agent Workload를 수용하기 위한 Runtime Engineering 단계로 이동하고 있다.

## 5. 중국 AI Chip ‘네 마리 용’ 급성장 — NVIDIA의 중국 점유율 약 55%까지 하락

[![Enflame AI chip](https://www.reuters.com/resizer/v2/)](https://www.reuters.com/commentary/breakingviews/chinas-ai-dragons-breathe-fire-nvidias-moat-2026-09-07/)

### 핵심 요약

Reuters Breakingviews는 9월 7일 중국의 AI Chip 스타트업 **Enflame, Moore Threads, MetaX, Biren**이 NVIDIA의 중국 시장 지배력을 빠르게 잠식하고 있다고 분석했다. Reuters가 인용한 수치로 NVIDIA의 중국 AI Chip 시장 점유율은 과거 사실상 독점에 가까운 수준에서 현재 약 **55%**까지 내려왔다.

Tencent가 투자한 Enflame은 최근 Shanghai IPO로 약 **$908M**을 조달했고 기업가치는 약 **$9.1B**로 평가됐다. 1분기 매출은 전년 대비 1,475% 증가했다. 회사는 조달 자금을 5세대·6세대 AI Chip과 관련 Software·Hardware 개발에 투입할 계획이다. Moore Threads 등은 CUDA로 작성된 Software의 이전 장벽을 낮추는 호환 계층에도 힘을 쏟고 있다.

### 왜 중요한가

AI Chip 경쟁에서 NVIDIA의 진짜 Moat는 GPU 성능만이 아니라 **CUDA Software Ecosystem**이었다. 중국 업체들이 Hardware와 함께 Migration Tool·Software Stack을 구축하고, 거대한 내수 Inference 수요를 확보하면 경쟁 기준이 달라질 수 있다.

특히 Training보다 훨씬 많은 장기 수요가 예상되는 **Inference 시장**에서는 전력 효율, 가격, 공급 안정성, 기존 Software의 이전 비용이 중요하다. 미국의 Export Control이 오히려 중국 내 대체 Hardware와 Software Ecosystem에 강한 투자 동기를 주고 있다는 점도 장기적으로 봐야 한다.

## 이번 회차 핵심

이번 5개를 연결하면 **Agent 시대의 병목이 Context·Orchestration·Content Runtime·Inference Runtime·Physical Compute Stack으로 퍼지고 있다**는 흐름이 보인다.

**ContextPilot** → Agent가 자기 Working Context를 학습해 관리  
**Qwen Code** → 여러 Coding Agent Task를 격리·관찰·조율  
**HyperFrames** → Agent가 Video Production까지 Code Workflow로 실행  
**llama.cpp** → 최신 Open Model을 Local Runtime으로 흡수  
**중국 AI Chip 생태계** → NVIDIA CUDA 중심의 Physical Compute 경쟁 확대

이번 회차에서 특히 중요한 것은 `ContextPilot`과 `HyperFrames`다. 하나는 Agent가 **무엇을 기억하고 버릴지**를 학습하는 방향이고, 다른 하나는 Agent가 기존 Software Skill인 HTML을 이용해 **새로운 전문 작업 영역인 Video Production까지 확장**하는 방향이다.

> **Agent 경쟁력은 더 큰 Context Window 하나보다, 필요한 정보를 능동적으로 관리하고 기존의 범용 Software Interface를 Tool로 재사용하는 능력에서 커질 가능성이 높다.**
