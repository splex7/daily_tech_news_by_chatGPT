# AI·LLM·에이전트 최신 브리핑

**2026년 9월 15일 20시 KST 기준**

오늘 08시 브리핑의 Bolt Forge, Salesforce Agentforce Long-Horizon Runtime, Perplexity Portable Computer Windows RTX, Temporal, AWS Pizza Bot은 중대한 추가 업데이트가 없어 제외했다. 이번 회차는 Agent가 웹에 접근하는 방식의 변화, Agent 특화 오픈웨이트 모델, 산업 특화 Frontier AI, 오픈소스 Agent의 Credential Security, 국내 Agent Security 가이드라인을 중심으로 선정했다.

## 1. Cloudflare, 오늘부터 `Search·Agent·Training`을 분리 — 광고 페이지의 AI Agent와 Training Bot 기본 차단

![Cloudflare AI crawl control](https://cf-assets.www.cloudflare.com/zkvhlag99gkb/4Hr3EhsMBH0oVwMVKywwre/2a01efbe03d67a8154123b63c05c000f/image3.png)

**핵심 요약:** Cloudflare가 7월 예고했던 새로운 AI Bot 기본 정책이 오늘인 9월 15일부터 적용된다. Cloudflare는 자동화 트래픽을 `Search`, `Agent`, `Training`으로 구분한다. Search는 검색 색인을 위한 수집, Agent는 ChatGPT-User나 Browser-use Agent처럼 사용자를 대신해 실시간으로 사이트를 방문하는 작업, Training은 모델 학습·Fine-tuning을 위한 수집이다.

새롭게 Cloudflare에 등록되는 도메인에서는 광고가 표시되는 페이지에 대해 `Training`과 `Agent`가 기본 차단되고 `Search`는 기본 허용된다. 또한 Search와 Training을 한 Crawler가 함께 수행하는 Multi-purpose Crawler는 가장 제한적인 규칙에 따라 처리된다. 따라서 사이트가 Training을 막도록 설정한 경우 Search 기능도 함께 가진 Crawler가 차단될 수 있다. Cloudflare는 BotBase와 robots.txt의 Content Signal도 이 분류 체계에 맞춰 확장하고 있다.

**왜 중요한지:** 지금까지 웹의 기본 계약은 대체로 `Crawler가 콘텐츠를 가져감 → 검색 결과에서 방문자를 돌려줌`이었다. AI Agent는 이 구조를 바꾼다. Agent가 사이트에 들어와 정보를 읽고, 비교하고, 구매까지 끝내면 사용자가 원본 사이트를 직접 방문하지 않을 수도 있다.

Cloudflare가 `검색용 Bot`과 `사용자를 대신해 행동하는 Agent`를 인프라 레벨에서 서로 다른 Traffic Category로 취급하기 시작했다는 점이 핵심이다. Agent 시대에는 robots.txt만큼 `Agent Access Policy`, `Content Use Policy`, `Bot Identity`가 웹 인프라의 기본 요소가 될 가능성이 높다.

## 2. Abacus.AI `Smaug` 3종 오픈웨이트 — DeepSeek V4 Flash·Qwen3.8·Kimi K3를 Agent용으로 재훈련

![Abacus Smaug](https://abacus.ai/static/hb4c41652/imgs/research/smaug_flash.webp)

**핵심 요약:** Abacus.AI가 Agentic Workload에 특화한 오픈웨이트 모델 제품군 `Smaug`를 공개했다. `Smaug Flash`는 DeepSeek V4 Flash 0731, `Smaug Mini`는 Qwen3.8 27B, `Smaug Agentic`은 Kimi K3를 기반으로 한다. 세 모델 모두 기존 Base Architecture를 바꾸기보다 실제 Multi-turn Tool-use Trace와 어려운 Synthetic Example을 활용한 Agentic Post-training에 초점을 맞췄으며 Weight는 Hugging Face를 통해 공개된다.

Abacus 자체 평가에서 Smaug Flash는 LiveBench Agentic Coding 61.1로 Base DeepSeek V4 Flash의 46.8을 앞섰고 AutomationBench는 38.83 대 25.1, NL2Repo-Bench는 73.3 대 54.2를 기록했다. Smaug Agentic은 DeepSWE에서 69.9 대 Kimi K3의 67.5로 개선됐지만 Terminal-Bench 2.1에서는 86.5 대 88.3으로 Base보다 낮았다. 따라서 모든 Benchmark에서 일방적인 향상이라기보다 Agent Loop의 안정성과 Tool-use 행동을 강화하는 Fine-tuning으로 보는 편이 정확하다. 이 수치는 Abacus 자체 평가를 포함하므로 독립 검증과는 구분할 필요가 있다.

**왜 중요한지:** 오픈모델 경쟁의 중심이 `누가 더 큰 Base Model을 Pretrain하는가`에서 `이미 강력한 Base Model을 실제 Agent Workflow에 맞게 얼마나 잘 Post-train하는가`로 이동하고 있다.

특히 Smaug Agentic은 Kimi K3를 서비스할 수 있는 Inference Stack에서 그대로 Drop-in Replacement로 사용할 수 있도록 Architecture를 유지한다. 앞으로 기업은 매번 새로운 Foundation Model을 직접 학습하기보다 `Open Base → 기업·Agent Trace 기반 Post-training → 자체 VPC 배포` 방식으로 전문 Agent Model을 만드는 경우가 늘어날 가능성이 높다.

## 3. TotalEnergies × Mistral, `€100M+` 투자 — 석유·가스 Reservoir 전용 Frontier AI 모델 공동 개발

![TotalEnergies and Mistral AI](https://www.lemagit.fr/visuals/LeMagIT/hero_article/totalmistral.jpg)

**핵심 요약:** TotalEnergies와 Mistral이 오늘 3년간 1억 유로 이상을 투자하는 공동 프로그램을 발표했다. 목표는 석유·가스 Reservoir의 탐사, 특성 분석, 개발을 지원하는 새로운 세대의 Frontier AI Model을 만드는 것이다.

양사는 Joint Scientific Laboratory를 만들고 TotalEnergies가 축적한 약 한 세기의 Geoscience·Reservoir Engineering 지식과 대규모 Proprietary Subsurface Data를 Mistral의 모델 및 Agentic AI 기술과 결합한다. 모델은 대량의 지질·저류층 데이터를 통합·해석하고 여러 Exploration·Development Scenario를 생성하며 기존 프로젝트의 수명과 생산성을 최적화하는 데 사용될 예정이다. TotalEnergies는 이를 유럽 Digital Ecosystem 안에서 자체 Proprietary Model을 구축하는 전략으로 설명했다.

**왜 중요한지:** 기업용 AI가 `범용 LLM + RAG`를 넘어서 특정 산업의 핵심 의사결정 자체를 위한 Frontier Model로 진화하고 있다. Reservoir Engineering은 데이터가 독점적이고 Domain Knowledge의 진입장벽이 높으며 한 번의 판단이 수십억 달러 규모 프로젝트에 영향을 줄 수 있는 분야다.

이런 시장에서는 인터넷 공개 데이터보다 `기업이 수십 년 동안 축적한 고유 데이터 + 전문가 Workflow + 모델 Post-training`이 더 큰 경쟁력이 된다. AI 회사와 대기업이 단순 API 공급자·고객 관계가 아니라 공동 연구소를 만들고 전용 Frontier Model을 개발하는 형태가 Vertical AI의 중요한 사업모델로 자리 잡을 수 있다.

## 4. 🔥 GitHub `Hermes Agent` 24만 Stars 돌파 — 비밀번호를 Agent에게 보여주지 않고 로그인·결제

![Hermes Agent](https://pbs.twimg.com/media/HE5I2_pbsAAvYvX.jpg)

**핵심 요약:** Nous Research의 MIT 오픈소스 `Hermes Agent`가 확인 시점 GitHub 약 24.6만 Stars와 5.1만 Forks를 기록하며 빠르게 성장하고 있다. 저장소도 9월 15일 현재 계속 업데이트되고 있다. 최신 정식 릴리스 `v0.21.2`의 가장 눈에 띄는 기능은 `Password-blind credential vault`다.

Hermes는 1Password, Bitwarden 또는 자체 Local Vault의 Credential을 이용해 웹사이트에 로그인하거나 주소를 입력하고 결제를 수행할 수 있지만, Agent Model 자체에는 Password나 Secret을 노출하지 않는다. 2FA도 저장된 Authenticator Key 또는 사용자 UI를 통해 처리한다. 함께 추가된 Plugin Catalog는 Plugin을 Commit SHA로 고정하고, Multi-profile 환경에서는 다른 Agent Profile의 Secret이나 Allow-list가 섞이지 않도록 격리를 강화했다.

**왜 중요한지:** Browser-use Agent가 실제 업무를 하려면 결국 Gmail, GitHub, 쇼핑몰, SaaS, 결제 시스템에 로그인해야 한다. 하지만 Password와 API Key를 LLM Context에 넣는 순간 Prompt Injection이나 Tool Hijacking이 Credential 탈취로 바로 이어질 수 있다.

따라서 Agent 시대의 Credential Architecture는 `Agent가 Secret을 안다`가 아니라 `Agent에게 필요한 Capability만 위임하고 Secret은 보지 못하게 한다`가 되어야 한다. Hermes의 Password-blind Vault는 Personal Agent가 현실 세계의 Action을 수행하면서도 Secret Exposure를 줄이는 중요한 오픈소스 패턴이다.

출처: [Hermes Agent GitHub](https://github.com/NousResearch/hermes-agent), [v0.21.2 Release](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.11)

## 5. 한국 KISA, `Autonomous AI Agent` 보안 가이드라인 개발 — Physical AI까지 공통 통제 검토

![KISA AI Security Manual](https://trustworthyai.co.kr/assets/img/posts/2026-07-08-ai-security-threat-mitigation-manual/cover.jpg)

**핵심 요약:** 한국인터넷진흥원 KISA가 기업의 Agentic AI 도입 확산에 맞춰 기존 `AI Security Guide`를 개정하고 있다고 9월 15일 밝혔다. 새 가이드는 사람이 모든 단계를 직접 감독하지 않아도 스스로 Tool을 사용하고 Action을 수행하는 Agentic AI Service에서 발생할 수 있는 보안 문제에 초점을 맞추며, 기업이 적용할 수 있는 Risk Management Checklist를 제공할 예정이다.

KISA는 또한 현실의 기기와 기계를 직접 제어하는 `Physical AI`에도 적용 가능한 공통 통제 항목을 포함할 수 있다고 설명했다. 특정 Frontier Model을 겨냥한 규제가 아니라 Agentic AI System 전반의 보안 통제를 다루는 방향이다. KISA는 올해 7월에도 Prompt Injection, 권한 오용, Data Leakage 등을 포함한 AI 보안 위협 대응 매뉴얼과 Red Teaming Guide를 발표한 바 있다.

**왜 중요한지:** LLM Security에서는 지금까지 Prompt Injection이나 Data Leakage가 핵심이었다. 하지만 Agent가 Shell, Browser, SaaS, Robot, 산업 장비를 직접 제어하면 위험의 단위가 `잘못된 답변`에서 `잘못된 행동`으로 바뀐다.

앞으로 기업의 Agent Security Checklist에는 `Tool Permission`, `Credential Isolation`, `Network Access`, `Human Approval`, `Audit Log`, `Physical Action Limit` 같은 항목이 기본 통제로 들어갈 가능성이 높다. 특히 한국이 AI Agent와 Physical AI를 같은 Security Framework 안에서 다루기 시작했다는 점에서 국내 기업의 Agent 도입 정책에도 직접적인 영향을 줄 수 있다.

## 이번 회차의 핵심

이번 다섯 소식은 Agent 시대에 `모델이 얼마나 똑똑한가` 외에 새로운 인프라 계층이 빠르게 중요해지고 있음을 보여준다.

- **Cloudflare** → Agent가 웹에 접근할 수 있는 권한과 콘텐츠 사용 목적을 분리
- **Smaug** → Base Model보다 Agent Workflow용 Post-training을 강화
- **TotalEnergies × Mistral** → 기업 고유 데이터로 산업 전용 Frontier Model 구축
- **Hermes Agent** → Secret을 보여주지 않고 현실의 Action Capability를 위임
- **KISA** → Agent와 Physical AI 행동을 통제하는 Security Policy 정립

결국 경쟁 단위는 점점 다음 전체 경로로 넓어지고 있다.

> **Model → Post-training → Proprietary Data → Tool Permission → Credential → Web Access → Security Governance**

Agent가 실제 업무와 인터넷, 물리적 시스템에 더 깊게 연결될수록 가장 중요한 기술은 단순한 Reasoning 성능뿐 아니라 **무엇을 볼 수 있고, 어디까지 행동할 수 있으며, 그 권한을 어떻게 증명하고 제한하는가**가 될 가능성이 높다.
