## 1. Anthropic Claude, 페르마의 마지막 정리를 11일 만에 Lean으로 완전 형식화

**핵심 요약:** Anthropic은 9월 4일 Claude가 11일 동안 대체로 자율적으로 작업해 페르마의 마지막 정리 FLT의 첫 end-to-end computer-checked formalization을 완성했다고 발표했다. Claude는 약 1,300만 줄의 Lean 코드와 최종 증명에 사용된 약 29,500개의 중간 정리를 만들었다. 다만 이것은 Wiles의 정리를 새로 발견한 것이 아니라, 기존 수학적 증명을 Lean이 기계적으로 검증할 수 있는 형태로 바꾼 작업이다. Mathlib과 Imperial College London FLT 프로젝트, flt-regular 등 기존 형식화 자산도 활용했다.

특히 수십 개 Claude Agent가 병렬로 작업했고, Prove2Me가 theorem DAG, 검색·재사용, 컴파일 구조를 관리했다. Anthropic은 초기에 Agent들이 프로젝트 상태를 잃고 협업에 실패했지만 이 구조를 적용한 뒤 완주했다고 설명했다.

**왜 중요한지:** 핵심은 단순히 “AI가 어려운 수학을 했다”가 아니다. AI가 생성하는 연구가 늘어날수록 사람의 검증 능력이 병목이 되는데, 이번 사례는 **생성 → 형식화 → 기계 검증**이라는 경로가 대규모 수학에도 현실화될 수 있음을 보여준다. 동시에 장시간 Multi-Agent 작업에서는 더 좋은 모델만큼이나 DAG, 공유 상태, 검색 가능한 중간 산출물 같은 Harness가 중요하다는 사례이기도 하다.

- 공식 발표 및 이미지: https://www.anthropic.com/research/formalizing-fermats-last-theorem
- 전체 증명: 공식 발표에서 연결된 Anthropic GitHub 저장소

## 2. Google `TimesFM-3` — 330M 모델로 Zero-shot 다변량 시계열 예측

**핵심 요약:** Google Research가 8월 31일 `TimesFM-3`를 공개했고 9월 5일 GitHub Trending에도 올라왔다. 330M parameters를 1조 개가 넘는 실제·합성 시계열 point로 사전학습했으며, 여러 target series와 과거 covariate, 미래까지 알려진 dynamic covariate를 별도 task fine-tuning 없이 함께 처리한다. 이전 세대와 달리 전체 예측 horizon을 single forward pass로 생성하고, 각 target에 대해 10～90 분위수의 9개 quantile도 출력한다.

Google 자체 평가는 GIFT-Eval, FEV-Bench, TIME에서 pretrained foundation model 가운데 최상위라고 보고한다. GitHub Trending의 9월 5일 화면에서는 약 31,005 stars, 당일 +340 stars로 표시됐다. 주의할 점은 source code는 Apache 2.0이지만 TimesFM 3.0 pretrained weights는 현재 별도 non-commercial license로 배포돼 상업·production 용도가 허용되지 않는다는 점이다.

**왜 중요한지:** Foundation Model 접근이 텍스트·이미지를 넘어 기업의 핵심 구조화 데이터인 **수요, 매출, 트래픽, 센서, 장애량 같은 시계열**로 빠르게 확장되고 있다. 특히 promotion·날씨처럼 미래에 이미 알려진 변수까지 zero-shot으로 넣을 수 있다면 기존의 “업무별 모델 학습” 비용을 크게 줄일 가능성이 있다. Cloud·DevOps에서도 capacity forecasting이나 anomaly baseline 같은 영역에 적용할 수 있는 흐름이다.

- Google Research: https://research.google/blog/timesfm-3-a-zero-shot-foundation-model-for-multivariate-forecasting/
- GitHub: https://github.com/google-research/timesfm

## 3. `GitSpawn` — Coding Agent가 Prompt 전에 Git을 실행하면서 생긴 공통 RCE 취약점

**핵심 요약:** Manifold Security가 공개한 `GitSpawn`은 Claude Code, OpenAI Codex, Cursor, Goose, Hermes Agent, Qwen Code, Grok Build 등 여러 Coding Agent에서 발견된 공통 취약점 계열이다. Agent들이 프로젝트 Context를 얻기 위해 자동으로 `git status`나 `git diff`를 실행할 때 repository-local `.git/config`를 충분히 무력화하지 않으면, Git 설정이 host에서 명령을 실행하도록 악용될 수 있었다. 일부 제품에서는 workspace trust 승인이나 사용자 Prompt보다 먼저 실행됐다.

중요한 제한도 있다. 일반적인 `git clone`, fetch, pull은 공격자의 `.git/config`를 전달하지 않으므로 이 경로로는 같은 문제가 발생하지 않는다. 위험한 경우는 `.git` 디렉터리가 포함된 ZIP, 공유 드라이브, 동기화 폴더, USB 등으로 프로젝트 전체를 전달받는 경우다. Manifold 공개 시점에는 7개 Agent에서 8개 finding을 확인했고 Codex와 Cursor 등 일부는 이미 패치됐다. Hermes Agent의 CVE-2026-71963은 0.18.2～0.21.0이 영향받는 것으로 등록됐으며 수정 commit도 공개됐다.

**왜 중요한지:** Agent 보안의 공격 표면이 Prompt Injection만이 아니라는 점을 보여준다. Coding Agent는 Shell·Git·파일·Credential을 실제 사용자 권한으로 다루기 때문에 **Agent가 읽는 Repository, Skill, MCP, Plugin 자체가 Supply Chain 입력**이 된다. 실무에서는 Coding Agent를 최신 버전으로 유지하고, 파일 형태로 받은 낯선 Repository는 Agent로 열기 전에 `.git/config`를 확인하거나 `.git`을 제거하고 정상 clone 경로로 다시 구성하는 것이 안전하다.

- Manifold Security: https://www.manifold.security/blog/ai-coding-agents-git-hijack
- Hermes 관련 CVE: CVE-2026-71963

## 4. 🔥 GitHub 1위 `mattpocock/skills` — “프롬프트”보다 엔지니어링 습관을 Skill로 패키징

**핵심 요약:** 9월 5일 GitHub Trending에서 `mattpocock/skills`가 전체 1위를 기록했다. 화면 기준 약 250,120 stars이며 당일 +2,757 stars다. 이 저장소는 Claude Code, Codex 등에서 사용하는 개발 Skill을 작고 조합 가능한 파일로 제공한다. Claude Code 공식 Marketplace Plugin으로 설치하거나, `skills` installer를 이용해 일반 파일 형태로 프로젝트에 복사해 직접 수정할 수도 있다.

내용은 단순 Prompt 모음과 거리가 있다. 요구사항을 깊게 묻는 `grill-with-docs`, 프로젝트 용어를 `CONTEXT.md`에 축적하는 shared language, ADR 기록, TDD, bug diagnosis, architecture review, spec→ticket→implementation workflow 등 전통적인 Software Engineering 습관을 Agent가 반복 수행할 수 있게 만든다.

**왜 중요한지:** Agent 생태계에서 재사용 가능한 자산의 단위가 **좋은 Prompt 한 문장 → 반복 가능한 업무 절차와 기준을 담은 Skill**로 이동하고 있음을 보여준다. 모델이 Claude에서 Codex로 바뀌어도 CONTEXT.md, ADR, 테스트 규칙, 리뷰 절차는 남는다. AI 시대에 기존 Software Engineering 원칙이 사라지는 것이 아니라 오히려 Agent가 실행 가능한 형태로 패키징되고 있다는 사례다.

- GitHub: https://github.com/mattpocock/skills
- GitHub Trending: https://github.com/trending

## 5. ByteDance, AI 해외 확장 위해 `$29.6B` 대출 확보 — AI Capex가 은행 메가론 시장까지 이동

**핵심 요약:** Reuters는 9월 4일 ByteDance가 약 30개 은행으로부터 296억 달러 규모 대출을 확보했다고 관계자를 인용해 보도했다. 당초 목표는 200억 달러였지만 수요가 커져 규모가 늘었고, 중국 은행이 전체의 60% 이상을 공급한 것으로 전해졌다. Reuters 소식통에 따르면 자금은 주로 AI 관련 계획과 중국 밖의 프로젝트에 사용될 예정이며 ByteDance는 동남아시아 여러 데이터센터의 장기 capacity 구매자 역할도 하고 있다.

이 대출은 올해 아시아에서 SoftBank가 OpenAI 투자 확대를 위해 조달한 400억 달러 다음으로 큰 규모다. ByteDance와 JPMorgan은 Reuters의 관련 질의에 즉시 답하지 않았고 Citi는 논평을 거부했으므로 자금 사용 세부사항은 소식통 보도라는 점을 구분해야 한다.

**왜 중요한지:** AI 경쟁의 자금조달 방식이 VC·주식 투자만이 아니라 **은행 대출로 수십억～수백억 달러 규모 Compute와 Data Center capacity를 선구매하는 단계**로 넘어가고 있다. Frontier AI의 경쟁력은 이제 Model 성능뿐 아니라 전력, 데이터센터, GPU, 장기 금융 조달 능력까지 포함한다.

- Reuters, 2026-09-04: https://www.reuters.com/legal/transactional/bytedance-secures-296-billion-loan-ai-push-sources-say-2026-09-04/

## 이번 회차 핵심

이번 회차를 하나의 흐름으로 묶으면 다음과 같다.

**Claude FLT → AI가 복잡한 연구를 생성하고 기계 검증**  
**TimesFM-3 → Foundation Model이 기업 시계열 데이터로 확장**  
**GitSpawn → Agent가 실제 도구를 쓰면서 새로운 Supply Chain 위험 발생**  
**Agent Skills → 업무 지식과 엔지니어링 규율이 재사용 가능한 파일로 축적**  
**ByteDance 대출 → 이를 돌릴 Compute가 금융시장 규모의 자본을 요구**

가장 주목할 두 가지는 Claude의 FLT 형식화와 `mattpocock/skills`다. 둘 다 모델 성능만으로는 설명되지 않는다. Claude의 수학 작업은 공유 DAG와 재사용 가능한 정리 구조가 있어야 완주했고, Coding Agent는 프로젝트의 Context와 엔지니어링 규칙이 파일로 남을수록 반복 작업의 품질이 올라간다.

> **AI가 강해질수록 경쟁력은 Prompt 자체보다 검증 가능한 중간 산출물, 구조화된 Context, 반복 가능한 Workflow를 얼마나 잘 축적하느냐로 이동하고 있다.**
