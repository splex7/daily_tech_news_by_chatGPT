## 1. MiniMax M3.1 Flash 공식 출시 — Agent 성능과 실행비용을 동시에 겨냥

![MiniMax M3.1 Flash 공식 벤치마크 비교표](https://filecdn.minimax.chat/public/m31-flash-en-2-1792403273121-webp-1.m31-flash-en-2-1792403273121-webp)

*이미지: MiniMax 공식 벤치마크 자료. 타사 독립 평가가 아닌 개발사 측정치.*

**발표: 10월 19일 · MiniMax**

### 핵심 요약
MiniMax가 코딩, Computer Use, 보안 분석, 장시간 Agent 작업에 최적화한 **M3.1 Flash**를 공식 출시했습니다. 개발사는 기존 모델 대비 온라인 추론을 약 3배 빠르게 하고 Agent 작업의 전체 사용비용을 70% 낮췄다고 발표했습니다. 생성속도는 중앙값 기준 초당 170토큰 이상, 특정 조건에서 200토큰 이상이라고 설명합니다.

| API 비용 | 100만 토큰당 |
|---|---:|
| 입력 | **$0.15** |
| 출력 | **$0.60** |
| 캐시 입력 | **$0.015** |

자체 평가에서는 DeepSWE v1.1 **73.7**, OSWorld V2 **61.7**, BankerToolBench **76.2**를 기록했습니다. **API, M Plan, MiniMax Code는 이용 가능하지만 모델 가중치는 아직 공개되지 않았으며 추후 공개 예정**입니다. 성능 수치는 독립적인 재현 평가가 아닙니다.

### 왜 중요한가?
복잡한 Agent는 한 번의 답변이 아닌 수십 번의 도구 호출과 긴 추론을 수행합니다. 따라서 **토큰당 단가뿐 아니라 작업 한 건을 끝내는 총비용·속도·성공률**이 경쟁력이 됩니다. 저렴한 API가 항상 더 경제적이라는 뜻은 아니므로 실제 업무 평가가 필요합니다.

## 2. AWS TorchNeuron 공개 예고 — PyTorch 코드로 Trainium을 직접 사용

![AWS TorchNeuron의 네이티브 PyTorch 백엔드 아키텍처](https://awsdocs-neuron.readthedocs-hosted.com/en/v2.28.0/_images/pytorch-native-neuron-stack.png)

*이미지: AWS Neuron 공식 기술 문서의 구성도.*

**발표: 10월 19일 · PyTorch·AWS**

### 핵심 요약
AWS와 PyTorch 진영이 Trainium2·Trainium3 가속기를 네이티브 PyTorch 장치처럼 사용할 수 있게 만드는 **TorchNeuron**을 공개했습니다. 모델을 **.to('neuron')**으로 옮기거나 **torch.compile**에 Neuron 백엔드를 지정하는 방식입니다. 즉시 실행하는 Eager 모드, 컴파일 최적화, 분산 학습, 프로파일링과 사용자 정의 커널도 지원 대상으로 소개했습니다.

**Apache 2.0 오픈소스·공개 베타의 예정일은 10월 20일 미국 현지 행사 시점**입니다. 한국시간 20일 08시 기준 이미 사용 가능한 정식 제품이라고 단정해서는 안 됩니다.

### 왜 중요한가?
AI 인프라의 선택지가 CUDA 중심 GPU에서 AWS 자체 설계 가속기로 확대됩니다. 기존 PyTorch 워크플로를 크게 바꾸지 않고 하드웨어를 선택할 수 있다면 **벤더 종속과 추론·학습 비용**을 비교하기 쉬워집니다. 다만 API 호환성만으로 모델별 성능이나 이식 작업이 모두 해결되지는 않습니다.

**출처:** [PyTorch 공식 발표, 2026-10-19](https://pytorch.org/blog/introducing-torchneuron-native-pytorch-backend-for-aws-trainium/) · [AWS Neuron 공식 아키텍처](https://awsdocs-neuron.readthedocs-hosted.com/en/v2.28.0/frameworks/torch/pytorch-native-overview.html)

## 3. Modal, NVIDIA Vera CPU 채택 — AI Agent 실행 인프라에서 GPU만큼 CPU가 중요해진다

![NVIDIA Vera CPU 제품 참고 이미지](https://cdn.3dnews.ru/assets/external/illustrations/2026/03/17/1138392/vera_03.png)

*이미지: NVIDIA Vera CPU 관련 기존 제품 참고 이미지. Modal 도입 현장 사진은 아닙니다.*

**발표: 10월 19일 · Reuters / Modal**

### 핵심 요약
Agent용 격리 실행환경인 Sandbox를 제공하는 **Modal이 NVIDIA의 Vera CPU를 새로 도입**하기로 했습니다. Modal은 기존에는 Intel과 AMD CPU를 사용했습니다. 자체 초기 실험에서 NVIDIA Vera가 기존에 이용하던 CPU 대비 Agent 처리 작업량을 **약 2배** 높였다고 설명했습니다.

중요한 조건은 비교 대상이 **현재 판매 중인 기존 Intel·AMD 제품**이라는 점입니다. 앞으로 출시되는 경쟁사의 신제품까지 비교한 결과는 아닙니다. 또한 Modal은 Intel·AMD를 중단하지 않고 혼합 인프라를 계속 운영할 계획입니다.

### 왜 중요한가?
Agent는 모델 추론뿐 아니라 Python 실행, 브라우저 조작, 파일 처리, 테스트 등 **CPU 작업**을 많이 수행합니다. 이번 채택은 NVIDIA가 GPU뿐 아니라 Agent 실행서버 CPU에서도 경쟁을 확대한다는 신호입니다. 10월 15일 다룬 Modal의 투자 유치와는 별개의 새로운 사업·기술 업데이트입니다.

**출처:** [Reuters, 2026-10-19](https://www.reuters.com/business/nvidia-wins-fast-growing-ai-startup-modal-new-central-processors-2026-10-19/) · [NVIDIA Vera 기술 개요](https://investor.nvidia.com/news/press-release-details/2026/NVIDIA-Unveils-Vera-the-CPU-for-Agents/default.aspx)

## 4. Microsoft Project Perception 확장 — Agent의 위험 수준에 따라 권한을 실시간 축소

![Microsoft Dynamic Agent Risk 위험도 분석 체계](https://www.microsoft.com/en-us/security/blog/wp-content/uploads/2026/10/image-21.webp)

*이미지: Microsoft Security 공식 블로그의 Dynamic Agent Risk 구성도.*

**발표: 10월 19일 · Microsoft Security**

### 핵심 요약
Microsoft가 보안 프로젝트 **Project Perception**을 기업 내부 AI Agent 통제 분야로 확대한다고 밝혔습니다. 로컬 Agent 탐지 대상을 **35종 추가해 총 60종**으로 넓히며 Claude Code, Codex, GitHub Copilot 등을 포함합니다.

핵심은 Agent에 사용자의 모든 권한을 물려주지 않고, **Agent 고유 ID, 작업별 최소 권한, 유효기간, 동적 위험도 평가**를 적용하는 것입니다. 외부 문서의 프롬프트 인젝션과 같은 징후가 발생하면 읽기 권한은 유지하면서 수정·승인 권한을 차단하거나, 사람 승인을 요구하고, 필요하면 실행환경을 격리하는 접근입니다. Dynamic Permissions, Dynamic Agent Risk, Guardian Agents 등의 기술을 발표했지만 기능별 실제 제공 단계는 다를 수 있습니다.

### 왜 중요한가?
AI Agent의 행동은 시작할 때 안전했어도 **작업 도중 읽은 데이터에 따라 위험해질 수 있습니다**. 따라서 '처음 로그인할 때 인증'만으로 부족하며 **실행 중 지속적 권한 검증**이 필요합니다. 기존 브리핑의 일반적인 Agent 권한관리 소식보다 실시간 위험 판단과 단계적 대응을 구체화한 새 발표입니다.

**출처:** [Microsoft Security 공식 발표, 2026-10-19](https://www.microsoft.com/en-us/security/blog/2026/10/19/agents-are-your-newest-insiders-security-must-move-at-their-speed/)

## 5. GitHub 오픈소스 Scout — 어떤 LLM이든 연결하는 브라우저 작업 Agent

![Outcrawl Scout 공식 브라우저 자동화 데모](https://raw.githubusercontent.com/outcrawlai/scout/main/.github/assets/demo-light.gif)

*이미지: Scout GitHub README의 실제 웹페이지 조작 데모.*

**GitHub 주목 프로젝트 · 10월 20일 확인 · Apache 2.0**

### 핵심 요약
**outcrawlai/scout**은 자연어로 지시하면 실제 브라우저를 열어 페이지 읽기, 클릭, 입력, 스크롤, 비교 등의 작업을 실행하는 TypeScript 기반 오픈소스입니다. **2026년 10월 20일 확인 시점 약 949 Stars**를 기록했습니다.

브라우저는 **개발자 로컬 환경 또는 Outcrawl 클라우드**에서 실행할 수 있습니다. 모델은 내장돼 있지 않아 OpenAI 호환 Chat Completions API를 제공하는 외부 서비스나 로컬 LLM을 연결해야 합니다. 모델을 역할별로 나눠 **hands는 행동, brain은 계획, eyes는 이미지 관찰, extract는 결과 정리**에 사용할 수 있습니다. 설치는 Node.js 22 이상에서 **npm i @outcrawl/scout**입니다.

### 왜 중요한가?
Agent가 작업할 웹사이트마다 전용 API나 스크립트를 만들어야 하는 부담을 줄일 가능성이 있습니다. 더 중요한 특징은 **브라우저 제어 계층과 모델 선택을 분리**해 빠른 모델, 정밀한 모델, 로컬 모델을 용도별로 조합할 수 있다는 점입니다. 웹페이지에 민감한 정보를 입력하거나 구매를 수행할 경우 권한 통제와 사람의 승인이 필수입니다.

**출처:** [Outcrawl Scout 공식 GitHub](https://github.com/outcrawlai/scout)
